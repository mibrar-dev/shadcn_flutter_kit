# Phase 3 pilot design: button, input, dialog (P3-A)

Design only. No implementation. All paths relative to `APP = flutter_shadcn_kit`
unless absolute. New tree `NEXT = lib/registry_next`.
Old tree `REG = lib/registry`. Token names from `NEXT/theme`
(`color_tokens.dart`, `tokens.dart`, `theme.dart` — read, real).
Primitive file names from P2-E1/P2-E2 briefs; any API not in a DONE
`registry_next` README is marked `ASSUMED`.

## 0. Conventions all three pilots follow

- Folder: `NEXT/components/<name>/` with exactly `<name>.dart`,
  `<name>_style.dart`, `<name>_theme.dart`, `preview.dart`, `meta.json`,
  `README.md`. Flat, no `_impl/`. Each Dart file <= ~400 lines.
- `<name>.dart` imports `package:flutter/widgets.dart` only (+ foundation,
  theme, primitives). No Material/Cupertino anywhere (old code violates this;
  each pilot removes its violations, listed below).
- `<name>_style.dart` (registry-owned): `<Name>Theme extends
  ComponentThemeData` with nullable per-variant fields, `copyWith`, `merge`
  (receiver wins, per real `Mergeable` in `NEXT/theme/theme.dart`), `lerp`,
  `forVariant`, plus `const <name>Defaults` built only from
  `ThemedColor.ref` (+alpha). No closures, no `BuildContext` params.
- `<name>_theme.dart` (user-owned, values only): `const <name>ThemeOverrides`.
  Only `const` ctors, `ThemedColor`, `StateValue`, `EdgeInsets`, `TextStyle`,
  `Color` literals. CLI never overwrites; Studio rewrites deterministically.
- Resolution at every build via the REAL 3-arg resolver in
  `NEXT/theme/theme.dart` (note: THEME_DESIGN.md §3.5 drafts a 4-arg version
  with a `merge` param — the built theme has
  `resolveComponentStyle<T, S>(context, {widget, select, defaults})`,
  merge via receiver-wins `Mergeable.merge`):
  `widget arg > ComponentTheme<T> tree > ComponentThemes app > defaults`,
  per-state via `StateValue.merge`.
- `meta.json`: `{id, name, category, deps: {primitives, components, foundation},
  theme: <generated schema section>}`. `theme` section generated by
  `tool/gen_theme_schema.dart`; hand-written rest.
- `preview.dart`: widgets-only gallery (all variants/sizes/states, light+dark,
  focus ring, disabled). No `material.dart` (old dialog preview uses it).

ASSUMED primitive APIs (P2 agents building now; builders must check names):
`primitives/clickable.dart: Clickable` (hover/press/focus/keyboard/semantics,
takes `statesController` + `onActivate`), `primitives/focus.dart: FocusRing`
(ring-color outline on focused, token `ring`), `primitives/animation.dart:
AnimatedState` or plain `AnimatedContainer` from widgets (UNVERIFIED which),
`primitives/overlay.dart: ShadcnOverlayRoute` (widgets-`ModalRoute`-based,
replaces material `RawDialogRoute`), `primitives/form_core/*: FormKey,
FormValueSupplier, ValidationResult, FormValidationMode`,
`primitives/localizations: ShadcnLocalizations` (input semantic labels),
foundation `CapturedWrapper` (re-injects theme+data into route subtrees),
foundation `Gap`.

## 1. Button family

### 1.1 Decision: three installable components, not one

OWNERSHIP.md merge row "button family" resolves to `button, toggle,
button_group`; PLAN §4 rule 2 says "different behaviour = its own small
component (toggle, button_group)".

- `components/button/` — `Button` + `ButtonVariant` enum + `ButtonGroup`
  (sub-widget file `button_group.dart`, NOT independently installable).
  Rationale: group is pure layout around `Button` children (border-radius
  surgery via inherited `ButtonGroupData`), has no theme of its own, and per
  OWNERSHIP.md only `color_picker` consumes it. Installing `button` installs
  the group file automatically.
- `components/toggle/` — separate installable component. Rationale: boolean
  on/off state + `ToggleController` + form integration (`FormValueSupplier`)
  is different behaviour from a momentary button; it also absorbs
  `SelectedButton` (value + selectedStyle, 3 external users per OWNERSHIP.md).
- `TabButton` moves to `tabs` (tabs-specific, 2 users). `CardButton` deleted
  (0 importers). `menu/menubar/fixed/muted` theme rows deleted or moved per
  THEME_DESIGN.md §3.1 (menu rows belong to menu/menubar components).

### 1.5 Toggle API

```dart
class ToggleController extends ValueNotifier<bool> {
  ToggleController([super.value = false]);
  void toggle();
}
class Toggle extends StatefulWidget {
  const Toggle({super.key, required this.value, required this.child, this.onChanged,
    this.controller, // optional controlled pattern; value wins if both given? NO — see rule
    this.enabled, this.style, this.theme, this.focusNode, this.autofocus = false,
    this.onHover, this.onFocusChange});
}
```

Controlled/uncontrolled rule (mechanical): `controller != null` =>
uncontrolled (reads/writes controller; `value/onChanged` must be null,
debug assert). Else controlled (`value` + `onChanged`; null => disabled).
Default style: ghost row; `selectedStyle` (old SelectedButton) becomes
`Toggle(activeStyle:)` — SelectedButton deleted, params map 1:1. Form via
`FormValueSupplier` from `primitives/form_core` (ASSUMED).
