# P4-B01 — Phase 4 migration batch B01 (wave A, parallel group A)

Seven components migrated from `lib/registry/components/**` into
`lib/registry_next/components/<name>/`. No primitive file was added: every
primitive this batch needs (`clickable`, `layout`, `overlay`,
`localizations`, `form_core`, `sheet_overlay`, `widget_states`) already exists
in `primitives/`, so the batch only *declares* them in `meta.json`.

Gates (`rearch/qa_gate.sh lib/registry_next`) are green for every file this
batch owns; see §6 for the two in-flight findings from other agents.

## 3. Bugs fixed (never ported)

Each has a regression test named `regression:` or an explicitly named test.

### alert_dialog
1. Barrier was `Colors.black` at **80%** and ignored `DialogTheme.barrierColor`
   entirely (Material `Colors` import). Now inherits the dialog barrier
   (black at 50%, per D3); an explicit `barrierColor` still wins.
2. The widget read `Theme.of(context)` and never consulted `ComponentTheme` /
   `ComponentThemes`, so no override leg existed. Now a four-leg
   `AlertDialogTheme` resolver.
3. `AlertDialogState` was a `StatefulWidget` with no state (dead lifecycle).
4. Hard-coded `maxWidth: 560 * scaling`; `DialogTheme.maxWidth` (480) applies.
5. `surfaceBlur` / `surfaceOpacity` / `surfaceClip` are gone — glass is not a
   token and the dialog owns the card.

### badge
1. `Styleable<BadgeTheme>` replaced a **whole** `AbstractButtonStyle`, so an
   override that restated one state lost the rest of the default row and the
   badge rendered transparent at rest. `BadgeStyle` + `StateValue.merge` merge
   per field **and per state** (test: "an override setting only one state keeps
   the other defaults").
2. Every badge was `Button(enabled: true)` inside `ExcludeFocus`, so a static
   badge showed hover/press styling, showed a click cursor and swallowed a
   pointer click that no handler answered. Without `onPressed` the badge now
   builds no `Clickable` and is painted at full strength (test: "a read-only
   badge has no clickable and no focus node").
3. Five variant classes + `BadgeThemeTokens` / `BadgeThemeSchema` /
   `BadgeThemeConfig` collapse into one enum + one table.

### card
1. `CardButton` deleted — verified 0 importers in the old tree (only
   `control/button/_impl/variants/card_button.dart` and the button barrel's
   theme registry referenced it). `menu` / `menubar` rows live in the menu
   batches. See §5 Q1.
2. The `filled` switch defaulted `fillColor` to `colorScheme.border`, so
   `filled: true` painted a grey block no shadcn preset defines. Deleted.
3. `SurfaceCard` deleted (translucent blurred fill = glass, plus a sheet-overlay
   branch that now lives in `Card`); the pilot `dialog` and `input` already
   dropped it.
4. The old `Card` painted through the unported shared `OutlinedContainer`;
   `Card` now paints its own `DecoratedBox` and installs standalone.

### checkbox
1. `enabled` was ignored by the tap target: `Clickable(enabled:
   widget.onChanged != null)` while the cursor used the computed `enabled`, so
   `enabled: true` with no `onChanged` painted a click cursor on a dead
   control.
2. `final bool _focusing = false` was never written, so the "focused border is
   2px" branch was dead code. Focus is a `FocusOutline` ring now.
3. `SizedBox(width: gap)` was inserted on **both** sides unconditionally, so a
   label-less checkbox was 16px wider than its box.
4. Disabled swapped in `muted` / `mutedForeground` instead of dimming the rest
   style; the switch had the same bug and both now use rest rows +
   `Opacity(0.5)`.
5. No `Semantics` at all: the checkbox announced an unlabelled group.
   `checked` / `mixed` / `enabled` + label are reported now.
6. Only one theme leg existed (`ComponentTheme.maybeOf`, widget argument
   ignored). All four resolve, per field and per state.
7. Disabled cursor was `SystemMouseCursors.forbidden` → system arrow.
8. The tri-state cycle was `checked → unchecked → indeterminate`; it is now the
   intuitive `unchecked → checked → indeterminate`.
9. `AnimatedCheckPainter` painted `colorScheme.primaryForeground` regardless
   of the theme; the indicator colour is now a `SwitchStyle`/`CheckboxStyle`
   row.
10. `ControlledComponentAdapter` + `ControlledCheckbox` collapsed into one
    widget with two modes (assert rejects `value`/`onChanged` with a
    controller).

### chip
1. `onPressed: onPressed ?? () {}` made a **read-only chip an enabled button**:
   it swallowed taps no handler answered and showed hover/press styling. Now a
   static chip builds no `Clickable`.
2. The theme padding leg was resolved inside a closure that read only the
   theme, so a widget style could never change it.
3. `chip_utils.dart` (`isChipCharacter` / `isChipUnicode`) had **0 readers** in
   the old tree; it is a private-use tokenizer helper for chip-style *inputs*,
   i.e. `chip_input` (B13). Not ported.

### divider
1. `VerticalDivider` had **no `theme` parameter** and read `colorScheme.border`
   and `theme.iconTheme` directly, so a themed divider lost its theme as soon
   as it was rotated. One widget, one resolution path.
2. `preferredSize => Size(0, height ?? 1)` reported a zero-length main axis,
   collapsing a horizontal divider inside a `Column`.
3. The old widget pulled in the whole `AxisAlignmentGeometry` /
   `AxisAlignment` / `AxisAlignmentDirectional` / `AxisInsets*` family from
   `shared/utils/axis.dart` plus 0-call sites; replaced by
   `DividerLabelAlignment {start, center, end}`.
4. `AnimatedValueBuilder` + `DividerProperties` animated a rule shadcn never
   animates; the paint is direct now.

### switch
1. `ControlledSwitch(enabled: true)` + `Switch._enabled = widget.enabled ??
   widget.onChanged != null` produced a switch that looked enabled but could
   not be flipped. One `_isEnabled` getter drives cursor, ring and tap target.
2. Disabled painted `muted` (track) and `mutedForeground` (thumb), so a
   disabled switch lost its on/off identity; now rest rows + `Opacity(0.5)`.
3. Disabled cursor `SystemMouseCursors.forbidden` → system arrow.
4. The hand-rolled `GestureDetector` + `FocusableActionDetector` stack never
   published `WidgetState` data, so the hover/press rows of `SwitchTheme` were
   unreachable; interaction moved to `Clickable` and the private
   `_SwitchTrack` reads the published `WidgetStatesData`.
5. `ControlledSwitch` + `ControlledComponent` collapsed into one widget with
   two modes.
6. Colours were raw `Color?` widget args; they are `ThemedColor` style rows
   now, so they follow preset switches.

## 4. Deviations from the batch data (with reasons)

1. **`badge` does not depend on the `button` component.** The batch data lists
   `component_deps: ["button"]`. A shadcn badge is ~20px tall
   (`px-2 py-0.5 text-xs`); `Button`'s size table enforces
   `minHeight: 28..44`, and reusing it would also dim a static badge (button
   house rule: disabled = `Opacity(0.5)`) — a read-only label must not look
   disabled. `Badge` therefore builds its own small surface on `Clickable`, like
   `Toggle` does. `deps.components` is `[]` and matches the imports exactly
   (the checker enforces this).
2. **`chip` imports `button` for its style table only.** A chip *is* a compact
   button row, so `chip_style.dart` reuses `ButtonVariant`, `ButtonVariantStyle`
   and `buttonDefaults` for the per-state paint while `Chip` renders its own
   box — same reason as (1): a static chip must not be dimmed. Both `button` and
   `clickable` are declared.
3. **`divider` declares no `primitives` entry** although the batch data lists
   `["layout"]`. `primitives/layout.dart` is `Basic` / `BasicLayout` / `Label`,
   which a rule does not need; declaring it would raise an
   `unused-dependency` warning.
4. **`alert_dialog` declares no `primitives` entry** although the batch data
   lists `["overlay", "localizations"]`. It pushes through the `dialog`
   component's `showShadcnDialog`, which already owns the route and the
   `dialogDismiss` localisation, and the alert has no user-facing string of its
   own.
5. **`card` declares `primitives: ["sheet_overlay"]`** (not in the batch data)
   because `SheetOverlayHandler.isSheetOverlay` is what the old `SurfaceCard`
   branch used. The primitive already exists; it was imported, not written.
6. **`switch` declares `primitives: ["widget_states"]`** (not in the batch data)
   because `_SwitchTrack` reads `WidgetStatesData` from `Clickable`.
7. **`checkbox` and `switch` value names.** shadcn/Radix use the name
   `CheckboxState` for the value union; the old Dart enum was also called
   `CheckboxState`, which collided with `State<Checkbox>` and made
   `_CheckboxState` ambiguous. The new enum is `CheckboxValue`. The switch
   keeps a plain `bool`, as shadcn does.
8. **`Divider` + `VerticalDivider` merged** into one widget with `axis`
   (shadcn `Separator orientation`). The component id stays `divider` so it
   matches the directory.
9. **New public API not in the old module**, all of it shadcn-shaped:
   `Badge.showAsDot`, the card slot widgets (`CardHeader` / `CardTitle` /
   `CardDescription` / `CardContent` / `CardFooter`), `Checkbox.label` /
   `Switch.label`, `kSwitchTrackKey` / `kSwitchThumbKey`.
10. **Preview helpers.** `alert_dialog/preview.dart` and `badge/preview.dart`
    use a plain `Button` as a toggle stand-in instead of importing the
    `toggle` component, which is not in this batch's deps.

## 5. Open questions

- **Q1 — `CardButton`.** The batch asked to "verify no new users". Verified in
  the old tree: `CardButton` / `CardButtonTheme` are referenced only by
  `components/control/button/_impl/variants/card_button.dart` and the button
  barrel's `button_variance_class.dart`; **0 external call sites**. The pilot
  `button` component already dropped it. No action needed, but the `button`
  component is not in B01's write scope, so nothing was changed there.
- **Q2 — `SurfaceCard` consumers.** `empty_state` (B08), `radio_group` (B08),
  `object_input` (B21), `color_picker` (B04), `autocomplete` (B23),
  `item_picker` and `form_field` (B10) used `SurfaceCard` in the old tree.
  They now use `Card` (identical outside a sheet overlay, transparent inside
  one). Each of those batches already declares `components: ["card"]`.
- **Q3 — `ChipButton` ownership.** It is used by `chip_input` (B13), `select`
  (B20) and `filter_bar` (B24). Those batches already declare
  `components: ["chip"]`, so keeping it in `chip` is consistent; no change.
- **Q4 — `chip_utils`.** Not ported. If `chip_input` (B13) ever needs
  private-use tokenizing it should declare its own helper; nothing in the old
  tree called it.
- **Q5 — hover delivery in widget tests.** `FocusableActionDetector` only
  receives hover events when `FocusManager.instance.highlightStrategy` is
  `alwaysTraditional`; with the default `automatic` strategy a simulated mouse
  gesture delivers nothing (this also affects the pilot `button_test.dart`,
  whose hover assertion is weaker than it looks). Every hover test in this
  batch sets the strategy explicitly and `addTearDown`s it.
- **Q6 — `paint.color` equality.** `Paint.color` round-trips through the
  engine and does not compare `==` to a literal `Color` of the same ARGB. The
  divider test compares `toARGB32()`; other components compare resolved
  `BoxDecoration` colours, which do compare.
