# P4-B02 — slider migration report

Batch B02, single component `slider` (old `components/form/slider`, ~9.5k
LOC incl. JSON/MD docs; ~4.4k Dart LOC in `slider.dart` + `_impl/**`). New
implementation: 1,461 LOC across 6 Dart files.

## Old -> new file mapping

New public API: `Slider`, `Slider.range`, `SliderVariant`, `SliderThumbShape`,
`SliderSnap` (`none`/`steps`/`values`), `SliderTheme`/`SliderStyle`,
`SliderLogic`/`SliderView`/`SliderThumb`/`SliderMark`,
`sliderDefaults`, `sliderThemeOverrides`.

`SliderPainter`, `SliderThumbShape`, `SliderMarksStyle`, `sliderStep` and
`sliderDraggedRange` live in `primitives/slider/` (layer 2, generic — no
`SliderTheme` types) so B04 colour sliders reuse them; the component
imports, never exports, the painter.

## Bugs fixed (not ported)

- **Material dependency (the batch's named bug):** old `slider.dart` and the
  six `shad_slider_*`/`upstream_*` files imported
  `package:flutter/material.dart`; a stock Material `Slider` cannot express
  segmented fills, so it was forked and bloated. Rewritten on
  `GestureDetector` + `CustomPaint` + `Focus` — zero Material/Cupertino.
- **`// ignore_for_file` blanket suppression** on all files; real lints now
  pass clean (no ignores added).
- `_impl/` layout and global mutable/style machinery replaced by the
  3-arg `resolveComponentStyle` + `Mergeable` receiver-wins merge (port of
  the P3 pattern).
- Range swap semantics preserved but simplified: `allowSwap` crossing now
  keeps the pair ordered; min-range is enforced in both modes via
  `sliderDraggedRange` (regression-tested).
- Disabled now follows the house rule: whole control `Opacity(0.5)`, no
  disabled colour rows (old painter used `withOpacity(0.35)` inline and a
  `cs.muted` fill that bypassed tokens).
- Old defaults painted `Colors.transparent` gap segments that clobbered the
  fill; new painter draws track/fill/marks directly per variant.

## Deviations / decisions

- **Extra files:** none in the component folder after QA round 2. All
  machinery moved down to `primitives/slider/` (logic 385, controller
  85, painter 158), which is generic (no `SliderTheme` types) so the B04
  colour sliders reuse it.
- **`SliderValue` (primitives) used for range values** instead of the old
  `ShadRangeValue`; `minRange`/`allowSwap` are widget params. Old
  `SliderValue.roundToDivisions` is unused (snap owns quantization).
- **Dropped knobs:** `thumbEdgeOffsetPx`, `thumbVerticalOffsetPx`,
  `joinGapPx`, `fillEdgeBiasPx`, `fillStopsAtThumbCenter`, `trackRenderer`,
  per-layer builder typedefs, `dragPopover*` overrides, upstream
  `ControlledSlider`/`SliderController`/intent classes/`SliderValueIndicator`.
  Documented in README.
- **`primitives: ["animation"]` from batch data not declared**: nothing in
  the new widget needs it (paint refreshes via `setState` on drag); deps
  match imports exactly (`form_core`, `slider_value`). Adding an unused
  primitive dep would break `check_layers`/`owner` consistency.
- Waveform variant is a static bar overlay (old animated wave slider dropped
  with the animation overlay machinery; bar heights deterministic).
- Theme loading: theme leg resolves live per build; `ComponentThemes` +
  `ComponentTheme` (tree) + widget leg all merge per field.

## Tests

`test/registry_next/components/slider_test.dart` (23 tests, widget level)
+ `test/registry_next/primitives/slider_test.dart` (15 tests, moved
logic/painter level):

- token-derived defaults per variant (light + dark), standard vs soft thumb
  shape.
- every variant renders; tap jumps; drag emits clamped values; `steps`
  quantization; `values` nearest-entry; zero-width domain snap.
- keyboard: arrows step (SnapNone domain/100, steps, values), Home/End
  bounds; range arrow adjusts active thumb.
- controlled range: nearest-thumb drag, `minRange` clamp, `allowSwap`
  crossing.
- disabled: opacity 0.5, gestures/keys inert.
- 4-leg theme precedence (default < app < tree < widget) with distinct
  colours at each leg; empty widget leg keeps lower leg's fill + overrides
  trackHeight only.
- form: `FormValueSupplier` reports `SliderValue` to a `FormFieldHandle`.
