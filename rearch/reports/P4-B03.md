## 0. Verdicts on the "UNVERIFIED overlap" questions

The batch asked the builder to confirm whether
`linear_progress_indicator` / `circular_progress_indicator` survive as
separate components.

### `linear_progress_indicator` → absorbed into `progress`

Evidence (old tree):

- Old `Progress` was a thin min/max normaliser that delegated to
  `LinearProgressIndicator` (`components/display/progress/progress.dart:63`),
  so it was already the same visual: a horizontal bar. `Progress` had **zero
  callers outside its own preview** (`grep -rn '\bProgress('`).
- Real `LinearProgressIndicator` callers: `layout/scaffold` (value,
  `value: null` indeterminate, `showSparks`, `backgroundColor`),
  `form/file_picker` (`value`, `minHeight: 4 * scaling`), example dashboard
  (`value`, `borderRadius`, `minHeight`). All of those knobs exist on the new
  `Progress` (`value`, `showSparks`, `backgroundColor`, `height`,
  `borderRadius`).
- No visual delta survives review: one painter, one component.

`Progress` keeps the shadcn name and absorbs the indeterminate sweep and the
optional sparks. `min`/`max` were dropped: every real call site already
normalises to `0..1`, and shadcn's `Progress` takes a `0..1` value.

### `circular_progress_indicator` → absorbed into `spinner`

Evidence (old tree):

- Every real call site uses **indeterminate** mode only:
  `display/markdown` (`strokeWidth: 2`), `control/command`,
  `overlay/gooey_toast`, `overlay/refresh_trigger`.
- Determinate circular (`value:`) appears only in `utility/image/preview`.
- The old `spinner` was a Material `CircularProgressIndicator` wrapper
  (indeterminate only). `spinner` is the shadcn component name for a
  circular indeterminate leaf.

Not ported: circular **determinate** mode (zero real consumers). If a future
consumer needs it, it should be a deliberate new API decision (open
question 2), not a copy of the Material component.

## 2. Bugs fixed (old code was not ported faithfully)

Cross-component:

1. **Material imports removed** (batch `bugs_to_fix`): old
   `progress.dart` (`package:flutter/material.dart hide Theme,
   LinearProgressIndicator`), `circular_progress_indicator.dart`
   (`material.dart as mat`), `circle_spinner.dart` (`material.dart as m`),
   `selectable.dart` (`material.dart as m`) and three previews. The new
   dirs are widgets-only (`grep` for material/cupertino in the six dirs:
   empty; gate `banned` empty).
2. **Theme legs were resolved wholesale**: the old pattern
   `widget.theme ?? ComponentTheme.maybeOf<T>(context)` picked one leg and
   dropped the others, and there was no app leg. All six components now use
   the 3-arg `resolveComponentStyle` with per-field `merge`
   (widget arg > scoped > app > defaults). Tests assert all four legs and a
   partial-merge regression per component.
3. **`gap` / `data_widget`**: none of these components actually imported
   them (avatar's old meta listed a `gap` pubspec dep but the code used
   `SizedBox`); nothing to replace.

Per component:

**avatar**
- Initials used `FittedBox(fit: BoxFit.fill)`, which stretches
  multi-character fallbacks non-uniformly; now `BoxFit.scaleDown`
  (regression test).
- `AvatarBadge` rendered its child with no colour context; the badge now
  applies `badgeForeground` through `IconTheme`/`DefaultTextStyle`.
- The old badge path rebuilt the tile twice and assembled an internal
  `AvatarGroup` with a notch clipper (`AvatarGroupClipper`, 71 LOC) to cut
  the previous avatar around the badge. The notch is replaced by the modern
  shadcn ring: `AvatarGroup` draws a `background`-coloured ring around each
  tile. `AvatarWidget`/`_AvatarWidget` (an abstract sizing interface with a
  `call()` helper) are gone; children are plain widgets.
- `Avatar.network` (a `ResizeImage`+`NetworkImage` convenience) and the six
  `AvatarGroup.toLeft/...` factories are dropped (clean break); pass an
  `ImageProvider` / an `overlap`+`ringWidth` instead.

**progress**
- Old `progress.dart` line 3 imported Material; gone.
- Old `Progress` asserted `progress == null || (progress >= min &&
  progress <= max)` — an out-of-range caller crashed debug builds. Values
  are now clamped (regression test).
- Old track colour derived with `color.scaleAlpha(0.2)` (alpha replace);
  new default is `ThemedColor.ref(ColorRef.primary, alpha: 0.2)` (alpha
  multiplies, so alpha-bearing tokens survive).
- Old sparks glow was painted at `size.width * (end - start)` — the fill
  width, not the fill's leading edge. New glow anchors at `size.width *
  end`.
- Old `Progress` delegated to the old `LinearProgressIndicator` component
  (cross-component coupling); the new `Progress` is self-contained and
  covers both, so `progress` stays installable alone.
- Old `min`/`max` normalisation dropped: no call site used it and shadcn's
  `Progress` takes a plain `0..1` value.

**spinner**
- Old `CircleSpinner` wrapped Material's `CircularProgressIndicator`; the
  new `Spinner` paints a 270° round-capped arc with `CustomPaint` and
  rotates it with the `animation` primitive (`RepeatedAnimationBuilder`).
- Old `Spinner.resolveColor` returned `null` when no override was set (the
  Material default took over); the new default is the `primary` token.
- `strokeWidth` was hardcoded `size / 8` in the old circle spinner; it is
  now a themeable field defaulting to `size / 12` (matches the old
  circular component and gives 2px at 24).
- The old `Spinner` abstract base + `CircleSpinner` subclass pair collapsed
  into one concrete `Spinner`.

**triple_dots**
- Old `MoreDots` read `DefaultTextStyle.of(context).style.color!` and threw
  when no explicit text colour was installed; the default is now the
  `mutedForeground` token (regression test renders without a
  `DefaultTextStyle` colour and proves the ambient text colour no longer
  leaks into the dots).
- Old dot size was derived from the ambient font size
  (`(style.fontSize ?? 12) * 0.2`, i.e. 2.4px at 12); the default is now
  `4 * scaling` and themeable.
- Class renamed `MoreDots` → `TripleDots` (component/dir name; clean break).

**icon**
- Only members with real call sites are kept: `iconSmall` (11 files),
  `iconXSmall` (4), `iconX3Small` (1), `iconMedium` (1), `iconLarge` (1),
  `iconMutedForeground` (2). Dropped: `iconX4Small`, `iconX2Small`,
  `iconXLarge`, `iconX2Large`, `iconX3Large`, `iconX4Large`,
  `iconPrimary`, `iconPrimaryForeground`, `iconSecondary`,
  `iconSecondaryForeground`, `iconDestructiveForeground` (deprecated, 0
  callers).
- `WrappedIcon` (0 external users) and its `call()`/`copyWith` machinery
  are dropped; the extension methods return `Widget` directly (same call
  syntax).
- Precedence fix: the old helpers did `theme.iconTheme.slot.merge(inherited)`
  and `IconThemeData.merge` lets the argument win, so an ancestor
  `IconTheme` silently overrode the modifier (a muted colour could be
  swallowed). New `IconTheme.merge(data: resolved)` makes the resolved slot
  win and lets the ambient fill only unset fields (regression test).
- `IconContainer`'s widget args were `@Deprecated` in favour of theme-only;
  they are regular widget-leg overrides again and the theme resolves per
  field over all four legs.
- Batch note `.fill has 38 callsites; .size/.weight/.onPrimary deleted at
  prim level`: **UNVERIFIED** — the old `display/icon` code has no `.fill`
  member (searched `lib/registry`; `fill` hits are slider segment kinds,
  `Positioned.fill`, `BoxFit.fill`, `PaintingStyle.fill`). Treated as stale
  batch metadata; the applied part is "keep only used members".

**selectable**
- Old `SelectableText` delegated to Material's `SelectableText`; the new
  widget builds a read-only widgets-layer `EditableText` and reuses
  `primitives/text_editing` (`ShadcnSelectionControls` handles +
  `defaultShadcnContextMenuBuilder`), the same machinery `Input` uses.
  Rich spans are rendered through a private `_TextSpanEditingController`
  (the widgets-safe equivalent of Material's controller).
- Old theme legs `this.theme ?? ComponentTheme.maybeOf<...>()` dropped every
  lower leg; fixed per-field (regression test).
- Selection colour alpha now multiplies the token alpha (rule: alpha never
  replaces).
- Dropped Material-only params: `useNativeContextMenu`,
  `magnifierConfiguration`; also dropped `scrollPhysics`,
  `dragStartBehavior`, `textScaleFactor` (clean break, no internal callers).

## 3. Deviations from the brief / batch data

1. **Two components are not separate installable dirs** (verdicts in §0):
   `linear_progress_indicator` and `circular_progress_indicator` are
   absorbed. This is the "collapse to one component" / "alias row" path the
   batch explicitly offered, but it is the largest deviation and needs QA
   ratification.
2. `icon`'s component theme is named `IconContainerTheme`, not `IconTheme`:
   `package:flutter/widgets.dart` already exports an `IconTheme` widget, and
   a same-named class would shadow the framework widget for every importer.
3. Avatar badges no longer notch the tile (see §2); `AvatarGroup` uses a
   background ring and lays children out at the group `size`.
4. `progress` indeterminate mode is a single sweeping segment; the old
   Material-style two-line, four-interval choreography is not ported.
5. `spinner` gained `strokeWidth` (from the absorbed circular component) and
   dropped the old `size / 8` stroke default.
6. `selectable` has no force-press selection (`forcePressEnabled => false`).
7. No new primitive was created. The batch-listed primitives (`text`,
   `animation`, `text_editing`) were sufficient; `selectable` does not
   import `primitives/text` because nothing from it is needed (declared deps
   match imports exactly, so no unused-dependency warning).
