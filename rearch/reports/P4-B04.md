## alpha

Mapping: `components/utility/alpha/alpha.dart` → `components/alpha/alpha.dart`;
preview rewritten widgets-only (old preview used Material `Scaffold`).

Bugs fixed:

1. `AlphaPainter.shouldRepaint` always returned `false` → a changed pattern
   never repainted. Now compares the three inputs.
2. Old loop computed row/col from the wrong axis indices (correct parity by
   coincidence) and the doc-comment litter made the pattern unreadable; rewritten
   with one square loop.

Deviation: `primary`/`secondary`/`squareSize` are constructor parameters now
(defaults keep the old constants) — additive, no theme file (painter-only leaf,
nothing to theme). No `_style`/`_theme` files: folder has the 4 allowed files.

## color

Mapping: `components/utility/color/**` (12 dart files) → `components/color/color.dart`
+ `preview.dart`.

Old → new:

* kept `ColorDerivative` (space-preserving HSV/HSL wrapper) + private `_HSVColor` /
  `_HSLColor`, now one file instead of 4 part files.
* **deleted** the whole gradient family (`ColorGradient`, `LinearColorGradient`,
  `RadialColorGradient`, `SweepColorGradient`, `ColorStop`, `GradientAngle`,
  `GradientAngleGeometry`, `DirectionalGradientAngle`): 0 consumers outside the old
  `color` folder (verified by grep of the whole old tree).
* `colorToHex` is **not** re-declared — it lives in `theme/color_utils.dart`
  (OWNERSHIP). `ColorDerivative.fromHex` uses `primitives/color_math.dart`.

External-package detox: the old meta.json pulled
`animation_kit/cross_file/skeletonizer/country_flags/phonecodes`; none are imported
by the new file and no new pubspec dependency is introduced. Country-flag/phone-code
data remains `primitives/phone_number.dart`.

Bugs fixed:

1. Cross-space equality: old `_HSLColor == _HSVColor` compared an `HSLColor` to an
   `HSVColor` and was always `false` (and asymmetric to boot). Equality now compares
   the rendered 32-bit ARGB, so an HSL and HSV derivative of the same colour are equal
   and hash identically.
2. `changeToColorRed/Green/Blue` passed an unchecked int to `withRed/Green/Blue`
   (debug assert / invalid value for out-of-range input). Now `round().clamp(0, 255)`.
3. `ColorDerivative.fromHex` is new (old code only had `colorToHex`); invalid input
   returns `null` instead of throwing (`color_math.colorFromHex` regression-tested).

Deviations: `ColorDerivative.transform` throws `StateError` (old `FlutterError`) on an
unknown implementation — the only implementations are private and exhaustive.
Channel getters (`red/green/blue`) clamp to `0..255`.

## formatter

Mapping: `components/form/formatter/{formatter.dart + 7 _impl files}` →
`components/formatter/formatter.dart` + preview.

* Formerly-private formatters are public now (clean API):
  `ToUpperCaseTextFormatter`, `ToLowerCaseTextFormatter`, `MathExpressionFormatter`,
  `HexTextFormatter`, `NumberTextFormatter` (was `_DoubleOnlyFormatter`),
  `IntegerTextFormatter` (was `_IntegerOnlyFormatter`), `TimeFormatter`.
* `_TimeFormatter` was owned here and duplicated in `time_picker` with a divergent
  body; the duplicated file + the old `contraintToNewText` misspelled alias are gone.
  `TimeFormatter({required int length})` follows the formatter copy (reconciliation:
  formatter copy wins) and is public for B13 (`time_picker` must declare the dep).
* `TextInputFormatters.time(length:)` still returns it.
* `mathExpression` keeps `package:expressions` (already an app dependency, not in the
  banned list; the color batch's banned packages are unrelated).

Bugs fixed:

1. Numeric clamp ignored the sign: old code clamped the magnitude and re-applied `-`,
   so `-5` with `min: 0` stayed `-5`. Both numeric formatters now clamp the signed
   value (`-5` → `0`).
2. `decimalDigits` was defeated by the trailing-zero stripper (`1.5` formatted with
   `decimalDigits: 2` came back `1.5`, not `1.50`). Fixed decimals are now exact;
   natural-precision parsing still trims trailing zeros.
3. Exact `min`/`max` equality used to rewrite the text (typing `100` with `max: 100`
   normalised the caret); now only true out-of-range values clamp.

Deviation from batch data: `primitives: []` (batch listed `form_core`; the new file
imports nothing from it — declaring it would be an unused-dependency warning).

## history

Mapping: `components/form/history/**` (5 dart files) →
`components/history/{history.dart, history_style.dart, history_theme.dart, preview.dart}`.

* `ColorHistoryStorage` + `RecentColorsScope`/`RecentColorsScopeState` +
  `ColorHistoryGrid` kept. `data_widget`'s `Data`/`ForwardableData` replaced by
  `foundation/data.dart`, `gap` by `foundation/gap.dart`, `Button` by the new
  `components/button` (`ButtonVariant.outline`, `ButtonSize.icon`).
* New themed slice `HistoryTheme` (selected ring colour/width, radius, spacing,
  swatch size) resolved with `resolveComponentStyle` (widget > tree > app > defaults).

Bugs fixed:

1. `addHistory` de-duplicated with `List.contains(color)`; `Color` has no value
   equality, so picking the same ARGB twice accumulated duplicates. Now de-dupes by
   `toARGB32()` before moving the entry to the front.
2. `setHistory` ignored `capacity` (could exceed the advertised maximum); now clamps.
3. The grid rebuilt on every parent frame (ListenableBuilder was fine, but the notifier
   was a stateful list mutated in place) — storage now owns a private `ChangeNotifier`
   and exposes an unmodifiable view.

Deviations: empty slots render a fixed-size box (old rendered an empty outline
`Button`); selection ring is drawn as a themed `Border` around the swatch; grid keeps
the old shrink-wrap (`IntrinsicWidth`/`IntrinsicHeight`) layout.

## hsl / hsv

Mapping: `components/form/hsl/{hsl_color_slider.dart + 3 _impl files}` →
`components/hsl/{hsl.dart, hsl_style.dart, hsl_theme.dart, preview.dart}` (same for hsv).

Installability fix: both now have a real entry file (`hsl.dart` / `hsv.dart`
re-exporting the slider + type), so `check installable` passes (old folders only had
`hsl_color_slider.dart`).

Reuse (per the brief): interaction is `primitives/slider/color_field_slider.dart`;
gradient painting is `primitives/color_field_paint.dart`; value clamping uses
`primitives/slider/slider_logic.dart` (`SliderSnap.none`); checkerboard from
`components/alpha`.

Bugs fixed:

1. Gesture conflict: the old `GestureDetector` attached `onTapDown` **and**
   `onPanUpdate`, and the pan recognizer lost to the tap recognizer — only the initial
   tap applied; drags never reached `onPanUpdate` (reproduced in a widget test). The
   shared surface drives a single pan-down/update/end path; tap = pan-down.
2. Cursor/channel state duplicated the widget colour (`_currentHorizontal/_hue/…`)
   and drifted from `didUpdateWidget`; positions are now derived from the current
   colour.
3. Painter `shouldRepaint` compared hand-picked channel subsets (missed alpha/hue
   edits); now compares the colour + axes.
4. The same axes switch existed in both the state and the painter (divergence risk);
   one `_hslAxes`/`_hsvAxes` per component, and the painter receives resolved axes.
5. Keyboard support was absent; arrows/page-up-down/home-end now move the slider
   (single-channel: any arrow steers the channel; 2D: arrow steers its axis).

Also fixed while porting: cursor geometry now uses the ambient theme's resolved
geometry (`cursorSize`/`cursorWidth`/`cursorColor`), so `Theme.of(context).scaling`
(Material) is gone; disabled state is the house-rule `Opacity(0.5)`; the old
tap-down-commits-with-unchanged-color quirk is gone (tap commits the position value).

Deviations:

* `meta.json` `deps.primitives` for hsl/hsv lists `color_field_paint`, `form_core`,
  `slider` — **not** `color_math` as drafted in the batch data: neither file imports
  it (`color_math` is imported by `color`). If the orchestrator wants the sliders to
  depend on `color_math`, it should be added together with a real use.
* `HSLColorSliderPainter`/`HSVColorSliderPainter` take explicit axes
  (`hueAxis/saturationAxis/lightnessAxis|valueAxis/alphaAxis`) instead of a
  `sliderType` — public API is new in the new tree, so no clean-break issue.
* Enum members keep their old names (`hueLum`, `satLum`, …); shadcn has no HSL/HSV
  slider naming to follow.

Open questions (for the orchestrator):

* B08 `color_field`: `color_field_paint.dart` is now the single owner of the gradient
  engine + `ColorFieldAxis`; `color_field` should re-export/import it, not fork it.
* B24 `color_picker` imports hsl/hsv under a private alias and must not re-declare
  `HSLColorSliderType`/`HSVColorSliderType` (its own bigger painter stays private).
* The old tree's hsl/hsv painters delegated to the color_field engine by importing
  the *component*; the new tree has that engine as a primitive, which also removes the
  old component→component dependency from hsl/hsv.
