## Scope: `fade_scroll` skipped (orchestrator note, P4_PLAN Q3)

The batch JSON lists `fade_scroll`; the orchestrator note supersedes it:
`primitives/fade_scroll.dart` is the accepted owner and no component is built.
Consequences verified in code:

- No `components/fade_scroll/` folder exists.
- `scrollable` keeps the one concern the old directory did not give to
  `scrollable_client` — the edge-fade viewport — and builds it on
  `primitives/scroll_metrics` (the primitive P4-PRIM-A extracted its math from),
  not on `FadeScroll`. `FadeScroll` is controller-driven; the viewport is
  notification-driven and has no controller, so it cannot reuse it without an
  API change. It does not re-declare `FadeScroll`/`FadeScrollTheme`, so
  `check_single_owner` stays green.
- Nothing in this batch declares `deps.primitives: [fade_scroll]`; tabs (B21)
  is the consumer named by the plan.

## Cross-cutting notes

- No new primitive was needed; `primitives/scroll_metrics.dart` is reused by
  `scrollbar`, `scrollable` and `scrollable_client` (P4-PRIM-1 was built for
  exactly this batch). `scrollable` additionally uses the `resolveGeometry` /
  `gradientStops` helpers it exposes for custom masks and tests.
- Every `meta.json` carries the pilot `deps` shape only (no top-level
  `dependencies` block) and matches the real imports (checker 0 errors,
  0 unused).
- All files ≤ 372 lines; tests are 157–278 lines.
- No `part`, no `// ignore`, no Material/Cupertino, no `_impl/`, no global
  mutable state, no aliases (only the pre-existing `ScrollableBuilder` typedef
  that is part of the public API).

## Open questions

- `scrollable` keeps the old notification-driven fade viewport. If QA prefers
  this behaviour to be folded into `primitives/fade_scroll.dart` (e.g. a
  notification-driven mode), that is a primitive change, not a component one.
- `outlined_container` dropped the public `DashedContainerProperties` /
  `DashedLineProperties` / `DashedLinePainter` classes (0 importers). If the
  CLI/Studio needs them for animation plumbing, they should come back as part
  of a primitive rather than the component.
- The `scrollview` component has no theme; if every component must ship a
  `<name>_theme.dart`, the only themeable value would be `enabled`.
- `scrollbar`'s default `minThumbLength` (48, from PRIM-1) is larger than
  Flutter's `RawScrollbar` default (18); this matches the old painter and is
  now overridable.
