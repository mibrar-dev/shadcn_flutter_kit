## 3. Bugs fixed (never ported)

Each has a regression test named `regression:` (or an explicitly named test).

### 3.1 async

1. The module needed a **template suppress-all-lints pragma** listing
   `duplicate_import, unnecessary_import, unused_import, unnecessary_null_comparison,
   dead_code, deprecated_member_use, …` — i.e. the file did not analyse cleanly.
   None of the listed suppressions is needed any more (there is no null
   comparison and no dead code in the new file).
2. `FutureOrWidgetBuilder<T>` was a **second public name for Flutter's
   `AsyncWidgetBuilder<T>`** (same signature, passed straight to
   `FutureBuilder.builder`). Dropped; `AsyncWidgetBuilder` is re-exported by
   widgets.dart. `initialData` now has an explicit documented contract (async
   path only — a synchronous value is always `done`).
3. `preview.dart` imported `material.dart` for `Scaffold` +
   `CircularProgressIndicator`.

**No functional defect found** in the widget body: I verified against the
Flutter SDK that `AsyncSnapshot.withData(done, null)` does **not** assert (the
`assert(data == null || error == null)` in `AsyncSnapshot._` is satisfied when
both are null), so the "null value crashes" theory is not real. Reported as
UNVERIFIED-nothing.

### 3.2 debug

Not migrated (§2.1). Bugs noted for the record: the sticker wrapped its label in
`Opacity(0.2)`, so a white 12px label was drawn at 20% alpha over a 20%-alpha
box; and `Container(color: color)` in `debugContainer` fully hides the child it
is supposed to highlight.

### 3.3 image

1. **The component did not exist.** `utility/image/image.dart` was a single
   suppress-all-lints pragma; the manifest shipped an installable id with no
   entry declarations.
2. The old preview hand-rolled `loadingBuilder` with a Material
   `CircularProgressIndicator` (hard-coded `1.0` scaling, not the theme) and an
   error state of `Icon(Icons.error)` with no token colour. Both are slots now.
3. `via.placeholder.com` URLs (dead service) in the old preview.

### 3.4 media_query

1. **Only two of the four theme legs existed.** The widget read
   `ComponentTheme.maybeOf<MediaQueryVisibilityTheme>` and nothing else, so an
   app-wide `ComponentThemes` entry never applied.
2. `MediaQueryVisibilityTheme.copyWith` **dropped `themeDensity`,
   `themeSpacing` and `themeShadows`** — it rebuilt the object without
   forwarding the `ComponentThemeData` slots.
3. The theme class did not `implement Mergeable`, so legs could not merge per
   field.
4. Out of range rendered `SizedBox(child: null)`; now `SizedBox.shrink()` with a
   documented "collapse, don't reserve space" contract.

### 3.5 page_route

1. **`canTransitionTo(nextRoute) => nextRoute is ShadcnPageRoute`** — pushing the
   `dialog` (or drawer, sheet, or any other route) over a page skipped the
   page's exit transition, because the page refused to animate into it. The
   framework default (`true`) is inherited now; the override is kept only as a
   documented no-op so the intent is greppable.
2. `static final Animatable<double> _fadeIn` / `_slideIn` were **lazily-initialised
   global mutable state**; they are `static const` curve/offset plus per-build
   `CurveTween`/`Tween`.
3. `debugLabel` interpolated `settings.name` unconditionally, printing
   `PageRoute(null)` for the (common) unnamed route.
4. `kDefaultPageTransitionDuration` (300 ms) read as if it were foundation's
   `kDefaultDuration` (150 ms). Renamed to `kShadcnPageTransitionDuration`
   (no duplicate name anywhere in `registry_next`; only the old module's own
   README/meta referenced the old name).
5. Barrel + `part` + suppress-all-lints pragma; the old module also declared
   `_opaque` privately *and* exposed `opaque` with a comment about Dart 3.12.

### 3.6 patch

1. **`ClickDetectorState` was public with public mutable `count` / `lastClick`
   fields** — any app code could corrupt the click count. The state class is
   private now.
2. **The threshold used `DateTime.now()`**, so an NTP correction, a DST change or
   a user editing the date could reset or extend a click sequence. A `Stopwatch`
   (the VM's monotonic clock) is used instead.
3. **The count ignored *where* the tap landed**: two taps at opposite ends of a
   large canvas inside `threshold` read as a double click. A tap further than
   `kDoubleTapSlop` from the previous one now restarts the sequence.
4. `ClickDetails` had **no `==`/`hashCode`**, so callers could not compare two
   events; it also had no position at all.
5. A **Material `Scaffold` preview shipped inside the installable component
   folder** (`_impl/core/patch_preview.dart`), and `preview.dart` was a 4-line
   re-export of it.

### 3.7 switcher

1. **`onPanStart` set `_dragging = true` without `setState`**, so the first drag
   frame still animated over `duration` instead of following the finger.
2. **`_snapIndex()` always called `onIndexChanged`** even when the snapped index
   equalled `widget.index`, so a one-pixel drag notified the caller.
3. **`widget.index` was never clamped**: `index: 5` with three children indexed
   `children[5]` and threw a `RangeError` on the first frame.
4. **`context.size!`** was a null assertion on the State's own context — a pan
   inside an unbounded or not-yet-laid-out slot crashed. The extent now comes
   from a `LayoutBuilder` with a zero guard on each axis.
5. `didUpdateWidget` ignored `direction`, so a changed axis stayed stale until
   the next drag.
6. `_RenderSwitcherTransition.paint` and `.hitTestChildren` **overrode mixin
   methods with the mixin implementations** (dead code), and the `absolute`
   branch was **unreachable** (`Switcher` always passed `false`) — 4 of the 8
   offset cases were dead.
7. `performLayout` returned `Size.zero` unless there were exactly two children,
   silently collapsing a one-child transition.
8. `AnimatedValueBuilder` came from `shared/primitives` and re-created the
   value/duration pair on every frame; the position is an
   `AnimationController.unbounded` value now (an `AnimationController` is
   bounded to `0..1` by default and would have clamped page 2 to page 1).
9. `children` empty would make `_index.clamp(0, -1)` throw an `ArgumentError`
   on the first pan; `children.isNotEmpty` is asserted.

### 3.8 dot_indicator

1. **The only animated dot widget, `DotItem`, had zero readers.** The pair the
   indicator actually built (`ActiveDotItem` / `InactiveDotItem`) was made of
   plain `Container`s, so changing the index jumped instantly despite the
   component's name. Both `AnimatedContainer`s now.
2. **Hard-coded colour literals in the theme defaults**: `activeColor =
   0xFF171717` (near-black) and `inactiveBorderColor = 0xFFF5F5F5` (near-white) —
   greys no preset defines. Tokens (`primary` / `muted`) replace them.
3. The inactive dot was a **transparent fill plus a `secondary` ring**, so it
   read as an outline rather than a dot.
4. **`SystemMouseCursors.click` was installed even when `onChanged` was null**, so
   a read-only indicator showed a click cursor and swallowed taps no handler
   answered (same defect class as B01's `chip` / `badge`).
5. **`resolvedPadding` was multiplied by `theme.scaling` *after* it had been
   resolved**, so a caller-provided `padding` was silently inflated; the padding
   was also re-resolved inside the per-dot loop.
6. `IntrinsicHeight` + `Flex(crossAxisAlignment: stretch)` around `Flexible`
   children forced an O(n²) intrinsic pass for a fixed-size row.
7. Only `ComponentTheme.maybeOf` was read (no app leg) and there were **no
   token-derived defaults at all** — every field fell back to a literal.
8. `ActiveDotItem` / `InactiveDotItem` were public classes each re-declaring the
   same five parameters plus their own `Styleable` theme handle.

### 3.9 anchor

1. **`OverlayAnchorRegistry.global` was process-wide mutable state.** Every
   anchor outside an `OverlayAnchorScope` registered there, so keys had to be
   globally unique and two screens could collide. There is no global registry
   now: `OverlayAnchor` asserts it sits under a scope, `LinkedAnchor` resolves
   one from the `show()` context.
2. **`AnchorSubscription`'s doc said "there's no explicit dispose method"** while
   both implementations were `ChangeNotifier`s whose per-frame `Ticker` kept
   running until `dispose()` was called. `dispose()` is now part of the
   interface.
3. `LinkedAnchor.subscribe()` **fell back to `OverlayAnchorRegistry.global`** when
   it had not been resolved, silently binding to the wrong tree. It asserts now.
4. `_LinkedAnchorSubscription.isVisible` used
   `entry.context.findRenderObject() != null`, which **stays non-null for a
   detached element**; it checks `RenderBox.attached`.
5. `anchorTransformRelativeTo` called `Matrix4.invert()`, which **throws on a
   singular matrix** (a zero-scale source). It yields the identity now.
6. `OverlayAnchorEntry.context` was only ever read through the stale
   `findRenderObject()` check; the field is dropped and the entry carries the
   `RenderBox` alone.
7. `package:data_widget/data_widget.dart` (banned) and **two
   `// ignore: invalid_use_of_protected_member`** comments — the ignores were
   also unnecessary, since `BuildContext.findRenderObject()` is public API
   (only `BuildContext.size` is `@protected`).

### 3.10 backdrop_transform

1. **`ScaleBackdropTransform.resolveExtraSize` never freed any space for the
   root layer.** The formula was `size - size * scale / minScale`; at `t = 1`
   that is `w - w*minScale/minScale == 0`, and at `t = 0.5` it is
   `300 - 292.5/0.95 = -7.9`, clamped to `0`. Every `t` returned zero. One
   formula (`size * (1 - scale)`) now serves both layers.
2. **`minScale` was unchecked**: `0` made the old root formula divide by zero
   (infinity), and any value `> 1` grew the backdrop past its box. Asserted to be
   in `(0, 1]`.
3. **`scaleAt(t)` extrapolated outside `0..1`** — an overshooting
   `animateTo` curve produced a scale below `minScale` or above `1`. Clamped.
4. `cornerRadius` fell back to the old `Theme.of(context).radiusXxl`;
   `ShadcnTheme.of(context).radiusXxl` now.

## 4. Deviations from the batch data (with reasons)

1. **`debug` is not migrated** (§2.1). Binding orchestrator decision Q4.
2. **`anchor` declares `deps.primitives: []`** although the batch data lists
   `["overlay"]`. `primitives/overlay.dart` (`OverlayHandler`,
   `PopoverOverlayHandler`, `OverlayBarrier`, `PopoverConstraint`) is not used by
   this component; declaring it would raise an `unused-dependency` warning.
3. **`page_route`, `patch`, `async`, `anchor`, `backdrop_transform` have no
   `<name>_style.dart` / `<name>_theme.dart`.** They paint no surface, so there
   is no token-derived property to theme; an empty theme class would be dead
   weight. Each `meta.json` says `"theme": null` with a one-line reason. The
   `installable` and `check_user_theme` rules only validate the files that exist.
4. **`image`, `dot_indicator` and `switcher` declare `deps.foundation:
   ["constants"]`** (not in the batch data) because their `*_style.dart` defaults
   use `kDefaultDuration`, matching `dialog`/`dot_indicator`'s existing
   convention.
5. **`media_query` declares `theme: ["color_tokens", "theme"]`** (not in the
   batch data) because `Mergeable` lives in `color_tokens.dart`.
6. **`image` is a real component built from scratch.** The batch described it as
   a "2-file tiny leaf", but the old entry file declared nothing. Building it on
   `ImageProvider` → `ImageStream` → `RawImage` (rather than wrapping widgets'
   `Image`) is what lets it keep a themed placeholder layer and a fade-in.
7. **`Image` was renamed `ShadcnImage`** (QA round 2, F1). See §8. The component
   id, directory and entry file stay `image`; no prefixed imports are needed
   anywhere.
8. **`kDefaultPageTransitionDuration` → `kShadcnPageTransitionDuration`** (clean
   break, disambiguates from foundation's `kDefaultDuration`).
9. **`overlay/anchor` dropped `OverlayAnchorEntry.context`** — it was only read
   through a check that is now wrong (§3.9.4). B12 (`overlay_configuration`) must
   not depend on that field; `RenderBox` is the live source.
10. **Preview cross-component imports** (`spinner` in `async`, `button` +
    `dialog` in `page_route`, `button` in `patch`, `clickable` + `button` in
    `switcher`, `button` in `anchor`) are not declared in `deps`: `preview.dart`
    is excluded from both the undeclared- and unused-dependency rules.

## 5. Open questions

- **Q1 — RESOLVED in QA round 2 (F1).** `Image` → `ShadcnImage`; see §8. A
  follow-up audit proved no other public name in this batch collides, so
  `ImageTheme`, `ImageErrorBuilder`, `DotStyle`, `SwitcherTheme`,
  `MediaQueryVisibilityTheme`, `ClickDetector`, `ClickDetails`, `ClickCallback`,
  `DotBuilder`, `DotIndicator*`, `Anchor*`, `ContextAnchor`, `LinkedAnchor`,
  `OverlayAnchor*`, `BackdropTransform`, `NoBackdropTransform`,
  `ScaleBackdropTransform`, `FutureOrBuilder` and
  `ShadcnPage*` all keep their plain names.
- **Q2 — ACCEPTED in QA round 2** (`Stopwatch` kept). Noted for the record:
  the threshold is not fake-clock testable, so `regression: a slow tap restarts
  the sequence` uses `tester.runAsync(Future.delayed(400ms))`.
  `SchedulerBinding.currentFrameTimeStamp` would be fake-clock driven but
  **asserts `_currentFrameTimeStamp != null`** for a tap that arrives in the
  gesture arena before the first frame (verified: it threw in every gesture
  test). `package:clock` is not a declared dependency of the app.
- **Q3 — DONE in QA round 2.** `Switcher.children.length` is documented on the
  field, in the README (with the `KeyedSubtree` recipe) and **asserted in
  debug**. The assert lives in `build()`, not `didUpdateWidget()`: a throw
  between the two hooks aborts the rebuild and leaves inherited elements with
  live dependents, which trips the framework's own
  `InheritedElement.debugDeactivated: _dependents.isEmpty` assertion during the
  *next* pump (verified — that is exactly what the first attempt did). Two
  regression tests cover it (`changing children.length asserts`,
  `a new key rebuilds with a longer list`).
- **Q4 — `switcher` drag direction.** `AxisDirection.right` moves the content
  rightwards, so the drag travels rightwards too (identical to the old sign
  convention, verified by the render object's offsets). Some authors expect
  `right` to mean "the next page comes from the right" (drag leftwards). I kept
  the old semantics rather than silently flipping a gesture, and documented it
  in the README. **QA decision wanted** if this should be flipped.
- **Q5 — FORWARDED TO B12 in QA round 2.** `anchor`'s scope requirement is a
  breaking change for any app that used `OverlayAnchor` without an
  `OverlayAnchorScope` and relied on the global registry. This is the intended
  fix (PLAN §5 single-owner / no global mutable state) but it will assert at
  runtime; B12 (`overlay_configuration`) must document it.
- **Q6 — `dot_indicator` padding semantics.** The old code folded the padding's
  left/right into the per-dot spacing. Padding is now the run's padding and
  `spacing` is purely the gap; the visual result is equivalent but the numbers
  a theme author must use differ. Noted in the README.
- **Q7 — CLOSED in QA round 2** (`debug` confirmed deleted). If a batch ever
  wants its two helpers, they belong in a developer-only package (`tool/` or the
  app's own `dev/` folder), not in `registry_next/components/`.
- **Q8 — `kShadcnPageTransitionDuration` consumers.** `grep` over the old tree
  shows only `navigation/page_route`'s own files reference the old constant
  name, so the rename collides with nothing today.

## 8. QA round 2 — F1 (name clashes with `package:flutter/widgets.dart`)

**Audit method (not a guess).** Every public type and constant this batch
declares was grepped against all ten libraries `package:flutter/widgets.dart`
re-exports — `src/widgets`, `src/painting`, `src/rendering`, `src/foundation`,
`src/animation`, `src/services`, `src/gestures`, `src/scheduler`,
`src/semantics`, `src/physics` (which is what
`src/widgets/basic.dart` re-exports) — plus `src/material` and
`src/cupertino`, with two passes (`^class|^typedef|^enum|^mixin` and a looser
`(class|mixin|enum|typedef|extension)[ ]+<Name>`).

**Result: exactly one clash — `Image`** (`src/widgets/image.dart:343`,
`class Image extends StatefulWidget`, exported by widgets.dart).

### 8.3 Q3 (Switcher) closed

`children.length` is documented on the field and in the README with the
`KeyedSubtree`/`Key` recipe, and **asserted in debug**:

```dart
assert(
  widget.children.length == _childCount,
  'Switcher.children must keep its length after the first build; the '
  'position range is fixed when the controller is created. Swap the page '
  'list with a new Key instead.',
);
```

The assert sits in **`build()`**, not `didUpdateWidget()` — measured, not
guessed. A throw in `didUpdateWidget` aborts the rebuild between the two
hooks, which leaves inherited elements holding live dependents and trips the
framework's own `InheritedElement.debugDeactivated: '_dependents.isEmpty' is
not true` assertion on the *next* pump, turning one clean failure into a
framework-level cascade. Asserting inside `build()` keeps the tree consistent.
Two regression tests: `regression: changing children.length asserts` and
`regression: a new key rebuilds with a longer list`.

`dot_indicator.dart` had a local `final shadcn = ShadcnTheme.of(context)`, which
read like the now-removed prefixed-import idiom. Renamed to `appTheme` so a
`grep "shadcn\."` over this batch comes back empty.
