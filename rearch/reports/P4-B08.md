## Deviations from the batch data (read this first)

Three of these need a decision from the plan owner.

### 1. `autocomplete` does **not** depend on `input` — it depends on `card`

The batch data declares `deps.components: ["input"]`. The ported feature does
not import `input`, so `check_layers` fails `undeclared-dependency` if the
declaration stays. Declared as `["card"]` instead.

This follows P3 design item **I2**: the public surface of `autocomplete` is
`AutoCompleteFeature extends InputFeature` only, and the old `AutoComplete`
wrapper widget is deleted. The field is the `input` component; the feature plugs
into `input`'s generic `SuggestionBuilder` slot. So `autocomplete` sits *above*
`input` in the data flow without importing it. `meta.json` documents the slot it
fills.

Also deleted: the duplicated `AutoCompleteMode` enum (two byte-different copies,
one a bare undocumented line) and the `@Deprecated`
`overlayConfiguration`/`adaptiveOverlay` theme fields, which no code path could
honour.

### 2. Two new primitives, because two components did not fit the 6-file budget

The folder rule allows exactly `<name>.dart`, `<name>_style.dart`,
`<name>_theme.dart`, `preview.dart`, `meta.json`, `README.md`. Splitting a
component by responsibility can only go *downward* into a primitive. Both new
primitives are shared with components still to be migrated (`select`, `menu`,
`tabs`), so this is duplication removal rather than relocation.

**`primitives/roving_group.dart`** — `RovingItem`, `RovingGroupRegistry`,
`RovingGroupScope`, `NextRovingItemIntent`, `PreviousRovingItemIntent`.

The non-obvious part: the traversal maps live on the **registry**, and each item
hands them to its own `Clickable(shortcuts:, actions:)`. A group-level `Shortcuts`
does not work — `Clickable` already binds the arrow keys to
`DirectionalFocusIntent`, and the *nearest* `Shortcuts` wins. This was found by
test, not by reading: the first roving implementation wrapped the items in
`Shortcuts` and the arrow keys silently did nothing.

**`primitives/selectable_radio/`** — `RadioItem<T>` (row), `RadioIndicator`,
`SelectableData`/`SelectableDataScope`, the lookup keys, plus
`RadioIndicatorStyle` / `SelectableRadioTheme` and their token defaults.

**The card item is deliberately *not* here.** A layer 2 file may not import a
layer 3 component, so `RadioCard` and `SelectableCardTheme` stay in
`radio_group/`. This surfaced as the single `layer-direction` error in the
whole-tree run and is why `radio_group.dart` is 388 lines rather than 201.

### 3. `keyboard_shortcut` drops its three shared typedefs

`KeyboardShortcutDisplayBuilder`, `KeyboardShortcutDisplayHandle` and
`shortcutActivatorToKeySet` already live in `foundation/keyboard.dart`. The old
component re-declared all three (the first two as `part` typedef aliases to
`shared/utils/keyboard_shortcut_utils.dart`). Only `foundation`'s copies are
kept; `meta.json` lists them under `api.providedByFoundation`.

## Additions to existing primitives

All three were forced by real bugs found while writing the tests, not by
refactoring taste. Each is covered by a regression test.

| File | Addition | Why |
|---|---|---|
| `primitives/input_features/input_features.dart` | `InputFeature.onFocusGained` | A field that starts out with text, or is focused without typing, never fires `onTextChanged`, so a text-driven feature (a suggestion list) never queried. `input` announces focus once per focus, resetting on blur. |
| `primitives/input_features/input_feature_host.dart` | `InputFeatureSlots.slotOf` / `InputFeatureState.featureSlotOf` | A feature has to release its slot in `dispose`; there was no way to look one up. |
| `primitives/localizations/localizations.dart` | 13 getters (`emptyState*` ×6, `dropzone*` ×7) | Both components had hard-coded English for their whole user-visible surface. English fallback only — **no translations were invented**; the other 45 locales inherit until someone adds one. |

`components/input/input.dart` gained ~19 lines of focus plumbing (net: 398 lines,
under the limit).

## Bugs fixed, per component

Each bullet has a matching test. Full detail is in each component's `README.md`
under "Fixed (not ported)".

### `autocomplete` (10)

- The list opened as soon as the parent handed over a non-empty list, before the
  user typed anything.
- `append` appended at the end of the text even when the caret sat in the middle.
- `Tab` was bound to "accept", which trapped focus in the field.
- The keyboard map went through `ListenableBuilder` + `FocusableActionDetector`,
  which is not in the key-event path of an `EditableText` — the arrow keys never
  reached it.
- The popover built its content from `SurfaceCard` + `Theme.of`, freezing the
  theme at show time.
- A dismissed list kept its highlight, so `Enter` applied a row the user could
  no longer see.
- (plus the enum duplication, the dead `@Deprecated` fields and the focus-query
  gap above)

### `radio_group` (7)

- `RadioItem` selected itself on **focus** (`onShowFocusHighlight` called
  `_setSelected`), so tabbing into a group changed the value before the user
  pressed anything.
- `NextItemIntent` / `PreviousItemIntent` were registered by *every* item and both
  just selected that item, so the arrow keys never moved.
- `RadioCard` computed a padding compensation as
  `borderWidth - selectedBorderWidth`, which went negative — and threw — whenever
  a theme set a wider selected border.
- `RadioCard` built `Card(filled:, fillColor:, boxShadow:)`, an API the accepted
  `Card` no longer has, so a themed card crashed at runtime.
- `RadioItem` had no label slot: the label had to be passed as `leading`, so the
  circle floated between two arbitrary widgets.
- `IntrinsicHeight` + `Row` per item row (an extra full layout pass per row).
- The group published its state through `data_widget`'s global registry; it is
  `Data` data now, comparing by value.

### `empty_state` (6)

- `EmptyStateTheme` extended the old `ComponentThemeData` **without implementing
  `Mergeable`**, so a leg that set only `iconColor` dropped every other value.
- `ignoreGlobalScaling` / `ignoreGlobalRadius` were multiplied in one flag at a
  time inside the widget, so the numbers depended on which flag was set.
- `cardFillColor` went into `Card(filled:, fillColor:)` — same removed API.
- Default title / description / icon were plain functions returning hard-coded
  English.
- Action spacing came from `theme.density.baseGap * scaling * gapMd` while the
  rest of the block used the size table, so a non-default density changed only
  the actions.
- `emptyStateThemeTokens` + `EmptyStateThemeSchema` were a second hand-maintained
  theme layer; one `EmptyStateTheme` with a per-size `EmptyStateMetrics` table
  replaces both.

### `keyboard_shortcut` (6)

- `KeyboardKeyDisplay` called `Data.of<KeyboardShortcutDisplayHandle>(context)`,
  which asserts when no mapper is installed — **any** chord rendered without an
  installed `KeyboardShortcutDisplayMapper` crashed on first render. The scope is
  optional now.
- It resolved its theme as `this.theme ?? ComponentTheme.maybeOf(...)`: the
  widget leg *replaced* the scoped leg and the app leg was never read at all.
- `KeyboardShortcutTheme` had no `Mergeable`, so a leg setting only `spacing`
  dropped `keyPadding` and `keyShadow`.
- It built `Card(padding:, fillColor:, filled:, boxShadow:)`, so every cap crashed
  — `keyShadow` defaulted to `null` and was still passed to `Card`.
- `resolvedPadding * theme.scaling` scaled only the padding, leaving the radius
  and shadow alone.
- `KeyboardShortcutTheme.copyWith` was a second, subtly different merge on top of
  the resolver's.

### `dropzone` (7)

- `_resolveBorderColor` returned `null` for `idle` and the outline was then
  painted with `color: null`, which `Border.all` rejects — **the default state
  crashed**.
- The status line and the browse label were hard-coded English.
- `DropzoneState.disabled` and `enabled: false` disagreed about whether the
  surface was outlined at all.
- A `LayoutBuilder` pinned `height: constraints.maxHeight` whenever the parent was
  bounded, so the dropzone swallowed the whole page instead of hugging its
  content.
- `focused` was a hand-rolled `BoxShadow` painted *under* the container, so it
  was invisible against most backgrounds.
- `showDefaultContent` had a state (`false` + `content: null`) that rendered an
  empty box, and made it impossible to keep the icon/status while hiding the
  default action.
- The border is a plain 1 px outline rather than a dashed one — the kit has no
  dashed primitive, and an approximating image would be dishonest.

## Theme conformance

- `<Name>Theme extends ComponentThemeData implements Mergeable<…>`, resolved with
  `resolveComponentStyle<NameTheme, NameTheme>(context, widget:, select: (t) => t,
  defaults: <name>Defaults)`. All 5 themes verified.
- Per-field first-non-null-wins merge, receiver wins, with a test for **every one
  of the four legs** (app / scoped / widget / partial-leg-keeps-the-rest) per
  component.
- Colours are `ThemedColor.ref(ColorRef.x)` and resolve at build; `alpha`
  multiplies the token's alpha (tested per component).
- Disabled = whole-item `Opacity(0.5)`; `keyboard_shortcut` has no disabled
  state, so it dims nothing.
- Strings come from `primitives/localizations`. **No translation was invented.**
  Key *glyphs* (`Ctrl`, `⌘`, `←`) are deliberately not localized: a shortcut has
  to read the same on every keyboard the user is on.
- `user-owned` `<name>_theme.dart` per component; `check_user_theme`: 0 findings.
- Sizes are asserted as real logical pixels: `h-9` = 36, `text-sm` = 14,
  `size-4` = 16, `px-1.5 py-0.5` = 6/4, `text-xs` = 12.
