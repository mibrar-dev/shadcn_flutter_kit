## 2. Bugs fixed (never ported)

### form
1. **Detached fields leaked.** `FormController.detach` was commented out, so
   unmounted fields stayed in `values`/`errors` forever. `FormEntry` detaches on
   unmount and the controller removes the registration (regression test:
   "unmounting a field detaches it").
2. **Revalidation kept the wrong lifecycle.** `revalidate()` went through the
   `forceRevalidate` flag, which still selected `FormValidationMode.changed`, so
   validators that only run on submit never ran. Revalidation now uses
   `submitted` (regression test: "revalidation uses submitted mode").
3. **Two parallel form systems.** The old tree had `FormFieldHandle` (component)
   and `shared_form.FormFieldHandle` (shared primitives) bridged by
   `SharedFormHandleAdapter`, which forwarded values but returned `null`
   validity. `form_core` now owns the single handle type.
4. **25+ `*Key` aliases** (`TextFieldKey`, `CheckboxKey`, `SelectKey`, …) were
   one-line `FormKey` aliases; dropped with the clean break.
5. `URLValidator` never failed: `Uri.parse` accepts almost any string. It now
   requires a scheme and a host.
6. `EmailValidator` no longer pulls `package:email_validator` into every
   install; it uses a documented `local@domain.tld` shape check.
7. `SubmitButton` (171 lines, 0 users) and the five zero-user helpers above were
   deleted instead of being ported "faithfully".
8. The old `ObjectFormField` dialog handed the whole editor to Material's
   `AlertDialog`; the new prompt is a widgets-only `showGeneralDialog` page that
   captures themes and data (dialog leg) and reuses `PopoverController` for the
   popover leg.

### command
1. **Four Material imports** (`command_widget`, `command_dialog`,
   `command_state`, `command_item_state`) removed; the surface paints from
   `CommandTheme`.
2. **Stale requests leaked**: the old generator kept `await for`-ing the
   previous builder stream forever (`continue` instead of stop). A new query
   cancels the old request (regression test: "a stale query stops feeding the
   list").
3. **`errorBuilder` was dead**: the `StreamBuilder` never checked `hasError`.
   Errors now render the builder (regression test).
4. **Infinite spinner**: the old list appended a spinner whenever the stream was
   active, so a never-completing stream showed a spinner forever.
5. **Read-only rows were clickable**: a `CommandItem` without `onTap` dimmed its
   label but still swallowed clicks and showed hover. `SubFocusListItem` builds
   no `Clickable` when disabled.
6. **Missing Navigator crash**: `Navigator.of(context).canPop()` threw for an
   inline palette outside a Navigator; now `Navigator.maybeOf(...)`.
7. A stream that completed without emitting left the old list area on its
   loading indicator forever; the new `_CommandResults` maps `done` + no data to
   the empty state.

### multiple_choice
1. **Single choice could not change.** `selectItem` returned early whenever a
   value existed (`if (value != null && value != item) return;`), so a second
   tap on another item did nothing. Selecting now replaces
   (regression test: "a new tap replaces the current selection").
2. **`allowUnselect` read the wrong legs**: `widget.theme ?? tree` skipped the
   app leg and let a widget override drop the whole theme. It resolves through
   all four legs now (tested).
3. Items now repaint on selection change even when they are const
   (`AlwaysUpdateData` on the scope state); the old data identity check left
   const items stale.

### star_rating
1. **Material import** (`Colors.white` star background) removed; stars paint
   with `StarBorder` from `painting.dart` and no background square.
2. **Double tap callback**: the old row called `onChanged` on tap-down and again
   on tap-up. One commit per tap (regression test).
3. **Unclamped/un-snapped values**: display and committed values clamp to
   `[0, max]` and snap to `step`.
4. **Disabled cursor** was `SystemMouseCursors.forbidden`; now the system arrow
   with `Opacity(0.5)` (house rule).
5. Theme resolution read `widget.theme ?? tree`; all four legs resolve per field.
6. Horizontal pointer mapping honours RTL (fills from the right); the old one
   always measured from the left.
7. `rotation` documented in degrees (it always reached `StarBorder`, which
   takes degrees, while the old doc claimed radians).
8. Sticky hover preview removed; drag updates live.

### locale_utils
1. **RangeError clamp**: the old formatter indexed `units[digitGroups]`
   unclamped; values past the last unit now stay in it (regression test).
2. `separator` was dead; the integer part is grouped now.
3. `fileBits` renamed `binaryBytes` (it held binary *bytes* and started at
   `Bi` even for whole bytes).
4. `getUnit` dropped (never read).

## 3. Deviations from the batch data (with reasons)

1. **Form machinery moved to `primitives/form_core/`** (`validators.dart`,
   `validators_compare.dart`, `validation.dart`, `form_controller.dart`,
   `form_entry.dart`, `form_builders.dart`, `object_form_field.dart`,
   `object_form_prompt.dart`). The component folder allows only
   `<name>.dart` / `<name>_style.dart` / `<name>_theme.dart` / `preview.dart` /
   `meta.json` / `README.md`; the form machinery is ~2300 lines and P4_PLAN
   already states "form state lives in primitives/form_core; the component only
   holds the Form UI". `form.dart` re-exports everything consumers need.
   `form_core` is listed in the batch's `primitives`.
2. **`primitives/subfocus_list_item.dart` is new** (not in the batch data).
   The old `CommandItem` row had to move so `command.dart` fits the file cap,
   and `SubFocus`'s own documentation scopes the mechanism to "menus, command
   palettes and similar keyboard-navigable lists" — later menu/select batches
   can reuse it. It is a shared primitive, tested on its own.
3. **`command` drops `CommandCategory`, `CommandKeyboardDisplay` and the
   keyboard-hint footer.** The component folder cap and the 774→350 LOC target
   leave no room for a second widget file; apps compose headers/footers around
   `Command` (the old footer used the dropped `CommandKeyboardDisplay`).
   Keyboard navigation itself is unchanged and tested.
4. **`command` uses `primitives/subfocus_item.dart` + `subfocus_scope.dart`**
   instead of the batch's `overlay`/`text_editing`: there is no overlay use
   (the dialog component owns the route) and no direct text-editing use (the
   search field is the `input` component). `localizations` + `input_features`
   are used (declared).
5. **`form` declares no `components` deps** although the batch lists
   `button`/`checkbox`/`input`: the new form UI composes no other component, and
   `ObjectFormField` (moved below the component layer) cannot import `button` by
   the layer rules, so its trigger and dialog actions paint from tokens. The old
   `SubmitButton` is dropped; use `Button` + `controller.submit(context)`.
6. **`form` meta declares `foundation: ["data"]`** (not in the batch data)
   because `Data.inherit` publishes the controller and the handle.
7. **`Form` / `FormField` renamed `ShadcnForm` / `ShadcnFormField`** (QA round
   2, F1): `package:flutter/widgets.dart` exports both names, and the house
   rule (ShadcnTheme / ShadcnImage / ShadcnTable) forbids clashes, so the
   component widgets carry the `Shadcn` prefix. `FormInline`,
   `FormTableLayout` and `FormFieldMessages` do not clash and keep their
   names. The old-tree `Form`/`FormField` symbols remain available as a
   migration reference only in the old registry.
8. **`star_rating` declares no `animation` primitive** (batch data lists it):
   the fill animation uses `TweenAnimationBuilder` from widgets, so declaring
   `animation` would raise `unused-dependency`.
9. **`multiple_choice` meta lists no primitives beyond `form_core`**, matching
   its imports (no `tokens`/`animation` additions).
10. **`validators.dart` split into `validators.dart` + `validators_compare.dart`**
    to satisfy the ~400-line file guideline after the move down.

## 4. Open questions

- **Q1 — form error decoration.** The old `FormField` wrapped its child in
  `FocusOutlineTheme` / `TextFieldTheme` overrides to paint a red border on the
  child. The new field only renders the message (and the label turns
  destructive); child error styling is the child's own concern (`input` has its
  own validator path). If later batches want the wrapper back it belongs in a
  shared "invalid-state scope" primitive.
- **Q2 — `ObjectFormField` presentation.** Dialog mode is now a
  widgets-only `showGeneralDialog` page (the old one used Material
  `AlertDialog`); item styles (`size`/`density`/`shape`) are gone. B13/B15/B21/
  B24 consume this and may want the extra knobs back via the component's theme.
- **Q3 — command keyboard hints footer.** Dropped for file budget; if the
  gallery wants it, it should return as its own small component (or a
  `KeyboardKeyDisplay` primitive) reused by `keyboard_shortcut` (B08).
- **Q4 — `FormPending` naming.** The L2 `FormPendingBuilder` is
  controller-free (P2E2 carry); the component provides the controller-aware
  `FormPending`. Two names for one concept is the honest cost of the layer
  split; QA may prefer to rename.

## 5. QA round 2 (2026-10-08)

- **F1 — name clashes removed.** `Form` → `ShadcnForm`, `FormField` →
  `ShadcnFormField` in the component, preview, tests, meta and README; the
  `hide Form, FormField` advice and its import-note block are gone. A scan of
  every public name added by this batch (components + `primitives/form_core`)
  against `package:flutter/widgets.dart` found no other clash. `Form.of` /
  `Form.maybeOf` are now `ShadcnForm.of` / `ShadcnForm.maybeOf`.
- **F2 — `CommandShortcut` added** (in `command_style.dart`, because
  `command.dart` is at the 400-line cap): extra-small type, `tracking-widest`
  (`theme.tracking.wide ?? 1.2`), `CommandTheme.mutedForeground`, right-aligned
  via `Align(AlignmentDirectional.centerEnd)` + `TextAlign.end`. Keyboard-key
  visuals stay out (B08 `keyboard_shortcut` owns them). Covered by a new
  command test (light/dark, colour, size, tracking, alignment).
- Decisions recorded: invalid-state scope later (ok), `ObjectFormField` knobs
  via theme later (ok), `FormPending` naming kept.
