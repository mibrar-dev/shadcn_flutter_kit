### F2 — popover crash (root-caused and FIXED)
Root cause: `Input.build` passes a fresh `ShadcnSelectionControls()` to
`EditableText` on every build, and `TextSelectionControls` uses identity
equality. Every overlay rebuild re-invokes the popover builder — which creates
fresh `Input` instances by Flutter convention — so `EditableText.didUpdateWidget`
sees `selectionControls !=` and disposes + recreates its `TextSelectionOverlay`:
entries are removed and disposed synchronously mid-build with re-show deferred
to post-frame, and the Overlay then builds a widget for a disposed entry ⇒
`Null check operator` (`_overlayEntryStateNotifier!`) in
`_OverlayEntryWidgetState.initState`, followed by duplicate-GlobalKey fallout.
Correction to the round-1 note: the minimal trigger is a SINGLE plain fresh
`Input` in a popover + tap (proven by bisection); "two TimeFormatter inputs"
was only the observed shape — formatter and count are irrelevant.
Fix (owning primitive `primitives/text_editing/text_editing.dart`, +17 lines):
value `operator ==`/`hashCode` on `ShadcnSelectionControls` (color, handleSize),
so fresh-but-equal controls no longer churn the selection overlay. One fix
covers all six construction sites (input, input_otp, formatted_input,
selectable, markdown, file_diff_viewer).
Regression tests: `time_picker_test.dart` gains `popover clock sheet digit tap
keeps the overlay alive` (real component path) and `two TimeFormatter fields
in a popover survive a tap` (original repro shape); `text_editing_test.dart`
gains `selection controls compare by value, not identity`. Verified the three
new tests FAIL with the fix neutralised (identity `==`) and PASS with it.
