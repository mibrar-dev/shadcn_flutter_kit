## Deviations (read this first)

### 1. `input.dart` changed — required, kept, and now tested (QA F3)

`InputFeature.onFocusGained` existed in `primitives/input_features/`
with a documented contract ("Called the first time the field takes focus after
a rebuild, and again whenever it regains focus") but **nothing ever called it**.
`chip_input` is the reader that needs it: tap a field that already holds chips
and the suggestion list must open for the next chip — `onTextChanged` never
fired for that case, so the list stayed closed until the first keystroke.

Change kept: `_InputState._focusAnnounced` plus `_notifyFocusGained()`, called
from `build` (which already rebuilds on focus change through
`WidgetStatesController.onStatesChanged`). Features are announced once per
focus session; the flag resets when the field blurs.

Two new tests in `test/registry_next/components/input_test.dart` prove it, as
requested:

* `a feature gets onFocusGained for a pre-filled field` — `initialValue:
  'already filled'`, `focusGained == 0` before the tap, `== 1` after, the
  announced text is `'already filled'`, and `onTextChanged` never fired.
* `a feature gets onFocusGained for focus without typing` — no keystroke, still
  announced; a rebuild inside the same session does not double-fire; after
  `unfocus()` + refocus it announces again (the reset branch).

### 2. Four token files, not three

`token_units.dart` was split out of `token_editing.dart` because the combined
file came to 442 lines (the `file-too-long` gate). It holds the Private-Use-Area
code-unit representation and the two scrubbers that keep a field's text and
selection consistent with its token registry. No component imports it directly;
`token_editing.dart` re-exports it.

### 3. `DecoratedChipClipboardHandler` is not ported as-is

Its prefix/suffix/escape grammar had **zero callers** in this repo. The one
behaviour worth keeping — "separator written between adjacent chips on copy and
consumed as a token boundary on paste" — is now
`PlainTokenClipboardHandler.chipDeserializer`, which `ChipInput` wires to
`onChipSubmit` by default, so copy and paste round-trip.

### 4. API reduced to fit the 400-line file

`placeholder`, `autofocus`, `textInputAction` and `textCapitalization` are gone
from `ChipInput`. The hint is `hintText`; the keyboard action is hardcoded to
`TextInputAction.done`. No behavioural loss for the documented use case.

### 5. `removable` is a new theme field

The old component had no such flag (verified against HEAD). Here it means
"whether each token gets a remove button" — the `Chip` wrapper is always
rendered, so a read-only or disabled field still shows chips, not bare text.

### 6. Token primitive unit tests live in `chip_input_test.dart`

`qa_batch.sh` maps the `primitives/text_editing` argument to
`test/registry_next/primitives/text_editing_test.dart` only, and that file is
already at its practical size. Putting the `token_{editing,span,clipboard}`
unit tests in `chip_input_test.dart` guarantees the gate runs them.

## Bugs fixed (each has a regression test)

1. The `padding` theme leg was read inside a closure that ignored the widget
   value (the P3-B QA pattern). All four legs now go through
   `resolveComponentStyle<ChipInputTheme, ChipInputTheme>`; the widget leg wins.
2. Copy produced an unreadable string: the default separator was `''`, so
   copying `["ab","cd"]` wrote `abcd`. Default is now `', '` —
   `copy writes readable values, never code units` asserts `'flutter, shadcn'`
   and that no Private-Use code unit reaches the clipboard.
3. `DecoratedChipClipboardHandler` (delimiter round-trip) had no caller, so
   paste never rebuilt chips. `pasting a delimited string splits into chips`
   now covers it end to end through `token_clipboard`.
4. The controller assigned a PUA code unit without registering a token, leaving
   an invisible character in the value. `TokenEditingController` scrubs
   unregistered units and shifts the selection —
   `regression: an unregistered code unit is stripped, not stored`.
5. `ChipSpan` carried no token index, so removing the second of two equal values
   was ambiguous. `TokenSpan.index` (and the `chipBuilder` index) make it
   addressable — `the remove button deletes exactly its own chip` on
   `['a','a','b']`.
6. `InputFeature.onFocusGained` was never invoked (see deviation 1).
7. `removable: false` dropped the `Chip` wrapper, rendering tokens as bare text.
8. A disabled or read-only field still accepted `Enter` and pasted raw text.
   The submit action is only registered when the field is editable; copy stays
   registered (a read-only field must serialize chips, not code units) and paste
   is consumed but inert.
