### Bugs fixed

- **Every keystroke was dropped in controller mode.** The mirror value was
  seeded from `value ?? initialValue` only, so a controller-driven field wrote
  each change into an *empty* `SegmentedValue` — the part list was lost and the
  controller always read back `''`. Regression test: `controller: typing writes
  through the controller`.
- **A same-shape value swap tore down every segment.** The rebuild check
  compared the whole part list *including values*, so each parent rebuild (every
  keystroke in controlled mode) disposed the live `TextEditingController`s and
  threw away the caret. `SegmentedValue.hasShape` (new) compares the shape
  only; a value swap now flows through the existing controllers. Regression
  test: `a same-shape value swap keeps the focus and the caret`.
- **Backspace / <kbd>←</kbd> at the start of a segment did nothing.** The key
  handler looked the segment up by node identity, but `Focus.onKeyEvent` is
  invoked on the *handler's* node, not on the primary focus, so the lookup
  always returned `-1`. It now finds the focused segment with `indexWhere(hasFocus)`.
  Regression test: `keyboard: backspace at the start steps back a segment`.
- **A visible error could never clear.** `FormValidationMode.initial` /
  `submitted` validate once, so the error stayed on screen while the user fixed
  the field. A shown error now revalidates on every change. Regression test:
  `an initial-mode error clears once the value is valid`.
- **`SegmentPart.editable(inputFormatters:)` was silently ignored.** The widget
  passed `part.segment.formatters()`, but `SegmentPart.segment` never copied the
  formatters across, so a digits-only mask did nothing. Regression test: `the
  segment keeps its own formatters`.
- The composing region lost its underline in the first port (`textInside` was
  concatenated with no style); `TextDecoration.underline` is back.
- The filler `_` padding resolved `theme.colorScheme.mutedForeground` (a
  non-token colour) and used `max(0, …)`; it now resolves
  `ShadcnTheme.of(context).colors.mutedForeground` and clamps.
- `_FormattedSelectionCoordinator`'s drag selection (`onDragStart` /
  `onDragUpdate` / `onDragEnd`, `_estimateOffset`, `_dragging`,
  `_dragAnchorPart`, `_dragAnchorOffset`) was never wired to a gesture hook —
  the old file says so in its own doc comment — and every call walked the live
  element tree looking for mounted states. Deleted.
- `package:flutter/material.dart` import, the per-part `FormKey` wiring (one
  field now registers one `SegmentedValue`), and the `// ignore_for_file`
  headers on 23 of the 25 files are gone.

### Deviations

- `component_deps` from the batch data (`button`, `form`, `input`,
  `outlined_container`) are **all dropped**: the new component imports no other
  component. Declaring them would trip `unused-dependency`.
- `WidgetPart` is dropped — a part whose content was an arbitrary widget made
  the value model describe layout as well as data. `leading` / `trailing` cover
  decoration.
- `FormattedObjectInput` (+ its state + controller) is dropped; B21 composes
  `FormattedInput` with `ObjectFormField`.
- `onPartsChanged`, `readOnly`, `autofocus`, `maxLengthEnforcement` and the
  per-part widget list are dropped. `enabled: false` is the read-only path;
  autofocus is meaningless when the field owns N focus nodes; the length
  enforcement mode is unused by shadcn text fields.
- Cross-part select-all / copy is not wired to the widget;
  `SegmentedTextController.selectAll` / `selectedText` stay available.
- Two new primitives were needed to fit the 2×400-line budget (the value model
  and the segment controller are reusable on their own).

### Open questions

- The `width` of a `SegmentPart.editable` is a fixed logical width, so a mask
  does not reflow when the density scale changes. `TextSegment.textAlign` is
  available but the widget always centres; a caller who needs `start`
  alignment has to set `leading`/`trailing` instead.
- The validator receives the *joined* text (separators included). Counting
  digits therefore has to strip them. Passing the editable-only text as a
  second argument would be friendlier; left as-is to match `input`.

### Bugs fixed

- `package:flutter/material.dart` (imported only for `Icons`) is gone; the
  chevron comes from `foundation/icons`.
- The node API was defined **three times** — static methods on `TreeView`, a
  `List` extension, and a deprecated `Tree` subclass forwarding both (~600 LOC
  of duplication). One `TreeNodeListExtension` remains.
- Shift-click range selection and Ctrl-click multi-select ran through
  `Actions`/`Shortcuts` inside a `FocusScope` holding a mutable
  `_multiSelect` / `_rangeMultiSelect` flag pair. Selection is now reported
  through `onSelectionChanged(nodes, multiSelect, selected)` and applied with
  `setSelectedNodes` / `updateNodes`. The flags had a bug anyway: the Shift/Ctrl
  key-up handler could leave `_rangeMultiSelect` stuck when the focus moved.
- `_borderRadiusFromPosition` silently returned a zero radius for an unknown
  position; `TreeSelectionPosition` is now exhaustive (`switch`, no `default`).
- The row painted its selection into an `AnimatedContainer` whose decoration
  resolved against `theme.colorScheme.primary.scaleAlpha(...)` — a non-token
  colour. Selection now resolves
  `ThemedColor.ref(ColorRef.primary, alpha:)`.
- `_mapNodes` copied the whole list once per level of recursion; the new
  `_flatten` reuses a single output list.
- The old state rebuilt the whole flattened list on every build and recomputed
  the selection run with a quadratic nested loop; the run detection is a single
  pass.
- Indent guides were drawn with a `CustomPainter`; they are now `ColoredBox` /
  `Stack` inside an `IntrinsicHeight`, which keeps the render tree inspectable.

### Deviations

- `selectNodes` / `deselectNodes` / `toggleSelectNode` and the shift-click range
  selection are **dropped** (see above). `updateNodes` is the general primitive
  every method is built on.
- `TreeRoot` is dropped (no callers).
- The widget is named `Tree` (the shadcn/upstream name) instead of `TreeView`.
- `deps.components: ["icon"]` is kept because the row's chevron is built with
  `Icon`; `deps.foundation: ["data", "icons"]` as listed.

### Open questions

- The row's `depth` is derived from the traversal, not stored on the node, so a
  node moved between parents re-indents automatically — but there is no
  "collapse subtree on reparent" hook, which the old `updateChildren` had.
- `recursiveSelection` is applied to siblings on toggle only; selecting a parent
  does not walk an expanded subtree (matching the old behaviour).

| `_impl/core/stepper_step.dart`, `stepper_data.dart`, `stepper_variant.dart`, `stepper_step_state.dart` | `stepper.dart` / `stepper_style.dart` |
| `_impl/utils/stepper_controller.dart`, `stepper_value.dart` | `stepper.dart` (`StepperController extends ChangeNotifier`) |
| `_impl/themes/*` | `stepper_style.dart` (`StepperTheme`, `StepperIndicatorStyle`, `stepperDefaults`) + user `stepper_theme.dart` |
| `StepperVariant` (3 values) | `StepperIndicator` enum in `stepper_style.dart` — one variant (`circle`) |

LOC: old 2058 → new `stepper.dart` 359 + `stepper_style.dart` 396 +
`stepper_theme.dart` 22 + `preview.dart` 105 = **882** (target 800).

### Bugs fixed

- `package:flutter/material.dart` is gone (`Icon`, `Icons.check`,
  `Colors.*` → `foundation/icons`, `ThemedColor.ref`).
- The old controller stored a `StepperValue` snapshot and compared it with
  `==`, so two structurally identical states re-notified listeners. The new
  `StepperController extends ChangeNotifier` only notifies on an actual change.
- The connector was drawn as soon as a step was *reached*, so a failed step kept
  a green line behind it. The connector is `pending` until the step is passed.
- A failed step's label used the plain foreground colour and was
  indistinguishable from a pending one; it now uses `destructiveForeground`.
- The indicator animation ticked on every rebuild because the controller was
  rebuilt with the widget; the phase is now derived state.
- `ThemeExtension`-style `copyWith`/`lerp` on the theme classes are gone
  (nothing in `registry_next` calls them).

### Deviations

- **The `circleAlt` and `line` variants are dropped**; the stepper keeps one
  `circle` indicator. Three variants of a 20-field theme class did not fit the
  2×400-line budget alongside the state, and the `line` variant needed a
  `CustomPainter` the other two did not. If a consumer needs them, the shape is
  an enum member plus a `StepperIndicatorStyle` branch.
- `StepperVariant` and the per-step `subtitle` are dropped (the step row is a
  title + optional content).
- `copyWith` / `lerp` dropped from the theme classes.
- `firstFailedStep` is exposed as a top-level helper rather than a static on the
  controller.

### Open questions

- `StepperController` is a `ChangeNotifier` and not a `ValueNotifier<StepperState>`,
  so there is no value-equality short-circuit at the type level — the
  `currentStep` setter does the comparison itself.
- `StepperStep` is a plain immutable value with no `copyWith`; callers rebuild
  the list with `List.of(...)` when a step changes. A `copyWith` would be ~15
  lines and would not fit.

`SegmentedValue.hasShape` was added during this batch's QA: the component needs
to know whether a new value implies a *new set of segments* (rebuild) or only
new *contents* (write through). That distinction is value-model knowledge, not
widget knowledge, so it lives with the model.
