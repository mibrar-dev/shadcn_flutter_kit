1. Material import (the batch's named bug).
2. Vertical mode measured the overflow on **width**

   right edge and scrolls the other way (test).
6. Reduced motion: `MediaQuery.disableAnimations` stops the ticker and holds
   the start position (test; read through `MediaQuery.maybeOf` so a bare tree
   without a `MediaQuery` ancestor does not assert).

  `primitives/animation.dart:pingPongProgress` (rest → run → rest → mirrored

## Deviations

1. **chat reactions are not ported.** `ChatReaction`'s overlap layout needed
   a bespoke render object (170 lines) to hang a badge over one bubble; the
   batch's 900 LOC target and the three-file folder cap left no room, and it
   is single-consumer. The pill (`ChatReactionContainer`) went with it — the
   README documents the `Stack` + `Positioned` recipe. `ChatCollapsible` was
   dead code (nothing read it) and is deleted, as is `ChatBubbleData.copyWith`.
2. **`file_diff_viewer` models live in `<name>_style.dart`.** The folder may
   hold at most `<name>.dart`, `<name>_style.dart`, `<name>_theme.dart`,
   `preview.dart`, `meta.json`, `README.md`, and the models + theme together
   exceed two files' budget in one file each; a primitive was not on the
   batch's list. `ChatBubbleData` likewise lives in `chat.dart`.
3. **`file_diff_viewer` theme is 8 fields, not the old 22-value resolved
   style**: `headerBackground` (= `muted`), `gutterForeground`,
   `gutterWidth`, `codeFontFamily`, `codeFontSize`, `lineRadius`,
   `markerWidth`, `markerSize`, `lineBackgroundOpacity` and
   `segmentHighlightOpacity` resolve at build from tokens/density/ambient
   typography (documented in the README). `FileDiffLine`'s named
   constructors (`FileDiffLine.addition(…)` etc.) were dropped for one
   constructor + `type:` (clean break); `FileDiffSegment` (inline highlight
   metadata, zero producers in the old tree) is deleted. The marker circle
   badge became a coloured `+`/`-` glyph (measured sizes: gutter 52×scaling,
   marker column 32×scaling kept). The header now reuses `linePadding`
   instead of a second themable padding.
4. **`border_loading`**: `spec`, `tracer`, `shapeBorder` and `backgroundColor`
   stay widget-level arguments (they are detailed render configs); the theme
   covers mode/stroke/padding/radius/duration/curve/opacity. The old
   `BorderLoadingSpec` extension point is kept (`BorderLoadingSpec` abstract
   + `BorderGradientSpec`).
5. **`chat`**: the group avatar default moved from vertical-centre
   (`AxisAlignmentDirectional.end` + `asVerticalAlignment(center)`) to
   `AlignmentDirectional.topEnd` (the usual chat layout); `position` on the
   tail (`AxisDirectional`) is gone — the tail always hangs downward from the
   bubble's side corner, derived from `alignment` (RTL-aware). The
   `widthFactor` bubble measure uses a `LayoutBuilder`, so a bubble cannot sit
   inside an `IntrinsicHeight`/`IntrinsicWidth` (they ask for intrinsics,
   which `LayoutBuilder` refuses); the old render object supported that — see
   open question Q2.
6. **`timeline_animation` has no `*_style.dart`/`*_theme.dart`**: there is no
   theming surface (the old component had none either), so `meta.json` has no
   `theme` section; `meta.json` `files` lists the two files that exist.
7. `timeline` keeps its `.medium().small()` visual result through
   `primitives/text`, so `deps.primitives: ["text"]` matches the batch data;
   `file_diff_viewer` does **not** import `primitives/text` (its code style
   comes from the ambient typography) but does import
   `primitives/localizations` (`menuCopy`) and `primitives/text_editing`
   (`ShadcnSelectionControls`) — `meta.json` matches the imports exactly, as
   the checker enforces. `overflow_marquee` declares
   `primitives: ["animation"]` (the shared `pingPongProgress`).
8. Old meta.json `component_deps` for chat were `[basic, button,
   outlined_container]`, but the old sources import none of them (dead
   metadata); the new chat imports no other component, so
   `deps.components` is `[]`. `file_diff_viewer` imports the pilot `button`
   for its copy action and declares `deps.components: ["button"]`.

## QA round 2 — F1 reactions + F2 intrinsic sizing

Both restorations landed; nothing else changed in the other five components.

### F2 — bubble intrinsic sizing (new primitive)

`lib/registry_next/primitives/fractional_align_box.dart` (128 LOC) +
`test/registry_next/primitives/fractional_align_box_test.dart` (148):

- `FractionalAlignBox(factor:, alignment:, child:)` + `FractionalAlignBoxRender`
  (a `RenderShiftedBox`): lays the child out under `maxWidth * factor`
  (non-finite incoming width ignores the factor), sizes itself from the
  constraints, aligns the child with the resolved `AlignmentGeometry`, and
  **forwards every intrinsic query to the child** — which a `LayoutBuilder`
  refuses (`does not support returning intrinsic dimensions`).
- `ChatBubble.build` now returns `FractionalAlignBox` instead of
  `LayoutBuilder` + `Align` + `ConstrainedBox`, and `ChatGroup` got its
  `IntrinsicHeight` back (removed in round 1 only because the LayoutBuilder
  could not answer it). The README limitation note is replaced by the
  supported statement.
- Tests: factor caps a 300px child to 200 in a 400px row; a smaller child
  keeps its size and hugs the end edge; a non-finite parent width ignores the
  factor; `IntrinsicWidth` + `IntrinsicHeight` wrappers answer (with the
  measured 140×30 box); RTL `AlignmentDirectional.centerStart` resolves to
  the right edge.
- Chat regression tests (`F2` block): group list under `IntrinsicHeight`,
  `IntrinsicWidth`/`IntrinsicHeight` around a single bubble, and bubbles
  stretched across a row under `IntrinsicHeight` — all three threw with the
  old layout (`RenderFlex children have non-zero flex but incoming width
  constraints are unbounded` came from the *test's* bare horizontal Row,
  which never bounds its non-flex children; the group scenario therefore
  lives in a `Column`, which is how a chat list is really laid out).

### F1 — chat reactions restored (new primitive + chat widgets)

`lib/registry_next/primitives/overlap_layout.dart` (291 LOC) +
`test/registry_next/primitives/overlap_layout_test.dart` (150), plus the chat
side in `chat.dart` / `chat_style.dart`:

- `OverlapLayout` (+ `OverlapCorner`, `OverlapParentData`,
  `OverlapLayoutRender`) — the ported `_ChatReactionRenderObject`: lays the
  overlap out loose, widens the primary child to `max(natural,
  overlap + extraWidth)`, places the badge at its corner with `gap`, grows the

  Bug found while testing: `BoxConstraints.tighten(width:)` **clamps** to the

- `ChatReaction` (chat.dart): wraps the bubble, derives the corner from the

- `ChatReactionContainer` (chat.dart): the pill — `onTap` toggle callback,
