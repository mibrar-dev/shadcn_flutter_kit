### Restored (had a consumer or were documented user-facing API)

`ErrorHandledRepository` (+ `execute`/`executeSync`/`executeWithHandler`),
`RetryStrategy` (exponential backoff + jitter), `ErrorReporter` /
`ConsoleErrorReporter`, `Env.showTechnicalDetails`, `fingerprintFor`,
`fallbackRule`, `ErrorRegistry`, `guardSync`, `AppError.copyWithActions` /
`hasMetadata`, the typed exceptions, the per-domain rule builders (`apiRules`,
`authRules`, `validationRules`, `platformRules`, `networkRules`),
`ScreenErrorScope`'s `clearOnInit` / `runSync`, `ErrorSlot`, `AppErrorGate`'s
`overlayBuilder` / `blockInteraction`, the `BuildContext` extensions
(`context.showErrorDialog` / `context.showErrorSnackbar`), and all seven
`ErrorAction` factories (`retry`/`report`/`back`/`login`/`settings`/
`contactSupport`/`dismiss`).

### Still dropped (with reason)

- `ErrorSnackbar`'s raw `OverlayEntry` machinery + static entry list:
  `showErrorSnackbar` uses the `toast` component's `showToast`, which owns the
  queue and lifecycle. (Behaviour preserved, ownership fixed.)
- The deprecated `AppErrorHub.global` / `scope` aliases (clean break).
- `networkRules`' old `dart:io` conditional-import trio. It declares the same
  top-level `networkRules` twice, which `check_single_owner` rejects (owner
  units are per file inside a primitive folder), and `dart:io` types cannot be
  named on web. It is one web-safe file now that matches the IO exception types
  by name (`SocketException`, `HandshakeException`); on web those two rules
  never match, `TimeoutException` is typed. `metadata` for a `SocketException`
  is `{'error': '<message>'}` instead of the old `address`/`port` (the typed
  fields are unavailable without `dart:io`).
