## 2. Round 2 fixes (QA F1–F3)

### 2a. F1 — `RovingRow` size + hover/focus paint (fixed in the owning primitive)

- `primitives/roving_row.dart` (new, 259 lines; split out of `menu_rows.dart` when the fix pushed that
  file past 400; `menu_rows.dart` re-exports it, so `menu.dart`'s export chain is unchanged):
  - the row's `minHeight` is now a border-box total: the inner minimum reserves
    `padding.vertical` (like `button.dart`), so the default `px-2 py-1.5 text-sm` row measures **32**,
    not 44. A caller padding beyond the minimum grows the row (context_menu test: v8 → 36);
  - the row paints hover/focus/pressed states: `highlightFill`/`highlightForeground` resolve through the
    `Clickable` state set (defaults `accent`/`accentForeground`), and the label/icon colours resolve per
    state through the same `WidgetStateProperty`. Disabled rows keep the rest colours and dim at 0.5.
- `components/menu/menu.dart`: `_plainRow` passes the theme's rest and hovered row values
  (`MenuTheme.background`/`foreground` resolved for `{}` and `{hovered}`), so a `MenuTheme` override still
  controls both.
- `menu_test.dart` updated (authorised): the two expectations that encoded the old layout —
  “a row is at least 32 high” now asserts the `RovingRow` measures exactly 32 (the old inner
  `ConstrainedBox` was 32 *plus* 12 padding), and “hovering a sibling closes the open submenu” now hovers
  the row's right side because the 192-wide submenu inverts over the left half of the stretched test row
  once rows are 32 high (the old 44-high layout kept the pointer below the submenu). The weak
  “a hovered row paints the accent fill” assertion is now real: it reads the row's `AnimatedContainer`
  decoration and expects the `accent` token.
- B20 workarounds removed: menubar/context_menu/dropdown_menu/spell toolbar no longer inject a
  horizontal-only `MenuTheme`; select rows resolve `SelectTheme.itemPadding` directly through `SelectRow`.
- Primitive split: `primitives/menu_rows.dart` 427 → 181 (surface, `showMenuPopover`, static rows,
  `columnMenuBuilder`), `primitives/roving_row.dart` 259 (row + arrow-bubble intents). Both ≤400.

### 2b. F2 — select capabilities restored

- `select.dart` (398): `canUnselect` (clicking the selected item clears it when true), `autoClose`
  (default true; false keeps the popup open), `popupConstraints` + `SelectTheme.constraints`
  (default band 192-320 wide / 240 high, always trigger-wide through `anchorFixedSize`), and the
  selection hooks `valueSelectionHandler`/`valueSelectionPredicate` (defaults
  `singleSelectionHandler`/`singleSelectionPredicate`). Controlled display now reads `widget.value`;
  the popup's live `_value` notifier syncs from `didUpdateWidget` on the next frame (syncing during build
  marked the popup rows dirty mid-build).
- `primitives/select_popup.dart` (new, 213, layer-clean): `SelectData`, the single-selection helpers,
  `SelectRow` (on the shared `RovingRow`), and `SelectPopupBody` (search controller, query/`FutureOr` row
  resolution, empty/loading states, constraints). The `select` component injects the `MenuPopup` surface
  and the `input` search field, so the primitive imports no component.
- `components/multi_select/` (new component, `multi_select.dart` 233): `MultiSelect<T>` wraps
  `Select<Iterable<T>>` with `multiSelectHandler`/`multiSelectPredicate`, `canUnselect: true`,
  `autoClose: false`, chips in the trigger (`MultiSelectChip`, chip component) and checkbox rows
  (`MultiSelectItem` on the menu component's `MenuCheckboxItem`). Why a sibling component: the rows need
  `menu`/`chip` (layer 3), which a primitive must not import, and the two-file `select` budget cannot hold
  the family — the plan gives different behaviour its own small component (toggle vs button, dropdown vs
  menubar). `meta.json` declares `components: [chip, menu, select]`.
- Tests: select +6 (canUnselect true/false, autoClose false, widget/theme constraints, custom hooks) and a
  new `multi_select_test.dart` (9): chips, toggle-keeps-open, row remove, chip remove, autoClose true,
  canUnselect false, keyboard toggle, 36/32 sizes, `SelectTheme.itemPadding` pass-through.

### 2c. F3 — spell-check no-suggestions row

- `primitives/localizations/localizations_overlay.dart`: new `spellCheckNoSuggestions => 'No suggestions'`
  (English fallback; Flutter's material/cupertino ARBs have no equivalent, so no translations copied).
- `buildButtonItems` returns one disabled placeholder item (`onPressed: null`) for a misspelled span with
  no suggestions; the toolbar labels a null-label item with the localized string and keeps it dimmed at
  0.5. Test added (localized label + disabled + inert).
