## Bugs found and fixed this session (all with regression tests)
1. `TabPane._move` off-by-one for left-to-right drags: pre-removal target
   inserted one slot too far (`from < target` needs `-1`). Fixed + drag
   test asserts `[b,a,c]` for A→C-left.
2. `TabPaneItemBuilder` returned `TabItem`: the drag ghost builds outside
   the container `Data` scope → `No Data<TabContainerData> found` crash on
   every drag. Typedef now returns `Widget`; README documents why.
3. `TabContainer` keyed wrappers `ValueKey(child)`: new widget instances
   every build remounted all tabs on each `setState`, killing active drag
   sessions (teardown `Data.maybeFind` crash). Keys removed; drag works.
4. `PinnedSheet.animateToStage` orphaned futures: a newer call disposes the
   controller mid-flight → unhandled async error. `TickerCanceled` guard;
   rapid open/close test.
5. `PinnedSheet` settle needed a post-frame and settled permanently closed
   if the first build was unbounded. Settles during the first bounded build
   instead (zero-extent test).
6. `_ClockField` wiped in-progress typing whenever a controlled parent
   echoed an intermediate null. Now `TextField`-like: live texts owned
   locally, `[value]` re-read only when it changes between builds (external
   set/clear still applies). Typing tests use echoing harnesses.
7. `primitives/object_segments.dart` (previous session) did not compile
   (private-named ctor, wrong `../formatted_input` import, duplicated docs)
   and could never work as drawn: a primitive importing the
   `formatted_input` *component* is a `layer-direction` error. Rewrote it as
   genuinely component-free machinery (rungs, shape builders, pure
   parse/format); rendering stays in the component.
