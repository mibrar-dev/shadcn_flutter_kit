## swiper

Swipe-to-open wrapper: dragging the child towards the panel edge reveals a
`drawer` (`SwiperVariant.drawer`) or a `sheet` (`SwiperVariant.sheet`) overlay
through the accepted `drawer` component.

### old → new mapping

| Old | New / fate |
|---|---|
| `swiper.dart` barrel | `swiper.dart` (real file, re-exports `OverlayPosition`) |
| `_impl/core/swiper_widget.dart` (`Swiper` + `SwiperHandler` field) | `swiper.dart`: `Swiper` |
| `_impl/state/_swiper_state.dart` (`_onDrag*`, open/reverse) | `swiper.dart`: `_SwiperState` threshold gesture |
| `_impl/utils/swiper_handler.dart` + `drawer_swiper_handler.dart` + `sheet_swiper_handler.dart` | `SwiperVariant` enum + one exhaustive `switch` in `_open` |
| `_impl/themes/base/swiper_theme.dart` (`SwiperTheme`) | `swiper_style.dart`: `SwiperTheme` (Mergeable) |
| `_impl/themes/config/swiper_theme_defaults.dart` | `swiperDefaults(variant)` |
| `_impl/themes/config/swiper_theme_{config,tokens,schema}.dart` + `theme.schema.json` | deleted (no runtime readers) |
| `_impl/themes/config/swiper_theme_schema.dart` (generated) | `meta.json` `theme` section |
| `preview.dart` (Material `Scaffold`) | `preview.dart` widgets-only |

### bugs fixed (not ported)

1. `SwiperHandler.drawer` forced `expands: true`, so a side drawer covered the
   whole screen. The new drawer variant uses `expands: false` and keeps the
   panel's `maxSize` width (regression test: panel width 320, not 800).
2. `_onDrag` used `details.primaryDelta!` (null-assert); now `?? 0`.
3. `_onDragEnd` / `_onDragCancel` called `controller.reverse().then((_) =>
   overlay.remove())` with no mounted guard; the new code opens on release and
   clears `_active` under a `mounted` check.
4. Theme resolution `widget.theme ?? ComponentTheme.maybeOf` skipped the app leg
   and per-field merge; now `resolveComponentStyle` (4 legs).
5. `SwiperThemeDefaults` / `SwiperThemeTokens` / `SwiperThemeConfig` /
   `SwiperThemeSchema` (4 generated files, ~420 LOC) had no runtime readers; the
   one useful value (`behavior: translucent`) now lives in `swiperDefaults`.

### deviations

- The old drag scrubbed the overlay's `AnimationController`; the new drawer API
  returns a `DrawerOverlayCompleter` without a controller, so the swipe is a
  threshold gesture: it opens on release when the drag crosses
  `SwiperTheme.threshold` (default 0.25 of the axis) or flicks past
  `kSwiperOpenVelocity` (300 px/s). Dismissal stays with the panel's own drag,
  the barrier and Escape.
- Dropped (backdrop/glass and panel chrome belong to `DrawerTheme`):
  `SwiperHandler`, `backdropBuilder`, `transformBackdrop`, `surfaceOpacity`,
  `surfaceBlur`, `barrierColor`, `dragHandleSize`.
- `position` stays required; `enabled` and `behavior` (theme) are kept.
- No keyboard/controller trigger (the old component had none either); the
  README asks for a non-swipe trigger for a11y.

## stage_container

Responsive helper that snaps content to breakpoint widths and centres it with
density-aware padding.

### old → new mapping

| Old | New / fate |
|---|---|
| `stage_container.dart` (`StageBreakpoint` + factories + `StageContainer`) | `stage_container_style.dart` (`StageBreakpoint` sealed) + `stage_container.dart` (`StageContainer`) |
| `_impl/core/stage_container_2.dart` (`StageContainer`) | `stage_container.dart` |
| `_impl/core/staged_breakpoint.dart` (`StagedBreakpoint`) | `stage_container_style.dart` |
| `ConstantBreakpoint` | `stage_container_style.dart` |
| `_impl/themes/base/stage_container_theme.dart` (`StageContainerTheme`) | `stage_container_style.dart` |
| `_impl/themes/config/stage_container_theme_defaults.dart` | `stageContainerDefaults` |
| `_impl/themes/config/stage_container_theme_{config,tokens,schema}.dart` + `theme.schema.json` | deleted (no runtime readers) |
| `preview.dart` (Material `Scaffold`) | `preview.dart` widgets-only |

### bugs fixed (not ported)

1. `StageContainerThemeDefaults` hard-coded `EdgeInsets.symmetric(horizontal:
   72)` while the widget computed `density.baseContainerPadding * 4.5`. The new
   default is the density-aware `EdgeInsetsDensity.symmetric(horizontal: 4.5)`,
   so it follows the preset (test: reduced density → 54, not 72).
2. An unbounded width (e.g. inside a horizontal scroll view) produced
   `(size - maxSize) / 2 = infinity` insets and a layout error; guarded with
   `size.isFinite` and falls back to the base padding.
3. Theme resolution used `compTheme?.breakpoint ?? this.breakpoint` +
   `styleValue` (widget > tree > default), with no app leg and no per-field
   merge; now `resolveComponentStyle` (4 legs, receiver-wins).
4. `StagedBreakpoint` asserted `breakpoints.length > 1`, which made
   `const StagedBreakpoint([...])` impossible (constant evaluation of `.length`
   fails) and rejected a single-value strategy; the assert is removed and the
   doc states `breakpoints` must be non-empty.
5. `ConstantBreakpoint` had no guard for `step <= 0` (division by zero); added
   `assert(step > 0)`.
6. The old widget shadowed the ambient theme with a local named `theme`; the new
   build names it `ambient`.
7. `StageContainerTheme.copyWith` dropped the `ComponentThemeData`
   density/spacing/shadow slots; the new one keeps them.

### deviations

- `StageBreakpoint` is a `sealed` class; the `StageBreakpoint.constant` /
  `.staged` factories are dropped (use `ConstantBreakpoint` / `StagedBreakpoint`).
- The widget's `padding` accepts `EdgeInsetsGeometry?` (superset of the old
  `EdgeInsets?`); the `builder` callback still receives a resolved `EdgeInsets`.
- Added the `StageContainerBuilder` typedef.
- `ignoreGlobalScaling` / `ignoreGlobalRadius` (tokens-only knobs with zero
  readers) are dropped.

## Round 2 (QA F1) — interactive scrub + SwiperController

QA accepted the batch and returned one regression (F1): the opening panel must
follow the finger (scrub) and settle on release by position + fling velocity,
and a programmatic `SwiperController` is wanted.

### Root cause: a pushed route cannot follow a gesture

The round-1 swiper opened only on release because the new `drawer` uses a
`Navigator` route, and `Navigator` cancels every active pointer when the route
history changes (`navigator.dart` `_cancelActivePointers`, called at the end of
the history flush). A `GestureDetector`/`Listener` therefore stops receiving
`onUpdate`/`onPointerMove` the moment a route is pushed mid-drag (verified with
a minimal reproduction: `start`, then `end`, no `update`). Driving a pushed
route's `AnimationController` from an in-flight gesture is therefore impossible
without changing the drawer back to a non-`Navigator` overlay layer.

### Chosen design: in-tree panel

`swiper` now paints the panel **in-tree** with the same chrome as the route
shell, so the drag can scrub it:

- New primitive `primitives/drawer_route/drawer_panel_surface.dart` —
  `DrawerPanelSurface` (fill, inner-edge border, outer radius, shadow, drag
  handle) reads a `DrawerRouteTheme`; the route shell now uses it too, so a
  swiped panel and an `openDrawer` panel look identical and share
  `DrawerTheme`.
- `swiper.dart` drives a local `AnimationController` (0..1) from a `Listener`
  (raw pointers, no arena), normalised by the **panel** extent so the panel
  follows the finger 1:1. On release it settles open when the progress passed
  `SwiperTheme.threshold` (default 0.5) or the release velocity passed
  `kSwiperOpenVelocity` (300 px/s); otherwise it settles closed.
- `SwiperController` (`open`/`close`/`isOpen`/`progress`) added; the barrier
  tap and Escape dismiss; `MediaQuery.disableAnimations` makes the settle
  instant.
- Kept modal-ish behaviour in-tree (barrier blocks the child, `FocusScope`
  traps focus while open). Not a route, so `Navigator.pop` / route-level focus
  restoration do not apply (documented in the README).

### `drawer` / `drawer_route` edits (allowed by the brief)

Kept (genuine fixes, existing drawer tests green):

- `drawer_panel.dart` split: the route in `drawer_panel.dart`, the shell in
  `drawer_shell.dart`, the chrome in `drawer_panel_surface.dart` (each ≤ 223
  lines). Required to fit the slide fix under the 400-line limit.
- **Slide-by-panel-extent fix**: the shell now translates the panel by its own
  extent, not the full route. The old `SlideTransition` on the page slid the
  panel by the screen width, so a side drawer only appeared in the last ~40% of
  the animation.
- The barrier is an `AnimatedModalBarrier` that fades with the route, so a
  light/dark switch and any scrub stay live.
- `openDrawerOverlay` / `openSheetOverlay` gained `autoOpen` (default true) and
  `DrawerOverlayCompleter` exposes `controller` and `panelExtent`; the route
  holds at the closed position when `autoOpen: false`. These are the machinery
  the QA asked to expose; the swiper cannot use them for the reason above, so
  they remain available for a future non-`Navigator` overlay path.
