## alert

Mapping: `components/layout/alert/**` → `components/alert/` (4 Dart files).
Old 489 → 489 LOC; the doc-comment soup and 4 theme-config files became one
`AlertStyle`/`AlertTheme` pair.

Bugs fixed:

1. Two `package:flutter/material.dart` imports (banned) — removed.
2. Old destructive styling wrapped the whole banner in
   `DefaultTextStyle.merge`/`IconTheme.merge` from outside the layout, so a
   caller's ambient text style could leak between title and content. Slot
   styles are now set on the title/content/leading widgets themselves
   (regression test).
3. The old `AlertTheme` had no destructive fields, so `Alert.destructive`
   ignored every theme override; both variants are rows now.
4. `Alert.destructive(...)` → `Alert(variant: AlertVariant.destructive)`; the
   shadcn `default` row is `AlertVariant.base` (`default` is a Dart reserved
   word — documented in the README).

Deviations: the old `OutlinedContainer` surface became the alert's own
`DecoratedBox` (one fewer component dep); `basic` primitive swapped for
`primitives/basic_layout.dart`.

## color_field

The old directory was painter-only (`ColorFieldAxis` + `paintHSVColorField` +
`paintHSLColorField`); P4-B04 moved the engine to
`primitives/color_field_paint.dart` as the single owner. This component
consumes and re-exports it and adds the missing surface widget:

- `ColorField` (hsv/hsl mode, per-channel axes, alpha axis, checkerboard,
  themed ring) with `ColorFieldTheme`/`colorFieldDefaults`.
- Re-exports `ColorFieldAxis`, `paintHSVColorField`, `paintHSLColorField`
  (the old component's public API stays reachable from the component import).

Bugs fixed / not ported: the engine is not forked (single owner); the painter
compares colour, mode and every axis in `shouldRepaint` (the old preview
painter missed colour edits — regression test); the old meta declared `alpha`
and `theme` deps the code never used — `alpha` now backs the checkerboard and
the theme is real.

Deviation: the old component had **no widget**; `ColorField` is new public API
(source: the "tiny color well" note in the batch data). Open question below.

## eye_dropper

Mapping: `components/overlay/eye_dropper/**` (11 files) → `eye_dropper.dart` +
style/theme/preview; capture, sampling and the preview painter moved to
`primitives/screen_capture.dart`.

Bugs fixed, all regression-tested:

1. Picked-colour index was unclamped `floor()` math → hovering the last pixel
   row/column (or one pixel past the boundary) threw a `RangeError`.
2. `previewScale == 0` divided the sample size by zero; the grid is now
   clamped and capped at 512×512 so no degenerate zoom allocates unboundedly.
3. `_ColorPreviewPainter.shouldRepaint` ignored `backgroundColor` (fixed in
   `PixelGridPainter`).
4. A picking session could never be cancelled; Escape now completes it with
   null (and `dispose` completes it with null instead of leaking the
   completer).
5. A touch tap without a prior hover never completed the session (the old
   `onTapDown` was installed only when a preview already existed).
6. A failed capture used to open a session that could never complete; it now
   returns null without a session.
7. Two Material imports and the custom `_ScreenshotImage` `ImageProvider` are
   gone (the capture keeps the decoded `ui.Image` and renders `RawImage`).

Deviations: `EyeDropperResult` → `ScreenSample` (primitive-owned, re-exported);
`Data`/`ForwardableData` come from foundation; session cancellation is a
behavior add.

## app

Mapping: `components/layout/app/**` (4 files) → `app.dart` + preview. No theme
file: the app installs `ShadcnThemeData`/`ShadcnTheme`/`ComponentThemes` and
does not duplicate them.

Round 2 (F1, locale bug): the old default resolved an `en_US` device to
`zh_Hant` because `supportedLocales` had no `en` and started with the Hant
entry. Fixed in `primitives/localizations/`:

- `supportedLocales` now starts with `Locale('en')` (the base English table is
  a real fallback entry; the old 39-locale count assertion is 40).
- `ShadcnLocalizations.resolveLocale(locale, supported)` matches by **language
  code first**, then refines by script/country: `en_US`/`en_GB` → `en`,
  `de_AT` → `de`, `zh_TW`/`zh_HK`/`zh_MO`/`zh_Hant*` → `zh_Hant`, `zh_CN`/
  `zh_SG` → `zh`, unknown (`sw`) → `en`.
- `ShadcnApp` installs it as the default `localeResolutionCallback` (a
  user-supplied callback still wins), so an `en_US` device resolves to `en`
  and no "not supported by all of its localization delegates" warning is
  emitted (regression-tested via `localesTestValue`).

Bugs fixed:

1. `ThemeMode.system` never resolved the dark theme: the old `_resolveTheme`
   ran above `WidgetsApp`'s MediaQuery (`MediaQuery.maybeOf` was always null).
   The theme now resolves inside the app builder (regression test with
   `platformBrightnessTestValue`).
2. The old app wrapped a manual `Localizations` (with a private locale
   resolver that disagreed with the framework's) around `WidgetsApp`'s own;
   only the framework resolver is used now.
3. Two Material imports, the `Material` transparency fallback and
   `registerComponentThemeGlobalConfigs()` (global mutable registry) are gone.
4. Found while testing: the delegate dedup filter was a lazy `where` over a
   `Set`, so a second iteration of the same list yielded an empty iterable and
   the app's delegates vanished on rebuild; it is materialised now.

Deviations: `ShadcnApp.router` and the router parameters are dropped (clean
break); `theme`/`darkTheme` are `ShadcnThemeData`; `scaling` is
`AdaptiveScaling` applied to the new theme data. The app uses
`flutter_localizations`' `GlobalWidgetsLocalizations.delegate` only (for RTL
text direction); no Material/Cupertino library is imported.

## window

Mapping: `components/layout/window/**` (17 files) → component
`window.dart`/`window_style.dart`/`window_theme.dart`/`preview.dart` plus the
two window primitives. Old 3357 → 1442 total (below the 2.5× ratio, above the
1350 target).

Bugs fixed (tested):

1. Two Material imports + `Icons` (banned) — Lucide icon set now.
2. The old code updated `maximized` through two different paths and its
   `WindowState.copyWith` could not update `maximized` at all (only a separate
   `withMaximized`); one `_set` path owns every transition now.
3. `WindowActions` dereferenced a nullable handle without the null checks its
   own `onPressed` skipped, so a detached action threw; actions render
   disabled instead (regression test).
4. Closing during the exit animation could skip the remove callback and leave
   a ghost entry in the navigator; removal is driven by the animation end and
   is idempotent (regression test).
5. The first navigator layout handed windows a `Size.zero` viewport, so a
   maximized window flashed at 0×0.

Deviations (API):

- `Window` is now one widget (old `Window` data object + `WindowWidget`
  renderer merged) and **requires** a `WindowController`; the uncontrolled
  constructor's initial-state fields became controller arguments.
- `Window.closed`/`Window.handle` accessors and the `WindowNavigatorHandle`
  mixin are gone; the navigator state implements the new public
  `WindowManager` interface (reachable through `WindowViewport.manager`).
- The top snap bar is **restored (round 2, F2)**: `primitives/window_snap.dart`
  owns `WindowSnapBar` + `windowSnapPresets` (halves, 70/30, thirds, 2-3-2,
  quarters) and the maximize strip; `showTopSnapBar` is back on
  `WindowNavigator`/`WindowHost`. The bar slides in while dragging near the
  top edge, previews the hovered preset through the existing overlay, and
  applies it on release (tested with a real mouse drag).
- `group` is not used: the host and the resize handles use framework
  `Stack`/`Positioned` (the batch's `group` hint is unused).
- `WindowActions` lives in `primitives/window_host.dart` (the component file
  was otherwise over the 400-line limit) and is re-exported by the component.

## wrapper — deleted

Audited per P4-Q4: `Wrapper` is a 97-line helper that conditionally wraps a
child in a builder + `KeyedSubtree`, with no theme, tokens, visuals or state of
its own, and **zero Dart consumers** in `lib/`, `test/` or `docs/` (only its
own preview and the old manifests reference it). Verdict: helper-only →
deleted, no shim. Matches the `debug` deletion precedent (P4-B06).

## Open questions

1. **New primitives not in batch data**: `screen_capture`, `window_host`,
   `window_manager`, `window_snap` (round 2). They were required to respect
   the 400-line file budget (window.dart was 936 lines inline; eye_dropper
   605). Each is generic machinery, but only `window_*` is used by one
   component and `screen_capture` by one component today. Ratify the
   placement or ask for a different split.
2. **color_field widget API**: the old component was painter-only; the new
   `ColorField` widget is the first real surface for the engine. Confirm the
   API (mode + axes) before B24/B25 build on it.
3. **window API break**: controller-required `Window`, `WindowHandle` reduced
   to the members the chrome uses (`focused`/`enablingSnapping` setters
   dropped), `WindowViewport.closed` dropped. Confirm the clean break is
   acceptable for card_image-style users (none found in-tree).
4. **flutter_localizations in `app`**: only `GlobalWidgetsLocalizations` is
   used (no Material import). Confirm this stays within the widgets-only rule
   for the app shell.
5. **`localizations.dart` file length**: the file is 557 lines in round 2 —
   another agent is adding keys and F1 added the `en` entry plus
   `resolveLocale`. The mechanical split already scheduled after the parallel
   batches should take it below 400.
6. **F1 API**: `ShadcnLocalizations.resolveLocale(locale, supported)` is new
   public API on the primitive; `ShadcnApp` uses it as the default
   `localeResolutionCallback`. Ratify the name/signature (a user callback
   still overrides it).
