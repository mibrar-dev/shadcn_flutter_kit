## color_picker

Old `components/form/color_picker/**` (3,472 Dart LOC incl. preview, 20 Dart
files + 4 theme-config files) → `components/color_picker/`:

| Old | New / fate |
|---|---|
| `color_picker.dart` (entry + parts), `_impl/state/_color_picker_state.dart` | `color_picker.dart`: `ColorPicker` + state + pad/bars |
| `_impl/core/color_controls.dart`, `_color_value_input.dart` + its state | `ColorPickerControls` (main) + `colorPickerFields()`/`_ColorChannelField` (style) |
| `_impl/core/color_picker_mode.dart` | `ColorPickerMode` in `color_picker_style.dart` (owned here, re-exported) |
| `_impl/core/hsl_/hsv_color_slider{,_painter,_type}.dart` (6 files, ~1.5k) | **not ported**: the accepted `hsl`/`hsv` components own the sliders, painters and `HSL/HSVColorSliderType`; nothing re-declared |
| `_impl/themes/base/color_picker_theme.dart` + 4 config files | `ColorPickerTheme` + `colorPickerDefaults` (style); config scaffolding deleted |
| `preview.dart` (Material) | widgets-only `preview.dart` |
| `meta.json`/`theme.schema.json` | single `meta.json` (`deps` exact) |

Bugs fixed, regression-tested:

1. The pad switched on `widget.initialMode`, so changing the mode dropdown
   never swapped the HSL/HSV pad — it follows `_mode` now.
2. The history button rendered unconditionally and `ColorHistoryStorage.of`
   threw without a `RecentColorsScope` when pressed — history UI renders only
   when a storage is in scope; the picker works without one.
3. Horizontal layouts ignored `initialShowHistory` (`_showHistory` was only
   read on the vertical path) — both orientations honour it.
4. The HEX field accepted exactly six digits and reset the alpha channel —
   `ColorDerivative.fromHex` handles 3/6/8 digits and the current alpha is
   kept.
5. Alpha fields were 0–100 in HSL/HSV but 0–255 in RGB/HEX — one 0–100 scale
   everywhere.

Deviations:

- `ColorPickerControls` (public, main) replaces the old public
  `ColorControls`; `colorPickerFields()` (public, style) and
  `_ColorChannelField` (private, style) replace `_ColorValueInput`. The flat
  folder has one widget file; the split mirrors `StepperIndicator`/`TreeRow`
  (widget helpers in the style file).
- The old per-widget `orientation`/`spacing`/`controlSpacing`/`sliderSize`
  arguments are gone (clean break); the same fields live in
  `ColorPickerTheme` and resolve through all four legs.
- `alpha` is not imported (the hsl/hsv sliders own the checkerboard) and
  `color_math`/`form_core` are not imported directly (`ColorDerivative` owns
  hex parsing; the picker has no form value of its own).
- The hue bar stays HSV in every mode (old behaviour); only the pad switches
  HSL/HSV.

## phone_input

Old `components/form/phone_input/**` (1,139 Dart LOC, 14 files incl. four
theme-config files + schema) → `components/phone_input/`:

| Old | New / fate |
|---|---|
| `phone_input.dart` + `_impl/state/_phone_input_state.dart` | `phone_input.dart`: `PhoneInput` + state + `PhoneNumberValidator` |
| `_impl/core/phone_number{,_valid}.dart` | value types from `primitives/phone_number.dart`; validator rewritten as `PhoneNumberValidator` on `form_core.Validator` |
| `_impl/utils/_always_prefixed_plus.dart` | deleted (the field holds the national number only) |
| `_impl/themes/base/phone_input_theme.dart` + 4 config files | `PhoneInputTheme` + `phoneInputDefaults` (style) |
| `phonecodes` `Country` + `country_flags` `CountryFlag` | `primitives/countries.dart` + `primitives/phone_number.dart` + the `country_flag` component |
| `preview.dart` (Material) | widgets-only `preview.dart` |

Bugs fixed, regression-tested:

1. `_updateCountry` did unclamped selection arithmetic (`offset -
   dialCode.length`) and could assert/corrupt the caret — the prefix rewrite
   is restored with clamped offsets (QA round 2, F2).
2. Switching between countries sharing a dial code reported the previous
   country (the controller was mutated before the country was stored).
3. The controller listener ran country detection and fired `onChanged` on
   selection-only changes — the listener compares text now.
4. The internally created controller was never disposed and
   `didUpdateWidget` leaked it on a controller swap — dispose + re-attach.
5. `searchPlaceholder` was dead API — wired to the select search field.
6. Country search was case-sensitive (the row was lowercased, the query was
   not) — case-insensitive now, matching name/ISO code/dial code.
7. `countries` did not constrain auto-detection — detection is gone and the
   list bounds the picker.
8. `onChanged` and the form value could disagree (one carried the detected
   country, the other the stored one) — one value feeds both.
9. Deprecated `filterPlusCode`/`filterZeroCode`/`filterCountryCode` no-ops and
   the forced `+` formatter (IME composing dropped, field could not be empty)
   are deleted.

Deviations:

- Typed-prefix detection is restored (QA round 2, F2; tie-break fixed in
  round 3): typing `+44…` selects the matching country — longest dial-code
  match, then the current selection, then the row marked
  `CountryInfo.primary` (`+1` → US, `+7` → RU, `+44` → GB, `+47` → NO,
  `+61` → AU, `+64` → NZ, `+262` → RE, `+358` → FI, `+590` → GP), otherwise
  the supplied list order. The field carries the optional prefix;
  `PhoneNumber.number` is the national number and `onChanged` reports null
  while it is empty.
- The number formatter keeps digits plus at most one leading `+` (no forced
  prefix); non-digits are still filtered.
- `countries` is a `List<CountryInfo>` (names live in the primitive table)
  instead of `List<Country>`; it bounds both the picker and detection.
- `PhoneNumberValid` → `PhoneNumberValidator` (clean name); no format/length
  rule is invented (the old validator had none).
- `country_flag` is imported although it is not in the batch
  `component_deps` — the orchestrator note sanctions flags via `country_flag`;
  the `form` component is not imported (the validator uses `form_core`).
- The selector and field render as two adjacent controls; the old joined
  corners are gone (`Select`/`Input` expose no corner surgery).

## filter_bar

Old `components/layout/filter_bar/**` (2,994 Dart LOC, 17 files: logic 599,
style 223, content 825, layout/theme/utils/preview) →
`components/filter_bar/` + `primitives/filter_core/`:

| Old | New / fate |
|---|---|
| `filter_bar_logic.dart` (599) | `primitives/filter_core/filter_state.dart`, `filter_matching.dart`, `filter_controller.dart`, `filter_group.dart` (engine + grouping) |
| `_impl/themes/base/filter_bar_theme.dart` (private resolved theme) + 4 config files | `primitives/filter_core/filter_theme.dart` (`FilterBarTheme` + `filterBarDefaults`), re-exported by the component |
| `_impl/styles/filter_bar_style.dart` (typedefs, custom filter, group, sheet scaffold) | `filter_bar_style.dart` (sheet chrome + public control sub-widgets); custom filters/grouping re-exported from `filter_core` |
| `_impl/core/filter_bar_content.dart` + `_impl/variants/filter_bar_layout.dart` + `filter_bar.dart` | `filter_bar.dart` (widget + state + inline/sheet content) |
| `_impl/state/filter_bar_controller.dart` + `_impl/state/filter_bar_state.dart` + `_impl/extensions/filter_state_extensions.dart` (export-only shims, 0 importers) | deleted |
| `_impl/utils/filter_bar_utils.dart` (`_Debouncer`) | inline `Timer` handling |
| `preview.dart` (685, 4 examples) | widgets-only `preview.dart` |

Bugs fixed, regression-tested:

1. A pending search-debounce timer could resurrect cleared text after
   "clear all" (and re-apply old keystrokes over external state) — the timer
   is cancelled before every emit.
2. The mobile sheet read its state once and went stale while open — it
   listens to a state mirror (`ValueListenableBuilder`).
3. `sheetBreakpoint` was compared against a staged breakpoint, so the
   documented default 720 behaved like 768 — the raw width is compared.
4. A half-null date range was dropped silently by `_toDateTimeRange` — it
   maps to a one-day span.
5. `controller` silently overrode `state`; supplying both is an assert now
   and both callbacks fire (no double rebuild).
6. The grouped sheet dropped ungrouped custom filters — grouping is restored
   with headers (`FilterGroup`), and every filter renders exactly once
   (grouped ids under their group, the rest in the trailing wrap).
7. The sheet trigger could be a dead button with nothing to show — it only
   renders when the sheet would have content.
8. `setMatcherIdOf` stored nothing for an unknown id but still returned a new
   state — it returns `this` unchanged (engine test).
9. `FilterState.hashCode` re-hashed custom filters on every call (sorting a
   fresh list) — the hash is computed once.
10. `FilterMatchers.greaterThan/lessThan` threw when the runtime types of the
    candidate and the selection differed (the `Comparable<Object>` guard is
    covariant) — a candidate of another type never matches (engine test).

Deviations:

- The value engine moved to a new primitive `primitives/filter_core/`
  (4 files, 736 LOC). The old tree exposed the same code as a second public
  entry (`filter_bar_logic.dart`, imported standalone by the docs); the flat
  component folder only has room for one widget file plus one style file, and
  the engine is pure data (no widgets/components). Not named in the batch
  data — ratify.
- `FilterBarTheme`/`filterBarDefaults` live in the primitive (the style file
  is at its 400-line budget); precedent: `HoverTheme`, `BasicTheme`,
  `FileUploadRowTheme` are primitive-owned component themes. Re-exported by
  `filter_bar_style.dart`, so the component import exposes them.
- Grouping is restored (QA round 2, F1): `FilterGroup(id, title, filterIds,
  itemBuilder)` and the grouped renderer (`FilterBarGroupedContent`) live in
  `primitives/filter_core/filter_group.dart`; `filter_bar_style.dart` and the
  component import re-export them. Headers render above their filters, and
  filters not covered by a group (plus `trailingFilters`) render after the
  blocks — the old grouped sheet dropped those ungrouped filters.
- Per-instance label parameters (`searchPlaceholder`, `searchLabel`,
  `sortLabel`, `dateRangeLabel`, `clearAllLabel`, `sheetTriggerLabel`,
  `sheetTitle`, `activeFilterCountLabel`) are gone: strings come from
  `primitives/localizations` (7 new keys, below).
- `FilterBarStyle` (layout metrics class) became `FilterBarTheme`; new public
  sub-widgets `FilterBarSearchField`, `FilterBarSortControl`,
  `FilterBarDateControl`, `FilterBarClearButton`, `FilterBarSheetTrigger`
  (composition units; `FilterBarSheetScaffold` was public in the old style
  file too). `FilterSheetItemBuilder` (a byte-identical duplicate of
  `FilterCustomFilterBuilder`) and `FilterField.label` (never rendered) are
  gone.
- `stage_container` is not needed: the staged-breakpoint helper caused bug 3,
  so the raw width compare replaced it. `checkbox`/`scaffold` were
  preview-only in the old meta; `form`/`calendar` are reached through
  `date_picker` (`DateRangePicker` + `PromptMode` from `form_core`), not
  imported directly.
- The date control is a `DateRangePicker` in popover mode (old: a custom
  `ObjectFormField` + `DatePickerDialog` with a separate clear button). QA
  round 2 (F3): it is wrapped in a 36px box so every control in the bar
  shares h-9 (the bare trigger measured 54).
- Test finding: the leading search icon with the default v8 padding made the
  field 40+ tall; the search field uses v5 vertical padding so it stays h-9
  (36), matching the sort/date controls.
