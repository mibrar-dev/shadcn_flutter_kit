## Public API

`ColorInput(value, onChanged, onChanging, showAlpha, initialMode,
enableEyeDropper, showHistory, mode, popoverAlignment, popoverAnchorAlignment,
popoverPadding, dialogTitle, enabled, theme)` — controlled only; participates
in forms as a `ColorDerivative` field (`FormValueSupplier`).

`ColorInputTheme` (fields: `mode`, `pickerMode`, `showAlpha`,
`enableEyeDropper`, `showHistory`, `popoverAlignment`,
`popoverAnchorAlignment`, `popoverPadding`, `gap`, `swatchSize`,
`swatchBorderRadius`, `swatchBorderColor`) + `colorInputDefaults` +
`colorInputThemeOverrides` (user-owned) + `colorInputTrigger(...)`.

Resolution: widget args > widget `theme` arg > nearest
`ComponentTheme<ColorInputTheme>` > app `ComponentThemes` > `colorInputDefaults`;
per-field merge, receiver wins. The widget args are folded into a widget-leg
`ColorInputTheme` and merged over `widget.theme`, so every leg is structural.

## Round 2 — F1 fixed at the root (`color_picker` controls reflow)

QA round 2 accepted the batch (deps, `colorInputTrigger` split, 8-digit alpha
rule, LOC) and asked for the root fix: the `color_picker` controls row was a
fixed ~464 px `Row` and overflowed narrow widths. Changes:

- `color_picker_style.dart`: field/mode/button widths are now constants, and
  `colorPickerControlsWidth({mode, showAlpha, leadingButtons, controlSpacing})`
  returns the row's one-line width (464 for RGB+alpha+2 buttons, 392 for RGB+2
  buttons, 344 for HEX+alpha+2 buttons — the hex and alpha fields differ in
  width). The width doubles as the picker's intrinsic/popover width, so the
  accepted popover look is unchanged.
- `color_picker.dart` `ColorPickerControls`: the row is now a `Wrap` inside a
  `SizedBox(width: colorPickerControlsWidth(...))`. One run at/above the
  one-line width; extra runs below it on narrower widths (280 px: buttons +
  mode select on the first run, fields flowing after). No `LayoutBuilder`:
  `ColorPicker`'s `IntrinsicWidth` queries its children, and a `LayoutBuilder`
  cannot answer intrinsic queries.
- `color_picker.dart` `ColorPicker`: the history grid is wrapped in a
  horizontal `SingleChildScrollView`, because the grid's fixed 10-column width
  (356 px) also overflowed at 280 px once opened.
- `color_input.dart`: the `FittedBox.scaleDown` workaround is removed; the
  dialog embeds the plain picker and relies on the reflow.
- Tests: `color_picker_test.dart` gains a `responsive controls` group
  (one-line width pinned to 464/392/344; single run at the one-line width and a
  wrap one pixel below it; 280/360/480 px have no overflow and every control is
  hittable with `hitTestWarningShouldBeFatal`); `color_input_test.dart`'s
  narrow dialog now runs on a 320×640 screen and asserts no overflow.
  `color_picker`'s README and `meta.json` document
  `colorPickerControlsWidth`.

## Old bugs fixed, regression-tested

Direct regression tests: 1, 5, 7 (and 6's dead-API removal is structural);
2–4 are fixed structurally — the throwing lookups and the leaked notifier no
longer exist, and the eye-dropper path cannot be exercised end-to-end in a
widget test (screen capture needs a live layer), so its pipette toggle is
tested instead.

1. **Committing threw without a `RecentColorsScope`.** The old state called
   `ColorHistoryStorage.find(context).addHistory(...)` (and `.of`) on every
   commit; without a scope that throws. History is now optional
   (`Data.maybeFind<ColorHistoryStorage>`), with a regression test that commits
   without a scope.
2. **The dialog eye-dropper path wrote through the same throwing lookup.**
   The old dialog action closed the prompt, sampled the screen, called
   `ColorHistoryStorage.of(context).addHistory(result)` (throws without a
   scope) and only then re-prompted. One `_pickScreenColor` path now closes the
   prompt, samples from the trigger's context, commits (history optional) and
   reopens; the picker's pipette uses it in both presentations.
3. **The embedded picker's eye dropper was disabled in dialog mode.** The old
   code passed `enableEyeDropper: promptMode == popover && enableEyeDropper` and
   re-implemented a footer action. The picker now owns its pipette in both
   modes (`onEyeDropperRequested` override).
4. **`_showHistoryNotifier` was never disposed.** The old state owned a
   `ValueNotifier<bool>` with no `dispose()`. The picker owns its history
   toggle now; the state owns only a `PopoverController` (disposed).
5. **The hex label reset alpha to opaque on parse.** The old picker's HEX field
   accepted exactly six digits and reset alpha; the trigger's new hex `Input`
   parses `#RGB`/`#RRGGBB`/`#AARRGGBB` and keeps the current alpha for 3/6
   digits (8 digits carry their own). Regression tests for both.
6. **Dead API removed:** `placeholder` could never render (`value` is required
   non-null) and `showLabel`/`orientation`/per-instance popover arguments were
   redundant with the trigger/theme redesign (see Deviations).
7. **Minimum touch target:** the old swatch was `minWidth/minHeight 28`; the
   well is 36×36 (shadcn h-9) and shares the row height with the hex field
   (tested with `tester.getSize`).

## Deviations (ratify)

1. **Trigger redesigned per the orchestrator note** — a 36 px colour well plus
   an editable hex `Input` (`input` is imported and declared in
   `deps.components`; the batch JSON's `component_deps` did not list it — the
   note supersedes). `showLabel` is gone: the trigger always shows both.
2. **`input` is used; `button`/`form` are not imported.** The old dependencies
   `button` (footer icon buttons) and `form`/`form_field` are replaced by the
   `form_core` object-field presentations (`ObjectFormPromptDialog`/
   `ObjectFormPromptPopup`) and the picker's own buttons; `form_core` is in the
   batch primitives list. The declared `deps` match the imports exactly.
3. **`colorInputTrigger(...)` is public** (style file) because the flat folder
   has one widget file and `ColorInput` (main file) composes it — the
   `colorPickerFields()`/`ColorPickerControls` precedent from `color_picker`.
   The private `_HexField` lives beside it for the same reason.
4. **`ColorPickerControls`/`colorPickerFields()` are not called directly** —
   the whole accepted `ColorPicker` is embedded (it composes both). Nothing
   from `color_picker`, `color_field`, `hsl`/`hsv` or the primitives is
   re-declared.
5. **Prompt mode defaults to responsive**: popover at ≥768 px, dialog below
   (the old widget always defaulted to popover). `object_input` is the
   precedent; widget/theme legs override.
6. **Dialog commits on Save, popover commits live.** The old popover delayed
   its commit until close; live popover commits match `date_picker`'s popover
   ("reports without Save"). `onChanging` still fires during drags in both.
7. **Narrow-width fix lives in `color_picker`, not here (QA round 2, F1).**
   The controls row now reflows (see "Round 2" below); the dialog embeds the
   plain picker again and needs no scaling wrapper.
8. **`ColorInputController`/`ControlledColorInput` dropped** (clean break):
   controlled `value` + `onChanged`, disabled via null `onChanged` (or
   `enabled: false`), `Opacity(0.5)` per house rule. The disabled hex field
   also gets `Input`'s own disabled surface (transparent fill), which is the
   accepted `input` behaviour.
9. **Hex field alpha rule refined vs `color_picker`'s accepted rule**:
   `color_picker`'s HEX field always keeps the current alpha; the trigger's
   hex field keeps it for 3/6 digits but applies it for 8 digits (otherwise an
   8-digit paste could never set alpha in a field whose value is displayed as
   `#AARRGGBB`). Confirm or align with the picker.

## Tests

  `FocusOutline` ring; disabled = `Opacity(0.5)`, disabled `Clickable`/`Input`,
  no prompt.
- theme legs: `theme` argument (28) > scoped `ComponentTheme` (32) > app
  `ComponentThemes` (40) > defaults (36), plus per-field merge (scoped size +
  app gap) and `mode` via scoped/app legs.

no overflow (`tester.takeException() == null`) and every control (buttons,
