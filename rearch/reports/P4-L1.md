## 3. The split

`ShadcnLocalizations` is declared as
`class ShadcnLocalizations with ShadcnLocalizationsForm, ShadcnLocalizationsOverlay, ShadcnLocalizationsDateTime, ShadcnLocalizationsFiles, ShadcnLocalizationsMisc, ShadcnLocalizationsError`,
so every `ShadcnLocalizations.of(context).foo` call and every locale subclass
(`localizations_<code>.dart`, overriding getters with `@override`) compiles unchanged.

| file | lines | mixin | getters |
|---|---|---|---|
| `localizations.dart` | 195 | (base class) | statics, `of`, `delegate`, `localizationsDelegates`, `supportedLocales`, `resolveLocale`, `localeName`; exports the mixins + delegate |
| `localizations_form.dart` | 59 | `ShadcnLocalizationsForm` | `chipInputRemoveChip`, `form*` (14), `invalidValue`/`invalidEmail`/`invalidURL` |
| `localizations_overlay.dart` | 44 | `ShadcnLocalizationsOverlay` | `command*` (5), `dialogDismiss`, `menu*` (10) |
| `localizations_date_time.dart` | 189 | `ShadcnLocalizationsDateTime` | date/pickers/time/duration, `month*` (12), `abbreviated*` (19), `getMonth`/`getAbbreviatedMonth`/`getAbbreviatedWeekday` |

| `localizations_error.dart` | 130 | `ShadcnLocalizationsError` | the 35 new error getters (§4) |

Added on the class: `static const ShadcnLocalizations english` — the canonical English table (used by
`of()`'s fallback and as the default of the new error-file parameters).

### Deviations (flagged for QA)

1. **The class stays concrete, not `abstract`.** The brief's shorthand described
   `ShadcnLocalizations` as abstract, but direct `const ShadcnLocalizations(Locale('en'))`
   constructions exist in `test/registry_next/components/dialog_test.dart:212` and
   `chip_input_test.dart:328` — files outside this brief's outputs — and in
   `localizations.dart` (`of()`) and `localizations_delegate.dart` (`lookup` default).
   Making the class abstract would either break those call sites or require a public
   factory redirect plus renaming the generative constructor for all **40** locale
   subclasses (`super.locale` cannot forward to a factory). The binding constraints are
   "no public API change" and "every locale subclass keeps compiling unchanged", so the
   class remains directly constructible, with the mixins applied.
2. **Mixins are unconstrained** (`mixin X { … }`, no `on ShadcnLocalizations`). Dart 3.13
   rejects a mixin constrained to the class that applies it (`recursive_interface_inheritance`;
   probe in §8). The mixins only reference their own members, so the missing constraint was
   not needed.
3. One mixin beyond the brief's "e.g." list: `localizations_error.dart`. Putting the error
   domain into `localizations_misc.dart` would have mixed two unrelated domains.
4. Dropped the unused `import 'package:flutter/foundation.dart' show SynchronousFuture;`
   from `localizations.dart` (the delegate file keeps its own).

## 4. Error strings moved

35 new getters in `ShadcnLocalizationsError` (English defaults, grouped as actions, HTTP
statuses, auth/validation/platform and network):

`errorSomethingWentWrong`, `errorUnexpectedMessage`, `errorActionRetry`, `errorActionReport`,
`errorActionBack`, `errorActionLogin`, `errorActionSettings`, `errorActionContactSupport`,
`errorBadRequest`, `errorBadRequestMessage`, `errorUnauthorized`, `errorLoginRequiredMessage`,
`errorAccessDenied`, `errorAccessDeniedMessage`, `errorNotFound`, `errorNotFoundMessage`,
`errorConflict`, `errorConflictMessage`, `errorInvalidData`, `errorInvalidDataMessage`,
`errorTooManyRequests`, `errorTooManyRequestsMessage`, `errorServerError`, `errorServerErrorMessage`,
`errorRequestTimedOut`, `errorRequestTimedOutMessage`, `errorAuthenticationRequired`,
`errorInvalidInput`, `errorReviewFieldsMessage`, `errorPlatformError`, `errorDeviceErrorMessage`,
`errorConnectionFailed`, `errorConnectionFailedMessage`, `errorSecureConnectionFailed`,
`errorSecureConnectionMessage`.

**No translation was invented or copied.** Verified against Flutter's
`flutter_localizations/lib/src/l10n/material_en.arb` and `cupertino_en.arb`: none of the strings
above exists there, so the getters stay English fallbacks (documented as such in the mixin).
The dismiss label (`'Dismiss'`, used by `showErrorDialog` and `ErrorAction.dismiss`) **reuses the
existing `dialogDismiss`** getter — Flutter's `modalBarrierDismissLabel`, already translated in all
40 shipped tables — instead of duplicating the string as a new English-only getter.

Call sites changed (all additive parameters, source-compatible):

- `ErrorAction.retry/report/back/login/settings/contactSupport/dismiss` now take
  `{ShadcnLocalizations strings = ShadcnLocalizations.english}` and read the labels from it.
- `apiRules`, `authRules`, `validationRules`, `platformRules`, `networkRules` take the same optional
  named `strings`; `_titleForStatus`/`_messageForStatus` became table-driven.
- `guard`/`guardSync` take `strings` for the unmapped-error fallback;
  `fallbackRule(error, [stackTrace, strings])` gained a third optional positional parameter and is
  still assignable to the `ErrorMapper` fallback tear-off (`fallback: fallbackRule` compiles; the
  existing error tests pass unchanged).
- `showErrorDialog`'s fallback button now reads
  `ShadcnLocalizations.of(context).dialogDismiss`.
- `components/error_system/meta.json`: `deps.primitives` is now
  `["error_handling", "localizations"]`, with a `notes` entry describing the l10n pass.

Deliberately **not** moved (not user-facing, or demo data): `AppError`/exception `toString()`s,
`debugPrint` output, `ErrorScope` channel keys (`app.sessionExpired`, …), `ArgumentError`/`assert`
developer messages, `technicalDetails`, and `preview.dart` / `README.md` sample text.

## 8. Notes

- Mixin-constraint probe (why no `on ShadcnLocalizations`): a scratch file with
  `mixin M on A {}` + `class A with M {}` fails Dart 3.13 with
  `error - recursive_interface_inheritance`. The probe lived in the session temp directory, not in
  the repo.
- `ShadcnLocalizations.english` is a new additive static const, documented on the class.
- The locale tables receive the new getters through inheritance; any future translation can be
  added by overriding them in `localizations_<code>.dart` (the fallback is explicit, not invented).
- Unresolved by design: `guard`/rules are context-less, so an app that wants localized errors passes
  `ShadcnLocalizations.of(context)` into them (the parameters exist for exactly that); `of()`'s
  fallback covers every current default call path.
