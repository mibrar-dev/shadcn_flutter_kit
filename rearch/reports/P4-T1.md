## Analyzer 14.5.0 API changes and fixes (all verified against installed source, none guessed)
Fields now live on a `FormalParameter` base / fragment nodes:
- `ClassDeclaration.name`/`.members` → `namePart.typeName.lexeme` / `body.members`.
- `EnumDeclaration.name`/`.constants`/`.members` → `namePart.typeName.lexeme` / `body.constants` / `body.members`.
- `MixinDeclaration`, `ExtensionDeclaration` keep `.name`; members move to `body.members`.
- `ExtensionTypeDeclaration.name` → `namePart.typeName.lexeme`; no longer `@experimental`, so
  the `_isExtensionType` helpers + `// ignore: experimental_member_use` were removed; the
  `NamedCompilationUnitMember` type was deleted → check `member is ExtensionTypeDeclaration`.
- `SimpleFormalParameter`/`DefaultFormalParameter`/`FunctionTypedFormalParameter` removed.
  `FormalParameter` base now exposes `.name`/`.type`/`.isRequired*`/`.defaultClause`;
  function-typed params expose `.functionTypedSuffix.{formalParameters,question}`.
- `MethodDeclaration.isAbstract` is now `@deprecated` → replaced with `body is EmptyFunctionBody`
  (byte-identical to 6.4.1 semantics, so the manifest's `abstract` flags don't drift).
- `@ToBeDeprecated` (e.g. `FormalParameterList.parameters`, `FormalParameterDefaultClause.value`)
  is a benign marker that emits no diagnostic — safe to keep.
- `parseString` keeps `content/path/featureSet/throwIfDiagnostics`; default `featureSet` is
  `FeatureSet.latestLanguageVersion()`, so null-aware elements parse.
