# P4-T2 — registry files pass a fresh app's default lints

Status: **done** — the nested `analysis_options.yaml` shim is gone and a real `flutter create`
app installs the registry and analyzes clean on its own stock `package:flutter_lints/flutter.yaml`.

## What was wrong

The CLI wrote `<installRoot>/analysis_options.yaml` (an analyzer-options file with **no
`include:`**) into the install root. That file replaced the app's lint set for every vendored
file, so **all** lints were off under `lib/ui/shadcn/**` — not just the six error codes it listed.
The registry had never actually been linted under a stock app's rules.

Measured before the fix: with `analysis_options.yaml` reduced to `include:
package:flutter_lints/flutter.yaml`, `dart analyze lib/registry` reported **190 issues**
(130 `unused_import`, 30 `unnecessary_import`, 17 `sort_child_properties_last`,
8 `deprecated_member_use`, 2 `unnecessary_null_comparison`, 2 `unnecessary_const`,
1 `duplicate_import`).

## Changes

### 1. `flutter_shadcn_kit/analysis_options.yaml`
Now contains **only** `include: package:flutter_lints/flutter.yaml` plus the pre-existing
`analyzer.exclude` entries. Every relaxation the old file carried was removed
(`errors: … ignore` for duplicate/unnecessary/unused import, null comparison, dead code,
deprecated member; `linter.rules` set to `false` for `unnecessary_const`,
`sort_child_properties_last`, `implicit_call_tearoffs`, `unnecessary_underscores`).
`test/rearch/fixtures/**` was added to `exclude`: those files are deliberate
lint-violation fixtures for the layer/owner checkers (they carry unused imports and a
Material import on purpose) and are parsed directly by the guardrails, not linted.
`flutter_lints` was already a dev dependency (`^6.0.0`), so no dependency was added.

### 2. `lib/registry/**` — real fixes (164 files)
- **161 mechanical** (`dart fix`, verified afterwards): unused/unnecessary/duplicate imports,
  `sort_child_properties_last`, `unnecessary_const`.
- **8 `deprecated_member_use`**, hand-migrated against the SDK source:
  - `SizeTransition.axisAlignment: a` → `alignment: Alignment(-1.0, a)` (accordion, toast_exit),
  - `ScrollView`/`RenderViewport.cacheExtent` → `scrollCacheExtent` (scrollable_client),
  - `Color.value` → `toARGB32()` (color_utils).
- **2 `unnecessary_null_comparison`** removed (patch, markdown_parser/view).
- **57 `prefer_initializing_formals`** (the app reports 25 of these in its subset): the
  `Foo({required T bar}) : _bar = bar` pattern now uses `this._bar`, which Dart 3.12+
  maps to the **public** name `bar` — the public API is unchanged.
- **5 component `meta.json`** deps dropped after the imports they referenced were removed
  (`card`→tokens, `command`→subfocus_item, `dialog`→captured_wrapper, `pinned_sheet`→drawer,
  `text_animate`→markdown_parser). `check_layers` went from 0 to 5 `unused-dependency`
  warnings; now back to the baseline 0.

### 3. Language version — why `this._field` and `// @dart=3.13`
`prefer_initializing_formals` only fires for a private field + public named parameter once
the `private-named-parameters` feature is enabled, i.e. **language version ≥ 3.12**. The
kit pinned `^3.10.7`, so its own analyzer could not even see the 57 findings a fresh app
sees. Two coordinated changes:
- `flutter_shadcn_kit/pubspec.yaml`: `environment.sdk` `^3.10.7` → **`^3.12.0`** (the
  feature minimum; P4-T1's `analyzer: ^14.0.0` already needs ≥ 3.11). `^3.12.0` is chosen
  over `^3.13.4` because 3.12 and 3.13 format identically while 3.10 does not — this avoids
  reformatting ~40 unrelated files.
- **17 files** carry `// @dart=3.13` as their first line so they lint/format identically in
  the kit, in the **docs mirror** (the docs app is still on `^3.10.7` and compiles
  `docs/lib/ui/shadcn/**` verbatim), and in a fresh 3.13 app. Once the docs app's floor is
  raised these headers become redundant and can be dropped.

### 4. `test/**`
- 43 `test/registry/**` files: import/const/sort/deprecated fixes + 3 analyzer-14 API fixes in
  `test/registry/themes/generated_theme.dart` (`NamedType.name2`→`.name`,
  `NamedExpression`→`NamedArgument`).
- **Restored** the 12 `test/rearch/fixtures/**` files that an earlier `dart fix test` had
  gutted (it removed their intentional unused/Material imports and broke the layer tests).
  Restored from HEAD with `git show HEAD:<path> > <path>`; `flutter test test/rearch` is green.

### 5. `gen/**` (2 files) + `tool/**` (3 files)
- `gen/bin/dotguides_gen.dart`, `gen/bin/llms_gen.dart`: analyzer-14 AST migration
  (`ClassDeclaration.name/members`→`namePart.typeName`/`body.members`, `EnumDeclaration`
  likewise, `ExtensionDeclaration.extendedType`→`onClause?.extendedType`,
  `ConstructorDeclaration.returnType`→`typeName`). Not in P4-T1's scope (`tool/**` only).
- `tool/rearch/src/registry_scan.dart`: 2 `prefer_initializing_formals` surfaced by the floor
  bump (`RegistryScan._` → `this._componentByDir`/`this._sharedIdsByRoot`). P4-T1 was finished
  when this landed.

### 6. Regenerated
- `lib/registry/manifests/registry.json` (`--check` up to date),
- `docs/lib/ui/shadcn/**` via `docs/tool/sync_registry.sh` (`--check` up to date),
- `docs/lib/generated/*.dart` + `docs/lib/previews/component_previews.dart` via
  `dart run tool/gen_docs_data.dart` (`--check` up to date).

### 7. CLI (`shadcn_flutter_cli`, 13 files)
- Removed `kInstallRootAnalysisOptions` + `InstallerFileInstaller.ensureAnalysisOptions()` and
  the call in `installer.dart`.
- Removed its test group and the `analysis_options.yaml` expectations in
  `installer_v2_test.dart`, `installer_golden_install_test.dart`; the e2e now asserts the file
  is **absent**.
- Updated the README + `doc/user/{commands,components,complete-guide}.md`,
  `doc/testing-guide.md`, `doc/reference/manual-testing-guide.md` and
  `tool/cli_manual_smoke.sh`, which documented/checked the removed file.
