# P4-T3 — remove per-file `// @dart=3.13` pins; one consistent SDK floor

Status: **done** (one external blocker, not caused by this task — see "Blockers").

## 1. What the pins were actually for (step 1)

Removing a pin and re-analyzing pins the blame on exactly one language feature:
**`private-named-parameters`** — a field formal whose *parameter name* is private
(`this._keys`), which is how the registry keeps a private field reachable from a
public named-argument call site.

Evidence chain:

| Check | Result |
|---|---|
| `grep -rn "this\._" lib/registry --include='*.dart'` | 68 occurrences; the public-facing ones are `theme/theme.dart:24` (`this._platform`), `keyboard_shortcut/keyboard_shortcut.dart:194` (`this._keys`) and `:202` (`this._activator`) |
| `analyzer-14.5.0` `ExperimentalFeature.private_named_parameters` | `releaseVersion: Version.parse('3.12.0')`, `isEnabledByDefault: true` → **shipped in Dart 3.12.0** |
| All 17 pins removed + `sdk: ^3.12.0` | `dart analyze lib/registry` → **No issues found!** |
| All 17 pins removed + `sdk: ^3.11.0` (after `flutter pub get`) | **242 issues**, every one of them `experiment_not_enabled` on `private-named-parameters` plus its cascade of `undefined_named_parameter` |

Note the pins were *not* load-bearing for their own files: the scanner gates the
feature in the semantic error verifier, not the parser, so a single-file probe
(`dart analyze <file>`) reports nothing. Only a whole-package analysis with a
lowered SDK constraint reveals it. That is why the pins survived the earlier
flutter_lints work.

**No other post-3.12 feature is used.** A clean analysis at `^3.12.0` proves it:
any feature needing a higher floor would still fail there.

## 2. The SDK floor

The floor is **`^3.12.0`**, proven both ways above (analyzer metadata says 3.12.0;
3.12 analyzes clean, 3.11 does not). `^3.13.0` would be wrong — nothing needs it.

Set in:

| File | Change |
|---|---|
| `flutter_shadcn_kit/pubspec.yaml` | `sdk: ^3.12.0` (unchanged) + a comment recording why the floor is 3.12 and that no per-library pins exist |
| `docs/pubspec.yaml` | `sdk: ^3.10.7` → **`^3.12.0`** + comment |
| `flutter_shadcn_cli/README.md` | Install-docs paragraph stating installed components need `sdk: ^3.12.0` |
| `flutter_shadcn_cli/doc/user/complete-guide.md` | Requirements bullet: Dart SDK 3.12.0 or newer |

The docs bump was **required**, not cosmetic: the mirror under
`docs/lib/ui/shadcn/**` is compiled at the docs package's own language version
(3.10), so with the pins gone it would have hit `experiment_not_enabled` on
`keyboard_shortcut`/`theme`. This is the finding P4-T2 flagged as blocked.

### CLI `init` pubspec check — verified absent

The CLI has **no** SDK-constraint check to edit. `InitPubspecDelta` carries only
`dependencies` / `devDependencies` / `flutterAssets` / `flutterFonts`; the
`startsWith('sdk:')` branch in `pubspec_editor.dart` is about `flutter: sdk: flutter`
dependency entries, not `environment.sdk`. `doctor` has no SDK diagnostic, and no
`languageVersion` / `@dart=` handling exists anywhere in `lib/`. The only
`environment:` blocks in the CLI are the throwaway Studio scratch-project
templates (`studio_manager.dart:290`, `:521`), which build the *old* v1 registry
and are unrelated to component installs. The floor is therefore documented in the
install docs instead, as the brief allows.

## 4. `keyboard_shortcut` usable from outside its library (step 3)

`KeyboardShortcut`'s constructors take `this._keys` / `this._activator`. The
declared field is private, but the **call-site name is the public `keys` /
`activator`** — Dart strips the underscore for named arguments. Both halves of
that contract are proven:

- **Positive** — new file `flutter_shadcn_kit/test/registry/components/keyboard_shortcut_public_api_test.dart`
  (5 tests, all passing). It imports the component from a *different library* and
  constructs `KeyboardShortcut(keys: …)`, `KeyboardShortcut.fromActivator(activator: …)`,
  `KeyboardKeyCap(keyboardKey: …)`, plus the `spacing` / `theme` / `padding` /
  `background` / `foreground` / `borderRadius` public parameters. Existing in-library
  call sites (`preview.dart`, the pre-existing `keyboard_shortcut_test.dart`) already
  relied on `keys:`; the new file locks that in from outside.
- **Negative** — the compiler enforces that `_keys` / `_activator` are *not*
  callable. Verified in a scratch package, since a runtime test cannot express
  non-compilation:
  ```
  error • The named parameter '_keys' should use the corresponding public name
          'keys' at the callsite. Try changing the name to 'keys'
  ```
