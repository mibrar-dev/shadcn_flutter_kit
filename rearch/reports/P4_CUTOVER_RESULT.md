## 0. Execution note (deviation from cutover.sh)

`rearch/cutover.sh --dry-run` showed 0 blockers (all B24/B25 components present). `--apply` was **not run as a
script**: its `git status --porcelain` precondition tripped on the orchestrator's untracked `rearch/design/`
(P6-A mockups) and P6-B report, while the brief's precondition ("clean except your own changes") held for all
tracked files. The script's exact git operations were executed manually in order (the brief explicitly allows
"the git operations it performs"), with one correction: after the `git mv` renames, the old tree must be removed
with `git rm -r -f` — the staged rename makes plain `git rm` refuse (the script was only ever dry-run, so this
was never hit). `rearch/cutover.sh` now refuses to run again ("already executed") so it cannot half-move the
flat tree.

The mechanical rename+delete landed in the orchestrator's commit `8d04b3a` (message says "P6 docs build plan"
but the stat shows 3889 files / 361,090 deletions — the staged cutover was swept into it). Everything after
that (meta import fixes, barrel, tests, tooling, manifest) is in the working tree/index awaiting the
orchestrator's commit.

## 3. Manifest (brief step 4)

- **New tool**: `tool/registry/gen_registry_manifest.dart` + `tool/registry/src/{registry_manifest,layer_scan,dart_imports,manifest_error}.dart`
  (uses `package:analyzer` for directives, `package:crypto` for hashes, `package:yaml` for pubspec).
- **Output**: `lib/registry/manifests/registry.json` (schemaVersion 2, ~340 KB):
  19 foundation units, 6 theme units, **73 primitive units / 90 primitive→primitive edges**, 118 components,
  42 presets, 651 file hashes. Deterministic (no timestamps, sorted keys); `--check` diffs.
- **meta.json imports fixed** in all 118 files: `ui/shadcn/<id>/` → `ui/shadcn/components/<id>/` (P5_CLI_PLAN §9.6);
  the generator now rejects a meta import that misses `components/`.
- **Test**: `test/rearch/registry_manifest_test.dart` — (1) manifest up to date with the tree,
  (2) validates against `rearch/reports/registry_manifest.v2.schema.json` via an in-test draft-2020-12 subset
  validator, (3) every component dep id exists, (4) every primitive closure terminates and exists.
- **Schema amendment (needs orchestrator awareness)**: the P5-A `componentTheme` def allowed only
  string/null/object-of-strings values, but its own measured keys `popupTheme`/`menubarTheme` nest another
  theme block (`fields` etc.). The third `oneOf` branch was relaxed to `{"type": "object"}` (description notes
  the P4-Z amendment). Without this, the real `menu` meta.json cannot validate.
- **Corrections to P5-A measurements** (flag for Phase 5):
  - primitive edges are **90, not 27** — the 27 came from ignoring bare relative imports such as
    `import 'clickable_state.dart';`;
  - the primitive graph **has cycles** (`clickable ↔ clickable_state`, `overlay_manager ↔ overlay_manager_layer`,
    the popover cluster). The CLI closure must be cycle-tolerant (visited set); "cycles rejected" in
    P5_CLI_PLAN §6.1 cannot hold for this tree.
  - `themes/index.json` is kept (unused by code today; the manifest's `themes` map supersedes it).
