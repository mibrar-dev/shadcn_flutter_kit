## 2. Lock v2 shape

```json
{
  "lockfileVersion": 2,
  "registry": { "name": "…", "ref": "…", "manifestSha256": "…", "generatedAt": "…" },
  "installRoot": "lib/ui/shadcn",
  "theme": { "id": "vercel", "path": "lib/ui/shadcn/theme/app_theme.dart", "sha256": "…" },
  "layers": {
    "foundation": { "units": ["data"], "files": { "<project-relative path>": "<sha256>" } },
    "theme":      { "units": [], "files": {} },
    "primitives": { "units": [], "files": {} }
  },
  "components": [
    {
      "id": "button",
      "version": "1.0.0",
      "files": { "…": "<sha256>" },
      "userOwned": { "…/button_theme.dart": "<sha256 @install>" },
      "deps": { "foundation": [], "theme": [], "primitives": [], "components": [] },
      "api": { "classes": ["Button"] }
    }
  ]
}
```

Matches `P5_CLI_PLAN.md` §4. All three `layers` keys are always emitted; `theme` is
emitted as `null` before a preset is chosen; `version` is omitted when the manifest
publishes none (the v2 manifest component schema has no `version` key).

Deterministic output: map keys sorted, components sorted by `id`, unit/symbol lists
sorted and de-duplicated, two-space indent, trailing newline.

## 3. Invariants the batch guarantees

1. **User-owned files are never updatable.** `files` and `userOwned` are disjoint by
   construction — a path in both raises `LockFileException` (a corrupt lock, never a
   silent overwrite). `ShadcnLock.updatablePaths` and `ShadcnLockComponent.updatableFiles`
   subtract `userOwned` defensively, and `LockDriftReport.updatablePaths` only ever
   contains unchanged, non-user-owned paths. In `inspect()` a user-owned entry wins
   over a registry-owned entry for the same path.
2. **Drift detection.** Every tracked path is re-hashed from disk:
   `unchanged` / `modified` / `missing`. Missing **user-owned** files are reported but
   do not make the report dirty (`isClean`), because the user owns that file.
3. **Registry moved.** `ShadcnLockRegistry.hasMoved(currentManifestSha256)` drives
   `LockDriftReport.registryMoved`.
4. **Corrupt vs missing.** A missing `shadcn.lock` loads as an empty v2 lock; an
   existing but unreadable one throws `LockFileException` (empty file, bad JSON, non-object
   root, `lockfileVersion != 2`, non-sha256 digest, component missing `id`). The v1 message
   says the file must be deleted and `shadcn init` re-run — that is the whole migration story.
5. **Merge.** `ShadcnLock.mergeWith` upserts components by `id`, unions layer units and
   files (incoming hashes win because they were written last) and prefers incoming
   registry/installRoot/theme when set. `ShadcnLockRepository.merge(incoming)` is the
   one-call read-merge-write.

## 4. API for the downstream batches

```dart
// B4 installer core / B5 commands
final repo = ShadcnLockRepository(targetDir);
final lock = await repo.load();                  // missing -> empty v2
await repo.save(lock.upsertComponent(record));
await repo.update((current) => …);                // read-modify-write
await repo.merge(incoming);
final report = await repo.inspect(lock, componentIds: {'button'}, manifestSha256: sha);
// report.modified / .missing / .userOwnedDrift / .updatablePaths / .isClean / .toJson()
lock.updatablePaths;      // Set<String>: safe to overwrite
lock.userOwnedPaths;      // Set<String>: never touched
lock.ownerOf(path);       // component id | layer key | null
lock.dependentsOf(paths); // ids owning any of paths (incl. user-owned)
```

`installer_manifest_part.dart` replaces `_pendingLockfileRecord` with a
`ShadcnLockComponent(id, version, files, userOwned, deps, api)`; the api symbols it needs
for the single-owner preflight come from `LockComponentApi.fromJson` (list values are
symbols; map values such as `providedBy` contribute their keys).

## 8. Deviations

1. **More files than the brief listed.** 9 focused files instead of 2, to respect the
   ~400-line cap. No file exceeds 287 lines.
2. **`shadcn_lock_repository.dart` re-exports the lockfile library.** One import gives
   callers every lock type; avoids 8 import lines in every consumer.
3. **Unknown top-level and per-layer keys are ignored**, not rejected (only `lockfileVersion`
   is strict, plus structural type checks). Forward compatibility for hand-edited locks.
4. **A non-object entry in `components[]` is skipped** rather than fatal, so one bad entry
   cannot block `doctor`.
5. **`removeComponent(id)` has no `--purge-user-themes` flag.** The dropped record is read
   before removal (`lock.componentFor(id)?.userOwnedPaths`); the lock cannot act on files it
   no longer tracks. The earlier `purgeUserOwned` parameter was dead code and was removed.
6. **The generated theme file is tracked** with owner `theme`, so its drift is visible.
   `ownerOf` therefore returns `theme` both for `theme/theme.dart` and for
   `theme/app_theme.dart`; consumers disambiguate by path.
7. **`LockFileException extends FormatException`** so callers that already surface format
   errors for user files keep working.

## 9. Open questions

- Does `registry.manifestSha256` stay a single digest, or does multi-registry support need a
  map? The v2 lock has one `registry` object (plan §4), so a second registry would need a
  lock change. Plan §6.4 still requires two registries providing `button` to work.
- `components[].version` has no source in the v2 manifest schema (`registry.version`
  exists, per-component does not). Optional today; B4 can fill it from
  `manifest.registry.version` if a per-component version is wanted.
- Should `doctor` treat a missing **user-owned** file as drift? Today it is reported in
  `userOwnedDrift` but keeps `isClean == true`, since the user owns the file.
- `LayerState.units` is stored but nothing prunes it yet; `remove` dropping an orphaned
  unit is B4's job (`layers.*.units` rule, plan §4).
