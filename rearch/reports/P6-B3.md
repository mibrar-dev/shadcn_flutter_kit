## 8. Cross-scope registry fix (flagged for QA review)

**In my brief's scope there is no docs-side fix for this — verified by
bisection.** `dashboard-01` and `pricing-01` take a wide-branch
`Row(crossAxisAlignment: stretch)` containing `Gap` separators. Inside the
block's own `SingleChildScrollView` the height is unbounded, so Flutter
hands non-flex children `tightFor(height: Infinity)` and `RenderGap`
asserts "BoxConstraints forces an infinite height" (debug builds; 30+
exceptions on the index page). Any app placing these blocks in a scroll
view — the normal usage — hits the same crash.

P6-B1's harness never caught it: `flutter_test`'s default 800×600 window
clamps every `SizedBox(width)` the harness uses, so the ≥1080 px branch
never executes (proven: the identical harness with a 1440 px viewport
throws; a 16-block × 1440 px probe showed exactly these 2 blocks failing,
all others clean — probe deleted after use).

Fix (2 files, visual-preserving): wrap each wide Row in `IntrinsicHeight`,
which bounds the cross axis before the stretch Row sees it; cards keep
equal heights. `RenderGap` implements intrinsics, so measurement is safe.

- `flutter_shadcn_kit/lib/registry/blocks/dashboard-01/dashboard_01.dart`
- `flutter_shadcn_kit/lib/registry/blocks/pricing-01/pricing_01.dart`

Verified: all 16 blocks render clean at a true 1440 px viewport; registry
blocks suite still +135; mirror re-synced; `block_sources.dart`
regenerated (it embeds block Dart verbatim). **Orchestrator: please confirm
this fix stays, or reassign to the registry owner — reverting it re-breaks
every Blocks page in debug builds.** Follow-up for the registry owner:
make the blocks harness set a ≥1440 px viewport so wide branches execute.
