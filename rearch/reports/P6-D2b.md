# P6-D2b — Codegen: API tables for static/factory-first components

Status: **done** (all gates green). Scope: extend the docs codegen so
components whose primary constructor is parameterless or private surface the
declared entry points from the manifest `api` block, plus the matching
`DocsApiMember` row type in `docs_api.dart`, golden updates and a regression
test that every declared name resolves. No docs pages/widgets touched
(D6 owns them).

## 1. Problem

`gen_docs_data.dart` built every API table from a single primary class'
unnamed constructor. Two components had no callable surface there:

| Component | Primary class found | Table rendered | Real API |
|---|---|---|---|
| `color` | `ColorDerivative` (`const ColorDerivative()`) | 0 params, 0 rows | 4 factories (`fromColor`/`fromHex`/`fromHSV`/`fromHSL`) + 18 conversions |
| `formatter` | `TimeFormatter` (`const TimeFormatter({required this.length})`) | 1 row: `length` | `TextInputFormatters` — a private ctor (`TextInputFormatters._()`) holding 5 factories + 2 constants, plus the top-level `constraintToNewText` |

The manifest `api` block already names the real entry points
(`api.methods`, `api.constants`, `api.functions`); the codegen only read
`api.classes`. A third component silently fell into the same bucket:
`overlay_configuration` (`OverlayConfiguration` is abstract with a
parameterless const ctor; its API is the top-level `showOverlay`).

## 2. What was built

### New tool modules (`docs/tool/src/`)

| File | LOC | Purpose |
|---|---|---|
| `api_model.dart` | 132 | Plain data model (`ApiFacts` gained `members`, plus new `ApiMemberFacts`, `DeclaredMembers`) — no `package:analyzer` types, so the renderer does not depend on the analyzer |
| `api_members.dart` | 239 | `extractDeclaredMembers()`: resolves each declared `Owner.member` / top-level name against the entry file with `package:analyzer` (unresolved AST) and emits `{name, kind, returnType, isStatic, params, doc}` rows. Declared-but-unresolvable names are reported via an `unresolved` sink, never invented |
| `ast_docs.dart` | 166 | AST helpers shared by `dart_scan.dart` and `api_members.dart` (doc comments, formal-parameter facts, field lookup) |

### Change sites

- `dart_scan.dart` (560 → 407 LOC after the helper move) — `extractApi()`
  gained a `declared` parameter. Primary-class selection now prefers a
  factory set: among the manifest `api.classes` candidates that has no public
  unnamed constructor *and* owns declared entries (`formatter` →
  `TextInputFormatters` instead of `TimeFormatter`). When the selected
  constructor is private or takes no parameters, `params` stays empty and the
  declared rows are emitted instead; a private unnamed ctor (`Foo._()`) is no
  longer treated as a public one.
- `registry_scan.dart` — `ComponentFacts` gained `apiMethods`,
  `apiConstants`, `apiFunctions` (manifest `api` first, `meta.json`
  fallback, same rule as `api.classes`).
- `model_build.dart` — passes the declared set into `extractApi`;
  `describeModel` gained an `api members: …` summary line.
- `render_api.dart` — emits a `DocsApiMember` class and a `members` field on
  `DocsApiTable` (default empty, so nothing else breaks).
- `gen_docs_data.dart` — exports the three new modules.

### Generated data

`docs/lib/generated/docs_api.dart` is the only checked-in file whose content
changed (+501 lines; the other 7 regenerated byte-identical). It now carries
31 member rows across 3 components, and every one of the 118 tables got the
new `members:` field (empty for the other 115).

## 3. Key decisions

1. **Manifest-driven, never guessed.** Rows come only from names the manifest
   declares; the codegen then reads the real signature from the source. A
   declared name that no longer exists in the entry file is collected into an
   `unresolved` list (asserted empty by the new test) rather than silently
   dropped — so a stale manifest can never fabricate or shrink a table
   unnoticed.
2. **Selection order for factory sets.** `TextInputFormatters._()` is private,
   so the old "first candidate with a public unnamed constructor" rule picked
   `TimeFormatter`. The new rule prefers the class that cannot be constructed
   publicly but owns declared entries, then falls back to the old behaviour.
   This keeps all 115 unaffected components byte-identical.
3. **`kind`/`returnType`/`isStatic` are first-class fields, not encoded in the
   name.** `ColorDerivative.fromHSV` is a redirecting `const factory`, so it
   is `kind: 'factory', isStatic: false, returnType: 'ColorDerivative'`, while
   `fromColor` is `kind: 'method', isStatic: true`. The docs page can group
   factories, statics and instance methods differently without re-parsing.
4. **Mutual exclusivity.** A table has constructor params *or* member rows,
   never both, matching the "one API surface per component" model.
5. **No page changes** (per the brief): `component_sections.dart` renders
   `table.params` only, so the member rows are in the data layer awaiting D6.

## 5. Test additions (`tool/gen_docs_data_test.dart`)

- **`formatter` golden**: symbol switches to `TextInputFormatters`, `params`
  empty, 8 member rows in declared order (5 factories + 2 constants +
  `constraintToNewText`), with per-row `kind`, `returnType`, `isStatic`,
  param names/types/defaults (`hashPrefix` default `false`) and doc first
  lines. Replaces the old `params.first.name == 'length'` assertion.
- **`color` golden**: 22 member rows, `fromColor`/`fromHex` static,
  `fromHSV`/`fromHSL` `kind: 'factory'` with `isStatic: false`, `toColor`
  parameterless, `fromHex.returnType == 'ColorDerivative?'`.
- **Declaration-coverage test**: for every component with a declared set,
  re-runs `extractApi` + `extractDeclaredMembers` and asserts (a) the
  selected component emits members and (b) nothing lands in the `unresolved`
  sink. This is the guard against future manifest drift.
- **Exhaustiveness**: exactly `['formatter', 'overlay_configuration',
  'color']` carry member rows — any other component growing a member table
  fails the test.

## 6. Findings worth flagging

1. **`overlay_configuration` was the same bug, unfixed by the brief.** Its
   `api.functions: ["showOverlay"]` was already in the manifest but invisible
   on the site; its primary class is an abstract base with a parameterless
   const ctor. It now renders 1 row. If that is unwanted, it is a manifest
   edit, not a codegen edit.
2. **The brief understates `color`'s surface**: not 4 static factories but 22
   declared entry points (4 creation + 18 space-preserving conversions,
   including instance methods `changeTo*` and `transform`). The codegen emits
   all of them because the manifest declares them; the page may want to group
   creation vs. conversion (see §3.3).
3. **`docs_api.dart` grew to 370K** (345.5K → 370K, +7%). Most of it is the
   118 empty `members: <DocsApiMember>[]` lines. D2's open question #4 about
   the JS budget gets slightly worse; if it matters, the `members` field can
   be omitted when empty (a deterministic renderer change, no model change).
4. **`hasApiTable` semantics shifted by one case**: a component whose primary
   class has a private-only ctor and *no* declared entries now reports
   `hasApiTable: false` (it previously reported `true` with a table full of
   uncallable private parameters). No component in the current registry
   changes (`flutter test` covers the 118-table assertion), but it is a
   behaviour change the QA lead should know about.

## 7. Round 2 — data repair (QA finding: correct)

**What QA found:** round 1's new test failed on
`flutter test tool/gen_docs_data_test.dart` because it asserted every declared
`api` name resolves. `button` — and 92 others — declare names that resolve in
no file the extractor read. **The root cause was mine, not the data's**: the
extractor only parsed the **entry file**, but a component's API is spread
across every file it installs (`buttonDefaults` lives in `button_style.dart`,
`buttonThemeOverrides` in `button_theme.dart`).

### 7.1 Tool: resolve against the component's installed files

`extractDeclaredMembers` now takes `List<DeclaredSource>` (path + parsed unit
+ source) instead of one entry unit, and walks them in order.
`dart_scan.declaredSources()` builds that list: entry file first (so
`color`/`formatter` keep resolving there), then the manifest `files` and the
user-owned theme file. Previews are excluded — they are demo code, not API.

**Effect: 93 failing components collapsed to 11.** 82 were only failing
because of the narrow scope; the 11 that remain are genuine data errors.

### 7.2 Data: 10 `meta.json` files corrected

Two root causes, both fixed per the registry's own convention (see `input`,
which already keeps `api.<kind>` component-owned and lists primitive-provided
symbols — including functions — under `api.providedByPrimitives`):

1. **Primitive-owned symbols listed as component API** (PLAN §5 single-owner
   violation). Moved into `api.providedByPrimitives` under the owning
   primitive, which each component already declares in `deps.primitives`:

   | Component | Names | Owning primitive |
   |---|---|---|
   | `markdown` | `computeStableMarkdownPrefixLength` | `markdown_parser` |
   | `text_animate` | 7 `*Streaming*` / `animateStreamingBlock` | `streaming_text` |
   | `color_field` | `paintHSVColorField`, `paintHSLColorField` | `color_field_paint` |
   | `file_picker` | `fileUploadRowDefaults` | `file_value` (merged into the existing block) |
   | `filter_bar` | `filterBarDefaults`, `FilterMatchers` | `filter_core` |
   | `window` | `kDefaultWindowConstraints`, `windowSnapPresets`, `windowMaximizeSnapStrategy` | `window_manager`, `window_snap` |
   | `navigation_bar` | `navigationItemDefaults`, `navigationActiveItemDefaults` | `navigation` |
   | `error_system` | `rule`, `guard`, `guardSync`, `apiRules`, `authRules`, `validationRules`, `platformRules`, `networkRules`, `fingerprintFor`, `fallbackRule` | `error_handling` |

   Nothing is deleted — every name stays documented, and every theme/widget
   reference (`"defaults": "filterBarDefaults"`) still resolves through the
   component's re-export.

2. **Malformed entries** (2):
   - `anchor`: `"anchorTransformRelativeTo(RenderBox, RenderObject)"` was a
     pasted **signature**, not a name — it resolved to nothing, so `anchor`
     rendered zero rows. Corrected to the symbol name. `Anchor` is an abstract
     parameterless class, so `anchor` now correctly emits its real API row.
   - `eye_dropper`: `PreviewLabelBuilder` is a **typedef** but was listed under
     `constants`; moved to `api.typedefs`.

### 7.3 Downstream regeneration

`gen_registry_manifest.dart` -> `sync_registry.sh` -> `gen_docs_data.dart`, all
verified fresh with `--check`. `docs_api.dart` grew by 1 row (the `anchor`
fix): **32 member rows over 4 components** (`formatter`, `anchor`,
`overlay_configuration`, `color`).

### 7.4 Test hardening

- **Reports all failures at once**: the test accumulates
  `component => [unresolved names]` and asserts once, so a reviewer sees the
  whole list in a single run (this is how the 11 were enumerated).
- **New invariant**: a component must end up with *some* API surface
  (constructor params or member rows) — catches a manifest that empties both.
- **New `anchor` golden** pinning the corrected name, `kind: 'function'`,
  `returnType: 'Matrix4'`, params `anchorBox`/`source`.

## 10. Open questions

1. **D6 handoff**: the docs pages render `table.params` only. The member rows
   need a table (or a second section) in `component_sections.dart`, plus a
   copy decision — the generated `summary` for `formatter` is now
   `"Factory methods for common text input formatters."` (the
   `TextInputFormatters` class doc) rather than `TimeFormatter`'s, and for
   `color` it stays `"An abstract base class representing a color that can be
   transformed between different color spaces."`.
2. Should the `color` table be split into creation/conversion groups, and
   should instance methods be shown at all for a "factory-first" component?
   That is a page decision; the data carries `kind`/`isStatic` to support it.
3. `overlay_configuration` inclusion (§6.1) — confirm with the registry owner.
4. Should `api.classes` also drop primitive-owned classes? `filter_bar` lists
   ~15 (`FilterMatcher`, `FilterField`, `FilterState`, …) owned by
   `filter_core`, while `input` keeps `api.classes` component-owned.
   Inconsistent, harmless to the tool (candidate selection tolerates it), and
   out of this brief's scope.
5. Empty `members: <DocsApiMember>[]` on 114 tables: keep for uniformity, or
   omit to save ~8K of generated source (§6.3).
