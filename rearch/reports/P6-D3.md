## 4. Key decisions (evidence-backed)

1. **Docs-only chrome widgets.** Sidebar rows (30 px), palette rows (36 px)
   and the search trigger are built on the shared `Clickable` primitive with
   role colors, because the registry `Button` size table is 28/32/36/40 px and
   cannot match the measured row heights; the spec's `R:button` mapping is
   honoured for nav links, Copy Page, icon buttons and pagers.
2. **Preview frame = `R:card`** with `padding: 0`, `borderWidth: 1`, no
   shadows (spec §6 open question 3 answered — no `D:PreviewFrame` needed).
3. **Palette is docs-only** (spike outcome): registry `Command` always inserts
   dividers between rows and its dialog ships its own scrim, both conflicting
   with the measured panel; the docs panel reuses the registry `Input`.
4. **CopyButton is fire-and-forget** on the clipboard write so the check state
   is immediate (and testable without a platform clipboard mock).
5. **`/docs/theming` and `/docs/dark-mode` routes added** (not in D1's table)
   because the spec sidebar lists both; they render placeholders until D4.
6. **Route transitions are instant** (`transitionDuration: zero`) — spec §5.2
   removes the route fade; only the palette keeps an enter tween.
7. **Landing copy is original**; every number (`kStats.components`,
   `kStats.presets`, `kStats.materialImports`) and the collage install command
   come from generated data.
8. **Copy Page copies `title + description + route`**; the reference copies
   page markdown, which the docs app does not render (no markdown source).
   The chevron/dropdown menu is omitted (no faithful menu contents available).
9. **Footer visibility** mirrors the reference hiding rules (`/docs*` and
   `/themes` hidden, landing shows it).

   after this report needs a re-sync + regeneration.
3. **Registry bug (needs a kit fix):**
   `components/keyboard_shortcut/keyboard_shortcut.dart` now declares
   `required List<LogicalKeyboardKey> this._keys` and
   `required ShortcutActivator this._activator`. Private named parameters

   `KeyboardShortcut.fromActivator(...)` are unusable by apps. D3 removed the
   component from the palette (docs-only key caps); the registry needs public
   parameter names (`keys`/`activator` with body assignment or a private
   constructor).
4. **`prefer_initializing_formals`** (analyzer 14 under the new language
   version) flagged D1 constructors; refactored to body assignments with
   `late final` fields — no `// ignore` anywhere.

## 11. QA round 3 (2026-10-09) — preset provenance + official neutral

### F1 — `vercel` restored; dark derived (no real source exists)

Provenance investigation for the pre-migration dark map (all read-only):

- `git log --all --name-only -- '*vercel*'` / `-G 'Vercel'`: the preset
  first appears in `f4f48d8` as `flutter_shadcn_kit/lib/registry/themes_preset/vercel.json`
  and is re-emitted by `22c0f20` (schema v2 migration). **Both already carry
  dark == light** (`0xFF…` values).
- `fxorign/main`, `chore/upstream-parity-audit`, the old docs copy
  (`docs/lib/ui/shadcn/themes_preset/vercel.json`), the generated
  `preset_themes.dart` / `app_theme_preset.dart`, the demo copy
  (`ai_shadcn_demo/.../preset_themes.dart`), the CLI data
  (`preset_theme_data.dart`, `light`/`dark` both empty) and the CLI fixture
  (`shadcn_flutter_cli/test/fixtures/theme_registry_v2/themes/vercel.json`):
  **every one has dark == light. No real dark source exists.**

So `vercel.json` was restored to HEAD for everything except `dark`, and the
dark map is the **documented inverse**: for each light token, sRGB→HSL,
`L' = 1 − L` (hue and saturation unchanged), back to sRGB, alpha byte
preserved. Results: background `#FFFFFF→#000000`, foreground
`#000000→#FFFFFF`, primary `#000000→#FFFFFF`, border/input `#E0E0E0→#1F1F1F`,
ring `#9CA3AF→#505763`, destructive `#FE5F55→#AA0B01`, charts invert. Light
and every non-dark field are byte-identical to HEAD.

### F2 — new `neutral` preset from `themes-css/neutral.css`

- The existing `migrate_presets.dart` converter fits only legacy JSON + CLI
  atoms, so the CSS was converted with a documented one-off:
  `oklch(L C H [/ a%])` → OKLab → linear sRGB → sRGB, 8-bit rounding, alpha
  byte kept (`/10%` → `1A`, `/15%` → `26`).
- `APP/lib/registry/themes/neutral.json` (schema v2, 32 tokens per mode):
  light background `#FFFFFF`, foreground `#0A0A0A`, primary `#171717`,
