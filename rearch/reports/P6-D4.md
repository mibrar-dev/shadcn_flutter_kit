## Decisions

1. **Function-first API extraction**: Extended the D2 codegen to extract parameters from primary top-level functions (`showShadcnDialog`, `showShadcnPopup`, `openDrawer`) when no widget class constructor exists. The primary function is selected by name containment + `show*` > `open*` ranking. This brings the API table count from 110 to 113 (dialog, popup, drawer now have params).

2. **Component page structure**: Title row (h1 + file-count/stability badges) → typeset description → preview card (PreviewFrame + PreviewStage + CodeTeaser) → H2 sections: Installation (install block), Usage (README snippets), API Reference (params table), Theme (fields table), Accessibility (keyboard table, hidden when empty) → prev/next pager. All facts from generated data.

3. **Install block**: Line tabs (Command|Manual) + package-manager pill tabs (flutter_shadcn/dart/flutter) + copy button. The Manual tab lists the exact generated file list from `kComponentFileLists` with user-owned files badged.

4. **Themes page**: 192 px rail (preset list with 4 swatches each, radius slider 0–16, mode toggle, footer actions: Copy JSON/Copy Dart/Shuffle/Get Code) beside a live preview of registry components (card, button, input, switch, badge) re-theming through AnimatedShadcnTheme (300 ms tween). The reference's welcome dialog is omitted — the rail is the primary interaction.

5. **Getting started**: Typeset page with `.step`-numbered H3 counters (numbered circle + title) and code figures. Four steps: create project, install layer core, add components, choose preset.

6. **CLI reference**: Typeset page rendering each command section from `cli_snapshot.txt` inside code figures, plus generated flags tables. No card layout — prose + headings + code figures per spec §2.6.

7. **File splitting**: The component page was split into `component_page.dart` (main page + preview card, 194 lines), `component_install_block.dart` (296 lines), and `component_sections.dart` (221 lines) to stay under the ~400-line limit.

## Key findings

- The component page template renders all 118 components from one route, with per-component data driven entirely by the generated manifests (API params, theme fields, keyboard rows, install file lists, snippets).
- Function-first API extraction works: dialog's `showShadcnDialog` now shows 12 params (context, builder, useRootNavigator, barrierDismissible, barrierColor, barrierLabel, useSafeArea, routeSettings, traversalEdgeBehavior, alignment, fullScreen, theme) in the API Reference table.
- The themes page re-themes live: switching presets or toggling mode updates the DocsState, which flows through AnimatedShadcnTheme (300ms ease-out-expo tween) to all registry components in the preview.
- The install block shows the exact generated file lists from the manifest (e.g., button → 3 registry files + 1 user-owned theme file), with the user-owned note.
- The CLI reference renders all 11 command sections from the snapshot with parsed flags tables.
- 54 tests total (37 existing + 17 new D4 tests), all green.
