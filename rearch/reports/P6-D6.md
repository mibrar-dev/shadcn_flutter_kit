## What this batch did

Captured every route at 1440 + 375 × light + dark (88 matrix shots) plus the
11 spec §2.8 state shots, compared each numerically (mean abs diff + %-px
differing) and as side-by-side ref|ours montages, then fixed the P1 deltas the
comparison surfaced.

### P1 fix — preview-card hit-test dead zone (`preview_stage.dart`)

The preview card's full-bleed 1 px border overlay was a bare `DecoratedBox`
painted above the card content. `RenderDecoratedBox.hitTestSelf` returns true
for its whole rect, so the overlay swallowed every pointer event inside the
card — the stage demos, the View Code pill and the in-card copy buttons were
all dead to hover and click, while everything outside the card (sidebar, TOC,
install block, header) worked normally. The overlay is now paint-only:

```dart
Positioned.fill(
  child: IgnorePointer(
    child: DecoratedBox(
      decoration: BoxDecoration(
        borderRadius: theme.borderRadiusXl,
        border: Border.all(color: border),
      ),
    ),
  ),
),
```

Verified after rebuild: pill hover registers (2775 px change), pill click
expands the code pane, stage buttons respond. This unblocked the codeview state
shots.

### P1 fix — code-figure compile break (`code_figure.dart` + tests)

The syntax-highlight pass declared a local `final SyntaxLanguage? language`
that shadowed the `String language` field. Dart's use-before-declaration rule
bound the earlier `language != null` (header flag) to the uninitialised local
(analyzer/CFE divergence: `flutter analyze` was clean, `flutter build web`
failed). Renamed the local to `syntax`, kept the field driving the header
label. Added `test/code_figure_test.dart` (4 tests: coloured spans light/dark,
unknown language plain, empty language plain).

## Decisions

1. **`/create` maps to our `/themes` customizer.** The ref create page is a
   dashboard gallery with a left customizer rail; ours is a preset rail + live
   preview on `/themes` (spec allows the structural difference). The ref's
   large light-mode diffs are its "Build your own shadcn/ui" welcome dialog
   overlay, which our `/themes` intentionally omits (documented in
   `pages/themes.dart`) — not a P1.
2. **Preview stage may grow past 288 px.** Our preview galleries contain
   multiple demos with headings; the stage grows instead of slicing a heading
   off. Ref's single-demo previews always fit 288. Documented deviation.
3. **Codeview framing.** The expanded code pane sits below the 900 px fold at
   scroll-0, so the codeview state shots are cropped from a 1440×1700 capture
   (pane at y≈1020–1309) rather than a 1440×900 viewport frame. Pixel content
   is authentic; the framing differs from ref's scrolled shot by ~126 px.
4. **Debug artifacts moved to /tmp, not deleted.** `precodeview` frames and the
   3 stale light extras that had no ref counterpart were moved out of
   `rearch/design/ours/screens/` (my own session artifacts; the "no deletes"
   rule protects pre-existing files).

## Remaining P2 / known non-P1 gaps

- `/themes` omits the ref welcome dialog (documented decision).
- Our `/create` (Goal-form builder) differs structurally from ref's dashboard
  gallery (spec allows).
- Ref full-page heights for `datatable` (28296 px) and `cli` (24802 px) exceed
  our 16000 capture clip; ours are clipped, not shorter.
- Ref `blocks` / `charts` pages are not routed in our docs (out of D6 scope).
- Pre-existing font warning in the release build (Cupertino/Material icon
  families referenced via `flutter_localizations`/`intl`, not by docs source).
- 375 dark diffs (25–31 mean) are driven by sidebar group-label rhythm and
  hero-copy wrap points — cosmetic, no structural mismatch.
- Header initial focus uses a 0-sized `_HeaderFocusAnchor` with
  `FocusTraversalOrder(order: -1)` and no visible `FocusOutline` so the
  reference's header-first tab order is preserved without a focus ring in
  screenshots; behaviour matches ref, implementation detail differs.
