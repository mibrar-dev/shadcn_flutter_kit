## 2. The contract

`flutter_shadcn_kit/lib/registry/foundation/component_preview.dart`:

```dart
class ComponentPreview {
  const ComponentPreview(this.name, this.builder, {this.description});
  final String name;
  final WidgetBuilder builder;
  final String? description;
}
```

Every listed component exports `const List<ComponentPreview> <camelName>Previews`
from its `preview.dart`; the first entry is the default. Browsing
`package:analyzer` (unresolved AST) for that top-level variable is what
`tool/registry/gen_previews_test.dart` does, so the test cannot drift.

Rules the rewritten previews obey:

1. no `ShadcnThemeData(` anywhere in any `preview.dart` (all 118, gate-checked);
2. the example reads `ShadcnTheme.of(context)` for colours, spacing, radius and
   shadows — a preset switch or the site light/dark toggle re-themes it;
3. the example shrink-wraps: no `Expanded`, no outer fixed-height box, no
   assumption of unbounded space. Components that are inherently measured
   (the colour picker, the feature carousel, the command palette) wrap their
   control in their own `SingleChildScrollView`/`SizedBox` so the stage height
   is what bounds them;
4. controllers and other state are created inside the example's own
   `StatefulWidget` (`initState`/`State`), so two examples can never attach one
   controller twice — the `scrollbar` bug class;
5. spacing comes from `theme.spacing.*` / `EdgeInsetsDensity.*` (P6-F1/F2 kept);
6. `Gap` is never used inside a `Wrap` (the foundation `Gap` requires a Flex or a
   Scrollable ancestor — the old `code_snippet`/`filter_bar` previews did this).

## 4. Bugs fixed, with root cause

| Bug (audit §2.7) | Root cause | Fix |
|---|---|---|
| `chat/chat.dart` OVERFLOW 42px (light+dark) | `ChatGroup` wrapped its `Row` in an `IntrinsicHeight` and set `crossAxisAlignment: stretch`. A stretch `Row` has no intrinsic height, so `IntrinsicHeight` had to invent one from the avatars (32px) and then forced the `Flexible` bubble column into it — the column overflowed by its own height. | Dropped `IntrinsicHeight` + `stretch`; the row now sizes itself to its tallest child (the bubble column) and the avatars keep their own size, positioned by the existing `avatarAlignment` (`AlignmentDirectional.topEnd`). Same picture, correct layout. |
| `empty_state` OVERFLOW 46px | `preview.dart` wrapped every section in `SizedBox(height: 320)` (a fixed outer box) — exactly what the contract bans. | The fixed box is gone; the full-page sizes are laid out in the stage's own bounded box. |
| `image` preview: pinned theme + remote SVG | `preview.dart:23` returned `ShadcnTheme(data: const ShadcnThemeData())` and fetched `raw.githubusercontent.com/.../react-logo.svg` (offline = blank, and it pinned light). | The example now decodes a 48×48 PNG from memory (`base64Decode` → `MemoryImage`) — no network, no pin. The placeholder/error/theme legs show in both modes. |
| `command` "setState() called when widget tree was locked" (found while running the new test) | `SubFocusScope.detach()` handed the sub-focus to the next item synchronously (`findFirstFocus()` → `markFocused` → `setState`). When the focused item is the one being unmounted — a docs page swapping one example for the next — that runs while the framework is tearing the old tree down, where `markNeedsBuild` is illegal. Two examples in a row therefore crashed. | `detach()` now defers the hand-over with `WidgetsBinding.instance.addPostFrameCallback`. One line in `lib/registry/primitives/subfocus_scope.dart`. |
| `command` / `carousel` "No Overlay widget found" | an `EditableText` (the palette's search field) needs an `Overlay` ancestor. The old gallery ran inside the whole docs shell, so it never showed. | Not a registry bug: the test harness now provides `Overlay.wrap`, which is what `ShadcnApp` gives on the docs page. Documented in the generated test. |
| `Gap` inside a `Wrap` | `alert_dialog`'s dialog actions are laid out in a `Wrap`, and a `Gap` only works inside a `Flex` (or under a `Scrollable`). | The preview uses `SizedBox` there; the rule is stated in the preview header comments. |
| `eye_dropper` "ValueNotifier<AppError?> used after dispose" | **UNVERIFIED owner.** `eye_dropper` holds no `ValueNotifier` at all; `ScreenErrorScope` (the only widget that disposes an error channel) is used by no component in the registry. The audit's harness stacked 118 pumps in one test, so the notifier outlived the pumped subtree — a harness artefact, not a component bug. | Re-verified: the new previews test pumps all 118 components × 8 combinations sequentially in one test and the error does not reproduce. Recorded as harness artefact; nothing in the registry to fix. |

same audit is fixed once by whoever owns the component): P6-F3b = `navigation_*`,

## 5. Test — `$APP/test/registry/previews_test.dart`

Generated by `tool/registry/gen_previews_test.dart` (99 lines of generator, no
hand-maintained table):

* reads every **listed** component from `meta.json` (`listed != false`) and
  parses its `preview.dart` with `package:analyzer` for the exported
  `const List<ComponentPreview>` variable;
* emits the import + table and runs `dart format` over the result, so the file
  on disk is byte-identical to the generated text — `--check` is a plain
  equality comparison (`dart run tool/registry/gen_previews_test.dart --check`);
* every named example of every listed component is pumped twice — inside a
  **720×420** box and inside a **375 wide** box — under the **neutral** and
  **claude** presets in **light and dark** (4 combinations × 2 boxes);
* each pump asserts `tester.takeException()` is null, which catches both
  framework exceptions and `RenderFlex` overflows;
* assertions: every listed component exports a list, no building block leaks
  into the table, example names are unique, and no `preview.dart` contains
  `ShadcnThemeData(`.

Result: **586 preview tests, all green** (plus 3,789 in the rest of
`test/registry`).

## 7. Notes for the docs agent

* Import `package:flutter_shadcn_kit/registry/foundation/component_preview.dart`
  and read `<camelName>Previews`; `ComponentPreview.builder` takes a
  `BuildContext`, so call it as `Builder(builder: example.builder)` (a
  constructor tear-off is *not* assignable to `WidgetBuilder` in Dart).
* Give the example a bounded box (720×420 in the tests) **and** an `Overlay`
  ancestor, or the command palette's search field throws.
* Private example helpers are named `<camelComponent><Name>` on purpose, so the
  single-owner gate stays quiet when every preview lives in one library.
* The manifest now carries `listed: true|false` per component; the sidebar,
  index, ⌘K group and sitemap should all filter on it.

## 8. Open questions

1. `eye_dropper`'s notifier-after-dispose is recorded as a harness artefact
   (UNVERIFIED owner). If a later audit still reports it, the next place to
   look is `AppErrorHub.disposeScreen` racing a still-mounted listener.
2. Building blocks keep their maintainer preview rather than a named-example
   list (the brief allows either). Converting them is a follow-up if the docs
   team wants a uniform surface.
3. `button` has no `loading` prop; the "Loading" example shows the shadcn
   pattern (disabled button + loader glyph) rather than a real spinner, because
   importing `spinner` from `button`'s preview would add a component
   dependency the registry does not declare.

## 9. Side effects of the required test gate

`flutter test test/registry` re-runs `test/registry/visual/pilot_screenshots_test.dart`,
which rewrites `rearch/screenshots/pilot/preview_{button,input,toggle}_{light,dark}.png`.
The pixel content is unchanged (that test asserts its plot hash never drifts);
only the file bytes were re-encoded by the test itself. This is the same output the
gate always produces, so it is left in the working tree.
