## 2. Preview stage + card

`docs/lib/widgets/preview_stage.dart` — the old harness put a horizontal
`SingleChildScrollView` outside the width constraint and a `Column`
(`mainAxisSize.min`) under an unbounded `maxHeight`, so the preview saw
**unbounded width and unbounded height**: every `SizedBox(width:
double.infinity)` / `Expanded` / `EditableText` preview threw or painted blank
(audit D4/D5/D6, 11 blank + 25 overflow + 25 threw). The new stage is a
`LayoutBuilder` → `Container(minHeight: 288, padding: 40, center)` →
`ConstrainedBox(maxWidth: viewport − 80)` → centered child: bounded width, a
288 px floor that grows with the example, no unbounded scroller. The P6-F3
examples shrink-wrap (no `Expanded`, no fixed outer box), so nothing needs the
scroller; leftovers overflow loudly instead of vanishing, which is what the
audit asserts against.

`docs/lib/widgets/component_preview_card.dart` (new, 340 lines; split out of
the page for the ~400-line rule) — `ComponentPreviewCard` (Select + toggle +
stage + teaser), `PreviewExampleControls` (stacks vertically below 360 px so
the 375 px article never overflows; this fixed a `responsive_test` failure),
`PreviewExampleLoader` (caches the deferred future per `(id, index)` so theme
switches re-theme instead of refetching), `PreviewSnippetCode`. `pages/
component_page.dart` is back to 107 lines and only composes sections.

`DocsState` gained `previewExampleFor` / `setPreviewExample` and
`isPreviewInverted` / `setPreviewInverted` / `togglePreviewInverted`
(in-memory per-component maps; the choice survives navigation because the state
sits above the navigator). The toggle is dynamic-opposite: while inverted, the
stage shows `themeModel.themeFor(opposite(siteBrightness))` — same preset
document, opposite leg — so a later site mode flip keeps the stage opposite.

Two docs-side bugs fixed along the way: the old page loaded the preview once
in `initState` and never reloaded on `componentId` change (stale preview when
navigating between components; the loader handles `didUpdateWidget`), and the
teaser's copy button copied `component.install` while showing snippet code
(now copies `snippets.first.code`).

## 4. Theme propagation + the Calendar question

Investigation (widget tests, not screenshots): pumped the full docs app,
`setPreset('claude')`, opened `/docs/components/calendar`.

- The ambient theme inside the preview **is** claude (`primary 0xFFC96442`
  light / `0xFFD97757` dark) — `ThemeDocument`, `ShadcnApp` wiring and the
  preview context all agree, and no nested default `ShadcnApp`/`ShadcnTheme`
  exists in the docs preview path (grep §7). The registry finding stands:
  `calendarDefaults.selectedBackground = primary`, no docs-side divergence.
- The trap: the **default** `Single` example seeds `_value = null`, so there
  is no selected cell to probe — a "selection is black" report against the
  default example measures nothing. The proof uses the `Read-only` example
  (seeds `SingleCalendarValue(Mar 14 2024)`): its fill scans to claude primary
  in light and dark, the ambient primary matches, a runtime
  `setPreset(claude → neutral)` repaints to the new primary, and the inverted
  stage paints the same preset's opposite leg. New file
  `test/component_preview_f4_test.dart` (10 tests) locks all of this.
- `ensureReadableDarkTheme` only patches foregrounds, never `primary` — ruled
  out by reading `theme.dart:229-263`.

## 6. Audits + the one remaining overflow

- Static audit rewritten for the contract (old file crashed: it `firstWhere`d
  a `*Preview` class that no longer exists for listed components). Now reports
  `examples=` per file and gates **zero pinned themes** (pass) and **zero
  variant dumps in old galleries** (pass; `button`/`stepper`/`toast` still
  iterate `.values` *inside one named example* — Sizes/placements showcases —
  which the page shows one at a time, so D2 stays fixed).
- Render audit (`AUDIT_RENDER=1`): **97 listed, threw=0, overflow=1, zero=0**
  in light + dark (was 25/25). The single overflow is a **registry preview
  bug, out of scope**: `navigation_menu/preview.dart` fixes `SizedBox(width:
  340)` but the `NavigationMenu` Row needs ~374 px under the real app text
  style (Geist via `ShadcnUI`), overflowing 34 px right in both modes. It
  passes the registry harness only because that harness pumps a bare
  `ShadcnTheme` without `ShadcnUI`'s `DefaultTextStyle`, so the fallback
  metrics happen to fit. No docs-side box can fix an internally-overflowing
  fixed-width preview. Reported for the owning batch (P6-F3b owns
  `navigation_*`): widen the example box (374 px intrinsic; 400 px is safe) or
  drop the fixed width and let the stage bound it. Registry untouched per the
  brief.
