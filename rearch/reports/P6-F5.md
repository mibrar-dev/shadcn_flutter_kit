# P6-F5 — Pagination, Calendar, InputOtp shrink to narrow columns

Fixes the three P6-T1 blockers at the root in each component: all three now lay
out without overflow in a ~300 px masonry column (tested tight at 240 / 300 /
375 px), so the docs blocks no longer need horizontal scroll views for them.

## Changes

### `pagination` (`lib/registry/components/pagination/`)
- `pagination.dart`: `build` is now a `LayoutBuilder`. When the full window
  would overflow the available width the control collapses to
  prev / ellipsis / current / next — icon-only ends, a one-page window, no
  skip-to-edge buttons. Ellipsis jump targets (`firstShown - 1` /
  `lastShown + 1`) are kept, so every page stays reachable via prev/next +
  ellipsis stepping. Unbounded widths (horizontal scroll views, the 720 px docs
  stage) keep the exact old full layout.
  - Collapse decision (`_collapses`): `controls × 56 × scaling + gaps +
    labelled × 112 × scaling`, calibrated against measured row totals at the
    default density (labelled 7-control ≈ 472, labelled 9-control ≈ 572,
    icon-only 9-control ≈ 436–440). Deliberately conservative: collapsing early
    only drops labels and window neighbours, never a reachable page. No fixed
    layout widths — only the theme `gap`, ambient `scaling`, and the resolved
    `showLabel`.
  - Window math refactored into `_window(size)` / `_firstShown(size)` /
    `_lastShown(size)`; the public getters (`pages`, `firstShownPage`,
    `lastShownPage`, `hasMorePreviousPages`, `hasMoreNextPages`) delegate with
    `_maxWindow`, behaviour unchanged. Public API additive only (no signature
    changed).
- `preview.dart`: removed the `_ScrollableRow` horizontal-scroll workaround —
  the component fits narrow columns by itself now. Both previews pump at 375 px
  in `previews_test.dart` (compact) and at 720 px (full).

### `calendar` (`lib/registry/components/calendar/calendar.dart`)
- `build` wraps `_grid` in a `LayoutBuilder`; `_grid` takes an additive
  `maxWidth` (default infinity) and fits each column's cells into an even share
  `(maxWidth − gaps) / columns`, keeping the nominal 32 px (date) / 56 px
  (month/year) sizes whenever they fit. Heights never shrink, only widths, so
  row pitch and keyboard/semantics behaviour are untouched.
- Floor `_kMinCalendarCell = 28` (7×28 + 6×4 = 220 px ≈ the brief's ~7×32 px
  minimum footprint). At 240 px a date cell is ~30.9 px; at 300/375 px the
  nominal 32 px is kept. Gap stays the theme row (`style.gap`, default 4).
- Side fix: the weekday header now shares the fitted day-cell width even when
  `cellWidth` is set (previously it always used `cellHeight`), matching the
  documented "one pitch" intent. No existing test depended on the old quirk.

### `input_otp` (`lib/registry/components/input_otp/input_otp.dart`)
- `build` wraps the slot row in a `LayoutBuilder`; slots shrink — staying
  square — to an even split of the available width after fixed gaps and
  separator dashes are reserved (`_slotSize`). Separator cost is measured, not
  guessed: `_separatorReserve` lays out `'-'` in the resolved separator style
  with a `TextPainter`. Nominal `boxSize` (default 36) is kept whenever it fits
  and for all unbounded widths. Slot size/gap still come only from the theme
  (`boxSize`, `spacing`, density `baseGap`); no fixed widths.

## Tests (all new tests in the components' own files)

- `pagination_test.dart` — `narrow columns` group (10 tests): 240/300/375 px
  with 20 pages (compact: no labels/edge numbers, current page + both ellipsis
  + icon prev/next all fire), a small 5-page pager, an icon-only pager, plus
  `unbounded widths keep the full layout` (scroll view back-compat).
- `calendar_test.dart` — `narrow columns` group (6 tests): 240/300/375 px date
  grids (fit, nominal ≥300 / shrunk ≥28 at 240, header keeps the pitch, a
  shrunken cell still selects its date) and month/year grids.
- `input_otp_test.dart` — `narrow columns` group (12 tests): 240/300/375 px
  six-slot (square, nominal ≥300 / shrunk at 240), separated, four-slot, and
  typing still fills slots + reports at every width.
