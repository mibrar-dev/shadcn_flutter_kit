## 1. Registry: MenuGroup no longer steals focus (root fix)
`RovingGroup.autofocus` defaulted `true` (every other component defaults
`false`); inline `MenuGroup` surfaces therefore pulled initial focus into
the wall, breaking first-Tab and Ctrl+K (H1 decision 3).
- `primitives/menu_nav.dart`: default `true` -> `false` + doc (inline never
  steals; overlays opt in). Keyboard engine untouched.
- `components/menu/menu.dart`: `MenuGroup` makes the default explicit
  (`super.autofocus = false`) + doc; `showShadcnMenu` passes
  `autofocus: true` (always an opened overlay).
- `components/dropdown_menu/dropdown_menu.dart`: new additive
  `autofocus = false` forwarded to `MenuGroup`; `showShadcnDropdown`
  passes `true`. Inline `DropdownMenu` (home Quick-actions card) no longer
  steals; opened dropdowns still take focus.
- `components/context_menu/context_menu.dart`: `showShadcnContextMenu`
  passes `autofocus: true` (overlay only; widget has no inline group).
- Unchanged (already explicit): `menubar` false, `select` `!_searching`,
  `spell_check` false, all `menu` previews false, submenu `_open`
  (false on hover/press, true on ArrowRight).
- New `test/registry/components/menu_autofocus_test.dart` (5 tests):
  default no-focus, `true` focuses, keyboard works after manual focus,
  `DropdownMenu` default/`true`. `menu/dropdown/context/menubar/select`
  suites: 88 pass. Full `test/registry`: 3831 pass.
- Docs workarounds removed: `collage_home_menus.dart` drops both
  `FocusScope(canRequestFocus: false)` guards (menubar keeps its
  horizontal scroll — it still needs it, overflowed 16 px at 1400 in H1).
