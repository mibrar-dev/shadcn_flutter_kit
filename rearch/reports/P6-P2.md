## 1. Command chip (brief §1)

`_TabRow` showed a tiny truncated `flutter_shadcn add` (no id) floating mid
tab row. Replaced with `BlockCommandChip`: the full `flutter_shadcn add
<id>` in a bordered mono chip with a copy button (shadcn style), right side
of the toolbar via `Expanded` + right `Align`.

- Wide path (card ≥ 560 px): one row, chip shrinks with ellipsis only under
  duress. Two real layout bugs found by test, both fixed:
  - `Flexible(child: chip)` splits free space evenly with the `Spacer`
    (both flex 1) → chip capped at half the free width, truncated at 768
    (measured: paragraph constrained to 190 px for 31 chars). Fix: no
    `Flexible`; `Expanded` + `Align.centerRight` gives the chip the full
    remainder as a shrinkable bound.
  - Unflexed chip overflowed 3 px at the 640 route (Ahem test font is far
    wider than Geist Mono) → the `Expanded` bound absorbs it.
- Narrow path (card < 560 px, i.e. 375): chip wraps below the tabs,
  full-width, no overflow.
- Tests: full command text on the Preview tab at 1400/768/375;
  `RenderParagraph.didExceedMaxLines == false` at 1400 and 768;
  `takeException() == null` at all three widths.

## 2. Continuous framed card (brief §2)

- `BlockCard` body is now `ClipRRect(bottom radius)` + a `Divider` between
  the tab row and the viewport, so the outer border + radius wrap header,
  tabs and viewport continuously (previously the border visually stopped
  under the tab row and the viewport had only vertical hairlines on a muted
  wash).
- `BlockPreviewFrame`: fill is now the `background` token (was
  `muted @ 40%`); the width-constrained frame has a full `Border.all` +
  `borderRadiusLg` of its own and is centred (`Alignment.center`); desktop
  fills the card (minus 16 px frame padding each side), tablet 768 / mobile
  375 clamp to the available width.
- Tests: frame `BoxDecoration.color == theme.colors.background`; desktop
  width == card − 32; mobile/tablet == 375/768 and centred (|dx| < 1).

## 3. Single title on the block page (brief §3)

`BlockCard(showHeader: false)` on `/blocks/<id>` (new param, default true):
the page header keeps badges + copy + title + description, the card shows a
slim viewport toolbar instead of a second name/description pair. Test:
`Dashboard 01` and its description each `findsOneWidget`.

## 5. Viewport fits the block (brief §5)

Fixed 640 px for every block left short forms floating. Frame height is now
per block: compact fits (`otp-01` 520, `calendar-01` 520, `login-01` 560,
`login-03` 600, `signup-01` 620 — card height measured from the widgets +
scroll/frame padding + wrap margin; taller content still scrolls inside the
bounded frame) and 640 for the other 11. Bounded heights kept deliberately:
5 blocks need bounded cross axes (`IntrinsicHeight` wide rows, `Expanded`
shells); an unbounded shrink-wrap frame would re-break them (see open
questions). Symmetric frame + scroll padding centres short cards. Test:
login-01 frame 560, otp-01 520, dashboard-01 640.

Side effect worth knowing: the new 375 index test caught two latent
narrow-frame overflows the 1400-only P6-B3 suite could not see (login-03
forgot row — mine, fixed; sidebar-03 search — pre-existing rigidity,
fixed). The mirror lag also bit once (docs embedded the pre-`Flexible`
login-01 until re-sync); procedure below re-syncs before testing.
