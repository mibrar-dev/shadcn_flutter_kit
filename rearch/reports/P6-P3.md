## 1. Disabled demo controls (brief §1)

Audit: every `Button`/`Checkbox`/`Switch`/`Tabs` in all 16 blocks. Before the
fix, 25+ controls rendered disabled (50% opacity grey): login-01 Sign in +
Remember me, login-02/03 Sign ins, otp Verify, dashboard View all / filters /
Download, account Upload/Save, calendar Clear/Apply/Book, sidebar
Compose/Mark/Upgrade/Open, signup Create/Start, plus 4 Checkboxes and 2 Tabs
strips with null handlers (`Tabs(index: 0)` with null `onChanged` disables the
strip per `tabs.dart`).

Fix: no-op handlers (`onPressed: () {}`, `onChanged: (_) {}`) so demos stay
enabled; the two static `Tabs` strips (`_Account01Tabs`, `Dashboard02Tabs`)
became stateful with local `_index` so taps visibly switch. `pricing-01` CTAs
already had `onPressed` — untouched. `calendar-02` taken slots keep explicit
`enabled: false` (whitelisted: taken slots disabled by design).

New `test/registry/blocks/blocks_interactive_test.dart` (18): per-block "no
disabled Button/Checkbox/Switch/Tabs" (whitelist: only calendar-02 explicit
`enabled: false`), "every enabled primary Button fills `primary`", and a
login-01 probe (Sign in enabled + primary-filled, Remember-me opacity 1).

## 2. Checkbox full-width bar (brief §2, root fix)

Root cause: `Checkbox` passed the box `BoxDecoration` (fill/border) and padding
to `Clickable`, whose `AnimatedContainer` wraps the whole `Row(box + label)`.
In a stretch column the container fills the width, so the fill painted a
full-width grey bar with the label inside it.

Fix in `registry/components/checkbox/checkbox.dart`: `Clickable` now carries
null decoration/padding (like `Switch`); a new `_CheckboxBox` reads
`WidgetStatesData` and paints the 16px `DecoratedBox` alone (`kCheckboxBoxKey`);
the `Row(min)` + theme gap hugs box + label. Side effect (correct): the box is
now border-box 16 (was 18 — the old container reserved the border as padding);
`size_audit_a_test` updated. `meta.json` gains `data` + `widget_states` deps
(same as `switch`); `registry.json` regened.

Siblings checked: `Switch`/`RadioItem` already use null-decoration Clickables
with self-painted track/indicator — no bug. `Toggle` fills its button by design
(not a label row) — no change.

New `test/registry/components/checkbox_label_layout_test.dart` (12): loose AND
stretch × light/dark × checked/unchecked/disabled — box 16px, label right of
box at theme gap 8 (±1.5), label colour foreground (uncoloured), no stretched
primary bar under stretch, Switch track 32 / radio indicator 16 under stretch.
Existing `checkbox_test` updated to read the box key (hover rows now assert
theme `StateValue` data; mouse-hover widget tests proved flaky in this harness
— see open questions).

## 3. Forgot-password right edge (brief §3)

login-01 row (label + `Spacer` + `Flexible(end)` link) already met the edge per
P6-P2; login-03 `_Login03ForgotRow` (`Spacer` + `Flexible(end)`) is the same
pattern. Extended `blocks_polish_test` with a login-03 rect probe
(|Δright| < 1.5px at 375, neutral light). Both pass; no layout change needed.

## 4. Continuous bordered card (brief §4)

No code change: P6-P2's outer `DecoratedBox` (border + `borderRadiusXl`,
`ClipRRect`, `Divider` between tabs and viewport) already wraps header + tabs +
viewport continuously; the inner `BlockPreviewFrame` border is the device
frame (contains viewport only). New docs test
`blocks_pages_test.dart` ("one continuous bordered card"): exactly one
`DecoratedBox` border rect in the card contains both the header text and the
frame — passes unmodified, proving continuity.

## 5. Input grey fill in light mode (brief §5)

`input_style.dart` used `input @0.3` rest in both brightnesses (grey in light).
shadcn v4 is `bg-transparent` light / `bg-input/30` dark with `border-input`.
Fix: `_inputLightBackground` (input @0) vs `_inputDarkBackground` (input
@0.3/0.5/0.3); `inputDefaults` = light, new `inputDarkDefaults`; 
`resolveInputSurface` picks by `colors.brightness` so overrides work in both
modes. Border stays `input` 1px. `text_area` inherits via the same resolver.
Updated `input_test` (2 light probes 0.3→0), `text_area_test` (light 0,
dark 0.3), new `input_surface_test` (3: light transparent, dark 30,
defaults rows). Dark probes unchanged (still 0.3).
