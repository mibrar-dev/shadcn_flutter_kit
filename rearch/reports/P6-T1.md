# P6-T1 — Theme Studio canvas: shadcn-style staggered (masonry) blocks

Implements brief P6-D8 part 1 + the user feedback of 2026-10-10 ("my blocks are
not looking good"): the Theme Studio canvas is now a staggered grid where every
card is only as tall as its content, the columns pack into the shortest gap, and
there are **40** realistic example blocks built exclusively from registry
components.

## Design decisions

1. **Shortest-column packing, stable left-most tie break** (P6-D8 requirement).
   `MasonryLayout.fixed(crossAxisCount:)` pins the count;
   `MasonryLayout.responsive(maxCrossAxisExtent:)` derives it with the exact
   `SliverGridDelegateWithMaxCrossAxisExtent` rule
   (`ceil(width / (extent + crossAxisSpacing))`, min 1).
2. **No stretch, no flex, no fixed height anywhere in the card chain.** Children
   get tight column width + loose height; the box is as tall as its tallest
   column minus one row gap. `StudioCard` no longer has a `height` parameter and
   no longer wraps its body in `Flexible` (both removed).
3. **Canvas gap = 24 px.** The reference `/create` canvas measures
   `--gap = 2.5rem` (40 px) on its fixed 3000 px wall (measured live:
   `grid-cols-7`, `gap-(--gap)`, `--gap: calc(.25rem * 10)`, 1176×806 preview
   area showing ~2.8 card columns). Our canvas is 1160 px of inner width at 1440,
   so the same *ratio* would be ~16 px; 24 px sits between the reference's
   absolute value and its proportion and matches our own card walls
   (home collage, spec §2.1 measured 24 px @1440), which is what keeps the wall
   tight without the cards touching. The gap also tracks the ambient density
   (`min(24, max(12, baseGap * 2))`), so the rail's density row re-stacks it.
4. **Columns: 3 ≥ 1140 px inner width, 2 ≥ 450, 1 below.** Measured inner widths:
   1440 → 1160 (3), 768 → 488 (rail still open) (2), 375 → 311 (1).
5. **RTL** mirrors the column order (`fromEdge = count - 1 - column`), and
   `visitChildrenForSemantics` walks the visual (column-major) order rather than
   the build order.
6. **Unbounded width throws a clear `FlutterError`** (`MasonryLayout was laid out
   with an unbounded width.` + a fix-it + the offending constraints).
7. **Public render-object fields** (`crossAxisCount`, `mainAxisSpacing`, …) with a
   batched `markNeedsLayout()` in `updateRenderObject`. A per-field setter cannot
   be paired with a public field of the same name in one class (it recurses at
   runtime); the batch write is equivalent because the config only moves with the
   widget.
8. **Two registry component bugs worked around in the docs layer, not fixed**
   (P6-F3 owns `components/**`, and the brief says to list blockers instead):
   - `Pagination` sizes its window through an intrinsic `Row` and cannot shrink
     below its widest row → the block wraps it in a horizontal scroll view.
   - `Calendar` pitches its 7 columns off a fixed cell height (min ~280 px), which
     a 232 px canvas column cannot hold → wrapped in a horizontal scroll view
     with tighter card padding.
   - `InputOtp` with 6 slots needs ~292 px → the block ships 4 slots.

## Tests

Registry (`flutter_shadcn_kit/test/registry/primitives/masonry_layout_test.dart`,
13 tests): shortest-column placement with the stable tie break; exact spacing and
no trailing gap; stacked-card `mainAxisSpacing`; responsive column math at
375/768/1024/1440 (+ never below one column); never more columns than children;
RTL mirror; `IntrinsicHeight` replays the packing; hit test lands on the painted
child and misses the gap below the short column; very tall/short children with no
overflow; empty box; works inside a `SingleChildScrollView` (708 px, no
exception); unbounded-width error message.

Docs (`docs/test/studio_canvas_test.dart`, 7 tests): the canvas is a masonry of
registry blocks; every named block present; **no canvas block is wrapped in a
height-pinning box** (`SizedBox(height:)` / `AspectRatio` / bounded
`ConstrainedBox`); rendered cards keep their own heights (a stretched grid would
give one row a single height — the wall shows > half distinct heights); cards hug
their content and columns pack tightly (300/40/60 probe → third card at
(200, 56)); columns relayout 3/2/1 at 1440/768/375; **no overflow at 375 / 768 /
1440 in light and dark**.

## Open questions / blockers for the orchestrator

1. **P6-F3 preview contract vs the docs harness.** P6-F3 rewrote every listed
   `preview.dart` to `const List<ComponentPreview> <id>Previews` and explicitly
   said "Do NOT touch `docs/**`". The docs codegen still only knew the old
   `XPreview` gallery class, so `docs flutter analyze` / `flutter test` /
   `gen_docs_data.dart` were all broken by an uncommitted change. I made the
   tool **additive** so both contracts work; P6-F4's own harness rewrite can
   replace it. **Please have one of them commit the canonical version.**
2. **Registry component bugs** (for P6-F3/P6-F4, not fixed here, worked around in
   the docs blocks):
   - `Pagination` cannot shrink below its intrinsic width → horizontal scroll.
   - `Calendar` has a ~280 px minimum width (fixed cell pitch) → horizontal scroll.
   - `InputOtp` with 6 slots needs ~292 px → the block ships 4 slots.
3. **`check_single_owner` now reports 16 private-name divergences**, all inside
   the rewritten `preview.dart` files (each component's preview declares its own
   `_Foo`). Public count stays 0. If the rule should ignore `preview.dart`, the
   P6-F3/P6-D9a owner is where that call belongs.
4. Canvas gap (24 px) is a deliberate adaptation of the reference's 40 px (see
   decision 3); it is a single constant (`_kCanvasGap`) if the QA lead prefers the
   reference value verbatim.
