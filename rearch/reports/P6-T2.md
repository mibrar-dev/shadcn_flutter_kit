## 1. Root causes (verified from code, engine + framework sources)

### 1.1 Scroll fade: `modulate` never multiplies alpha (same class as P6-F2 §1.1)

`FadeScroll` built a `ShaderMask` with the default `BlendMode.modulate` and a
colour→transparent gradient (white→transparent by default; the rail passed
`card`→transparent, the code teaser `codeSurface`→transparent). Per
`dart:ui` (`painting.dart`) `modulate` multiplies **colour only**; the
transparent stops multiply colour by white/card (near-identity for white,
a dark tint for a dark surface) and leave destination alpha untouched. In
dark mode the rail's top fade therefore painted an opaque dark block over
the first row — the user's screenshot. Worse, the stop math was inverted
(opaque at the extreme edge, transparent just inside), but the mask was a
no-op either way so nobody saw it.

Fix (`REG/primitives/fade_scroll.dart`): the mask is now alpha-only
(`BlendMode.dstIn`, opaque white → transparent white), so the fade dissolves
into whatever surface is behind the scrollable in light and dark mode. The
`gradient`/`startCrossOffset`/`endCrossOffset` parameters are removed (the
cross offsets were never read by `build`; clean break per REARCH §3). The
widget is now `StatefulWidget` with one post-frame refresh so an initially
overflowing scrollable fades without waiting for a scroll. Same constructor
otherwise; `FadeScrollTheme` keeps `startOffset`/`endOffset`.

### 1.2 `LayoutBuilder` inside `IntrinsicWidth` (the `_ErrorRecorder` note)

`MenuPopupSurface` wrapped rows in `SingleChildScrollView > IntrinsicWidth >
Column`. `RenderIntrinsicWidth.performLayout` calls `child.getMaxIntrinsicWidth`
during layout with `debugCheckingIntrinsics == false`; any descendant
`LayoutBuilder` (the registry `Slider` in the radius/spacing/shadow popups)
throws, cascading into ~20 "was not laid out" errors. Reproduced: 1 root
error + 20 follow-ons when opening the radius picker.

Fix (`REG/primitives/menu_rows.dart`): the surface no longer issues intrinsic
queries at all. Width is deterministic (`width`, else up to `maxWidth` = 288
with `minWidth` = 192 floor); height caps at `maxHeight` = 360 with its own
scroll area. A second failure (mobile rail sheet, `PopoverConstraint.intrinsic`
→ `getMaxIntrinsicWidth` during layout) ruled out a `LayoutBuilder`-based
implementation, so sizing lives in `_RenderSurfaceSizing`, a `RenderProxyBox`
that reads constraints in `performLayout`. Tight incoming sizes (select's
`anchorFixedSize`, 220 px) flow through untouched — `select_test`'s
`popup.width == 220` still passes. A tight incoming *height* is treated as an
anchor size, not a viewport cap, or every select list would clip to one row.

`RovingRow` (`REG/primitives/roving_row.dart`) gains a `FocusNode` listener
(not the highlight callback — highlight only reports in traditional mode)
that `Scrollable.ensureVisible`s the focused row, so keyboard traversal keeps
the selection in view. `MenuPopup`/`showShadcnPopup` gain optional
`width`/`maxWidth`/`maxHeight` passthroughs.

  radius slider changes `themeModel` before `Done`; Escape keeps the dragged
  value; hovering a preset re-themes without picking.
