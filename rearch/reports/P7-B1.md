## Shared conventions applied to every rewritten block

- Root pattern (works bounded in an app AND unbounded in the intrinsic docs
  frame): `ColoredBox > SafeArea > LayoutBuilder`. `bounded =
  constraints.maxHeight.isFinite`. Bounded → `SingleChildScrollView` internal
  scroll; unbounded → same content shrink-wrapped, no scroll. No vertical
  `Expanded`/`Flexible`/`Spacer` anywhere (they throw under unbounded height).
- Auth cards `maxWidth: 384` (max-w-sm) centred; login-02 two equal columns,
  form column centred at 320 (max-w-xs); settings pages 768 (max-w-3xl);
  signup-02/pricing/dashboard shells 1024–1280 as noted per block.
- Label→control gap 8 (`spacing.sm` / form default spacing 8), section gap 24
  (`spacing.xl`).
- Every validated form: `ShadcnForm` + `ShadcnFormField` with
  `showErrors: {changed, submitted}` (the kit default with no filter shows
  `initial`-mode failures on mount — see finding F3), `FormController`,
  ordered `FocusNode`s, first-invalid focus on failed submit, `Enter` submits
  (`onSubmitted` / `textInputAction`), submit button validates → loading
  (disabled + `Spinner`) during a ~600 ms simulated async call → inline
  success `Alert`. Typed `XxxData` + `onSubmit` callback with demo default
  (success alert). No `ToastLayer` dependency: blocks must install into apps
  without one, so success is an inline `Alert`, never `showToast`.
- No `material.dart` / `cupertino.dart` imports. `dart format` + `flutter
  analyze` clean per file.

## Finding F1 — docs frame (block_viewport.dart)

- Removed `kBlockPreviewHeight` / `kCompactBlockHeights` / `heightFor` static
  table. `BlockPreviewFrame` no longer fixes heights: it constrains only width
  (full card / 768 / 375 device frame) and `minHeight: 360`, and lets the
  block size to its intrinsic height (the docs page scrolls vertically, so the
  block's internal `SingleChildScrollView` shrink-wraps instead of clipping).
  Nothing is ever clipped; short forms keep a 360 minimum.
- Requires every block to be unbounded-height safe (see root pattern above).

## Finding F3 — form component default shows initial errors

- `ShadcnFormField` without `showErrors` renders `initial`-mode failures on
  mount (empty required fields show errors before any interaction). Every
  block passes `showErrors: const {FormValidationMode.changed,
  FormValidationMode.submitted}`. Owned by P7-U1/U2 (do not edit); recorded
  here. UNVERIFIED beyond code reading + widget-test observation.

## Finding F4 — TextArea is not form-aware

- `TextArea` is a `StatelessWidget` with no `FormValueSupplier`; it never
  reports into `ShadcnForm`. account-01 bio uses `Input(minLines: 3,
  maxLines: 5, maxLength: 160)` (form-aware) instead. Owned by P7-U1/U2.

## Finding F5 — Button has no loading state

- Blocks render loading as `enabled: false` (via `onPressed: null`) +
  `Spinner(size: 14)` in the label row. Owned by P7-U1/U2 if a first-class
  loading button is wanted.
