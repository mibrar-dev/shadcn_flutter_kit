## Progress log
- 2026-10-11: read brief + PLAN + all owned sources/tests. Baseline gate
  running. Key findings so far:
  - `RovingRow` builds `Clickable` with default `focusOutline: true` while
    also painting the accent hover/focus fill → the thick ring in the
    screenshot is `FocusOutline` (3px ring @50% alpha) on every hovered row.
    `SubFocusListItem`'s inner `Clickable` never takes focus itself (hover
    requests the `SubFocus` node instead), so command rows have no ring; the
    command "heavy rounded focus border" is the `Input`'s own full border.
  - `Menubar` builds its root `MenuGroup` with `direction: Axis.vertical`
    and `MenuButton._open` always uses side placement (`topLeft`/`topRight`,
    offset `(8,-4)`), so bar submenus open to the SIDE of the trigger instead
    of below it. Root cause of the mis-anchored home-card popup.
  - `MenuPopupSurface` always stretches to `maxWidth` (288): the inner
    `SingleChildScrollView` takes the full max constraint, so every menu
    popup is 288 logical px wide (~570+ device px @2x) however short the
    items. Root cause of the too-wide popup.
  - `Select` opens with `anchorFixedSize` (popup == trigger width exactly)
    and both `SelectPopupBody` (320) and `MenuPopupSurface` (288) cap the
    width below wide triggers and at 192 minimum, so narrow triggers crush
    options per-character and wide triggers clip. Fix: `anchorMinSize` +
    content hug (never narrower than trigger).
  - `command` preview passes raw `EdgeInsetsDensity.pxSymmetric` multipliers
    (0.5px!) as real padding → tiny list items in the docs demo; `_buildList`
    puts a `Divider` between EVERY item; input has full rounded border and
    `spacing.md` vertical padding (oversized row).
