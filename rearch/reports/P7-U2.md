# P7-U2 — radio group spacing, date/time picker dialogs, form-control spacing audit

Brief: `rearch/briefs/fixes/P7-U2-forms-pickers.md` (user captures 2026-10-11).
Scope: `radio_group` + primitive `selectable_radio`, `checkbox`, `switch`, `toggle`, `calendar`,
`date_picker`, `time_picker`, `form`, `dialog` (sizing only), `slider`/`input`/`text_area` (audit only),
plus the `form_core` prompt primitive that draws the picker surfaces.
Not touched (P7-U1 owns them): `menu*`, `select*`, `command`, `popover*`, `overlay*`.
No git operations were run. No repository files were deleted.

## 1. What the screenshots showed, and the root cause

| Reported bug | Root cause | Fix |
|---|---|---|
| Radio group rows touch (Free / Pro / Team) | `ShadcnRadioGroup` took a caller-supplied `child`, so the item gap belonged to whoever wrote the demo. The docs home collage and the component preview both passed a plain `Column` (zero gap). | The group owns the layout: `items` is stacked along `direction` with the theme's item gap (12 = shadcn `gap-3`). |
| Date picker dialog is far too big | `ObjectFormPromptDialog` stretched a `Column` inside a `maxWidth: 480` box, so the card was 480 wide and the calendar (272) floated in empty space. | The card shrink-wraps its content (`IntrinsicWidth`, clamped to 240…480) and the calendar paints its own `p-3` shell, so the card is `p-0` + content. |
| Time picker dialog is far too big | Same stretched frame; the four duration columns then overflowed a 375 phone. | Same shrink-wrap, plus flexible digit columns and a compact `size-(--cell-size)` caption row. |

## 2. Changes by file (registry)

### `radio_group` (the reported bug)
- `radio_group.dart`: `child` → `items` (`List<Widget>`); the group builds the `Row`/`Column` itself
  (`spacing: itemsGap`, `mainAxisSize.min`, cross `start` vertical / `center` horizontal).
  `RadioCard`'s indicator↔content gap now uses the same density scale.
- `radio_group_style.dart`: new `RadioGroupTheme.itemsGap` + `radioGroupItemsGap = 12`
  (shadcn `gap-3`, scaled by density), threaded through merge/`==`/`hashCode`.
- `preview.dart`: uses `items`; card items no longer hand-roll their gap.
- `test/…/radio_group_test.dart`: two new tests — the stacked gap is exactly 12 px at the default
  density (the reported bug: it was 0), and it scales 4/8/10 → wait: **6/12/15** at
  compact/default/comfortable.

### `primitives/selectable_radio`
- Label↔indicator gap is density-scaled (shadcn `gap-2`), and `itemPadding`
  (`EdgeInsetsDensity.pxAll(2)`) is now resolved against the density. **This was a live bug**: the
  raw `EdgeInsetsDensity` was handed to a `Padding` as-is, so the row had **0.125 px** of padding
  instead of shadcn's `p-0.5` (2 px).

### `calendar`
- `p-3` shell on the `Calendar` root (shadcn puts it on the `DayPicker` root), inside the
  `LayoutBuilder` so the grid is fitted against the width it really has.
- Cell sizes are shadcn px values × density: `size-8` (32) day cells, `size-14`/`h-10` month and
  year cells, cell pitch 4, weekday header in its own cell box.
- New `_CalendarHugWidth`: a private proxy that answers intrinsic sizes honestly
  (`LayoutBuilder` returns 0 and *throws* when asked). This is what lets a shrink-wrapping parent
  size itself to the calendar — the fix for the oversized picker dialogs depends on it.
- `calendar_style.dart`: exported `calendarPadding`, `calendarDayCellSize`,
  `calendarMonthCell{Width,Height}`; `meta.json` now declares `theme.density`.

### `date_picker` / `time_picker`
- `DatePickerDialog`: caption row is `mainAxisSize.min` (no `Expanded`), the two chevrons are
  `size-(--cell-size)` with `p-0` and the caption is `h-8` — the row is 32 px tall instead of 48.
- `TimePickerDialog` / `DurationPickerDialog`: own `p-3` shell; digit columns are flexible
  (`w-18` nominal, floor 48) so the four-column duration sheet fits a 375 phone; colon offsets are
  density-scaled; `kTimeColumnKey(label)` is the lookup key of a column.
- Both triggers pass `dialogPadding: EdgeInsets.zero` + `dialogFooterPadding: p-3`, and the popover
  variant asks for `PopoverConstraint.intrinsic` (shadcn's `w-auto p-0`).

### `primitives/form_core`
- `object_form_prompt.dart`: the dialog card is wrapped in `IntrinsicWidth` between
  `BoxConstraints(minWidth: 240, maxWidth: 480)`; screen inset is its own `p-4`; the footer can
  paint `p-3` + a hairline top border; new `kObjectFormDialogSurfaceKey`.
- `object_form_field.dart`: `dialogPadding` / `dialogFooterPadding` pass-through;
  popover `widthConstraint: PopoverConstraint.intrinsic`.

### `form` (spacing audit)
- `FormTheme.messageSpacing` (shadcn `gap-1.5` = 6) separate from `spacing` (`gap-2` = 8);
  both are scaled by density like every other spacing.
- `labelStyle` 13 → 14 (`text-sm`), `hintStyle`/`messageStyle` 12 → 14 (`text-sm`; shadcn v4's
  `FieldDescription` / `FieldError` are both `text-sm`).
- `FormInline` and `FormTableLayout` pass the message spacing through.

### `checkbox` / `switch` / `toggle` (list rows)
- `checkbox`: the label gap is density-scaled; the preview now uses the component's own
  `label:` (so the whole row is clickable and the gap is the component's), and its list gap is
  `spacing.md`.
- `switch`: label gap density-scaled; new "Rows" example (three switch rows at `gap-3`).
- `toggle`: new "Group" example (three members at `gap-3`); the existing examples already used
  `spacing.md`.

### Audited, no change needed
- `dialog`: `dialogDefaults` is already shadcn — `p-6` card, `p-4` inset, `sm:max-w-lg`, 1 px
  `border`, `shadow-lg`.
- `input`: `h-9` (36) minimum height and `px-3 py-2` padding (already density-scaled).
- `text_area` (same surface as `input`) and `slider` (canvas control, no spacing rows).

### Deliberate deviations from the brief (both verified against shadcn v4 source)
1. **Helper/error gap 8 px, not 6?** No — the brief's 8/6 split is what shipped: label→control is
   `gap-2` (8) and helper/error is `gap-1.5` (6), matching `Field`/`FieldContent` in shadcn v4
   (`ui/field.tsx`). The label, description and error are `text-sm` (14) there too, so the form
   theme was raised from 12/13 px.
2. **Control heights stay fixed at h-9 (36)** instead of scaling with density: the kit's documented
   rule is "padding scales with density, the control height table does not" (`_buttonMetricsFor`),
   and a 36 px button next to an 18 px input would be worse. The 12/8/6 gaps *do* scale.
3. The 6 px helper gap is expressed as `FormTheme.messageSpacing` (a shadcn px value at the default
   density) rather than a `SpacingScale` step, because the 4 px spacing scale cannot express 1.5×base.
