# P7-U3 — Theme Studio: apply on SELECT, never on hover

## What changed (docs only, no registry/primitive edits)

**Problem (user feedback 2026-10-11):** hovering colours/themes/fonts in the
Theme Studio rail pickers re-themed the whole site per hover; sweeping 4–5
options caused rebuild jank.

**Fix:** browsing (hover, scroll, arrow keys) is now popup-local visual state
only. `DocsState`/theme model is touched exactly once per committed select.

| File | Change |
|---|---|
| `docs/lib/widgets/rail_picker_rows.dart` | Removed `onHighlight` from `RailPickerRow`/`RailSeedSwatch` (hover/focus no longer call the model; `Clickable` hovered/focused states still give local visual feedback; focus still scrolls into view). `RailHexField` commits on submit only (per-keystroke live apply removed). |
| `docs/lib/widgets/rail_pickers.dart` | Preset + colour pickers: no `StatefulBuilder`/`live` value; `onChanged` fires once on pick (tap/Enter/Space) then closes. Closing without picking keeps the value. |

## Keyboard (no popup/primitive API change needed)

`Clickable` already maps arrows → focus traversal and Enter/Space →
`onPressed`. Removing the focus→model path was sufficient: arrows move
highlight with zero rebuilds, Enter/Space commits once, Escape discards
(verified in tests). The popup's autofocus `Focus` container + Tab entry
also work unchanged.

## Key findings

1. **Settle timer removed (race):** the first `DraftSlider` draft committed
   via pointer-up, with a 300 ms timer fallback for releases outside the
   thumb. The timer fired *during* the popup's ~600 ms close animation —
   after Escape but before unmount — committing a draft Escape should
   discard. Removed the timer: release-inside commits on pointer-up,
   keyboard edits commit on `Done`, everything else discards. Verified:
   Escape mid-drag leaves the model untouched with 0 notifications.
2. **Widget-test gesture mechanics:** a single `moveTo` jump (or a first move
   of exactly the 18 px slop boundary) never produces drag updates under
   `DragStartBehavior.start`; incremental moves each safely above slop do
   (`tester.drag` splits 60 px into 20+40 — i.e. `kDragSlopDefault` is 20).
   Tests use `moveBy(30,0)` × 2. No production-code impact (real drags emit
   many move events).
3. **Releasing a test pointer after overlay disposal crashes** (`up` hit-tests
   a disposed `Listener`); tests use `removePointer()` for the discard path.
   Production is unaffected (real ups re-hit-test the live tree).
4. **Tap-track jump + release ordering:** `Listener.onPointerUp` (flush) runs
   before the tap recognizer's `onTapDown` in the same dispatch, so a tap
   that only moves the thumb display commits on the *next* flush rather than
   being lost or double-committed — always at most one notify per gesture.
